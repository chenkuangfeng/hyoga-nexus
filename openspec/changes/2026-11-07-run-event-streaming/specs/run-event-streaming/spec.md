# 规格：Run 事件通道

来源：`openspec/changes/2026-11-07-run-event-streaming`（待确认，确认并实施后归档）。

## 需求

### R1 事实来源
- 数据库是 Run 与持久事件的唯一事实来源；通道不可用、断档或丢信号时，Run 的状态、事件与消息保持正确。
- 持久事件在同一事务写库，提交后再发布到通道，事件 ID 为 `sequence`；通道发布失败不使 Run 失败。

### R2 订阅
- 订阅者先占位通道尾部，再重放数据库中 `after_sequence` 之后的持久事件，再消费通道，并按 `sequence` 去重；不丢失、不重复。
- `Last-Event-ID` 只指向持久序号；临时事件不带 SSE `id`。
- 通道断档时发送 `stream.resync`，随后以数据库为准；不得静默丢事件。
- 空闲时按配置周期发送心跳。

### R3 临时事件
- 在支持临时事件的后端，`message.delta` 只发布到通道，不写库；完整文本由持久化的助手消息提供。
- 在 `database` 后端，`message.delta` 保持写库，行为与变更前一致。

### R4 围栏
- 临时事件的发布以生产者令牌为条件；租约丢失后发布被拒绝。持久事件仍由数据库租约围栏。
- 生产者租约过期且 Run 未终止时，订阅者收到 `stream.closed`。

### R5 控制信号
- 取消与审批结果同时写库并发送控制信号；worker 收到信号后立即读库确认。信号丢失时，延迟退化为心跳周期，结果不变。
- 控制信号不出现在用户可见流中。

### R6 活动 Run 标记
- 会话有进行中的 Run 时存在标记，活动期间续期，终态清除；`GET /sessions/{id}/live-run` 返回该 Run 或 204；会话与 Run 删除时清理其通道键。

### R7 部署与配置
- `[run_events].backend` 取 `database`（默认）、`redis`、`memory`；无效配置阻止启动。
- API 与 worker 分进程部署时配置 `memory` 启动即报错。
- Redis 为可选依赖，`database` 后端不导入它。
- `redis` 后端不可用时，订阅自动回退数据库路径，`/health/ready` 报告降级。

### R8 并发
- 流式接口不为每个连接占用一个线程，也不持有请求级数据库连接。
- `database` 后端下，同一进程内同一 Run 的所有订阅者共享一个轮询器。
