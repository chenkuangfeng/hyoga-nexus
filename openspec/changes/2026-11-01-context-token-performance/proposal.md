已确认。全部决定（P1、P2 方向、P3、P6、P9、消息存储与回放规则 P10、P11）已确认；P2 的具体阈值待基线数据确定。规格见 design.md，实施状态见 tasks.md。

## 原因

基于对 Native 运行路径的代码审阅（而非性能测量），当前设计存在以下问题：

1. **前缀缓存失效**：`runtimes/native/context/assembly.py` 的 `append_context` 把每轮变化的 `[WORKING MEMORY]`（含当前轮次、最近 30 条历史、`key_info`）插入到 system 之后、历史之前。供应商的前缀缓存按字节匹配，因此从这里开始的整段历史每轮都无法命中缓存。
2. **工具结果重复计费**：工具输出截断到 4000 字符，但每个后续轮次与后续 Run 都会整段重发，直到触发压缩。输入成本随轮数近似平方增长。
3. **压缩不稳定且默认关闭**：`summarize_context` 默认为 `False`，走确定性摘录。摘录不落库，每个 Run 重算；边界每轮推进，摘要文本随之变化，同样破坏前缀缓存。
4. **每个流式 delta 一次事务**：`engine/turn.py` 对每个文本块调用 `store.emit('message.delta')`，`DurableRuntimeStore.emit` 每次开事务、锁 `runs` 行、校验租约并写 `run_events`。长回答产生数百次写入与行锁争用。
5. **准备阶段读取与授权随会话线性增长**：`runs/preparation.py` 读取会话全部消息，对每个历史 Run 调用 `_history_allowed`（逐资源授权），消息循环中对带 `source_run_id` 的消息再逐条 `db.get`。
6. **工具 schema 每轮重算并每轮授权**：`gateway.definitions()` 每轮对每个工具调用 `access.authorize`。
7. **token 估算粗糙**：`input_estimate` 对整段历史做 `str()`，每轮 O(总长度)，且字符数与 token 无直接关系。
8. **工具默认串行**：`parallel_reads` 默认为 `False`，而只读并行的基础设施已存在。

以上均为代码推断，尚未测量。实施的第一步是建立基线（见 tasks.md），以数据确定优先级。

## 范围

范围内：

- **P1 工作记忆位置**：把 `[WORKING MEMORY]` 从历史前部移到消息列表末尾。内容不变，只改位置；追加在末尾，保证工具调用与结果相邻。
- **P2 工具结果外置与滚动裁剪**：超过阈值的工具输出存为 artifact，历史只保留摘要与句柄；较早的工具结果压缩为单行索引。
- **P3 摘要压缩默认化**：开启 LLM 摘要，摘要持久化到 `context_summaries`（已有表），仅在超过阈值时更新；阈值带滞后（例如超过 100% 时压到 60%），避免边界每轮移动。
- **P4 Run 内缓存工具定义**：每个 Run 计算一次工具列表。执行时的授权复核保持不变。
- **P5 token 估算校准**：以上一轮供应商返回的 `usage` 为准，字符估算只作为首轮兜底。
- **P6 delta 合并**：worker 内按时间（默认 150ms）或字符数合并 `message.delta` 后再持久化。最终消息与检查点不合并。
- **P7 一轮内合并写入**：`save_progress`、`emit` 与消息写入在一轮内合并到一个事务，共享一次租约与 Run 校验。
- **P8 准备阶段窗口化**：读取最近窗口加摘要替代旧消息；授权结果按 Run 缓存，消除 N+1 查询。
- **P9 并行只读工具**：经审查确认满足 `read_only` + `idempotent` + 无副作用的内置工具，默认开启 `parallel_reads`。
- **P10 跨 Run 不回放工具行（已确认）**：模型视图只保留历史 Run 的 user 消息与最终回答；当前 Run 内的工具行完整保留。规则与理由见 design.md 12.2。
- **P11 摘要表追加式（已确认）**：`context_summaries` 改为追加式，每次压缩新增一行，记录 `supersedes_id`，旧摘要不覆盖。结构见 design.md 12.5。
- **消息存储的其他约定（已确认）**：整体遵循 Hermes Agent 的逐消息存储；工具行为唯一来源，界面展示由其派生，不另存 JSON 副本（见 design.md 12.3）。

不在范围内：

- 更换模型、供应商或引入新的缓存层（Redis 等）。
- 权限判断缓存。仍然每次工具调用查库。
- 忙时策略、队列与派发账本的语义（由 busy-session-queue 与快照提案负责）。
- 投影缓存与会话快照的落地（由 `2026-11-01-session-context-cache` 负责）。本提案的 P8 不依赖它。

## 行为与接口变化

| 项 | 当前 | 变更后 | 是否需要确认 |
|---|---|---|---|
| 工作记忆位置 | system 之后 | 消息列表末尾 | 是（改变模型输入结构） |
| 工具结果（超阈值） | 截断 4000 字符 | 外置为 artifact，历史存句柄 | 是（改变模型所见内容） |
| 旧工具结果 | 完整保留直到压缩 | 滚动压缩为单行索引 | 是 |
| `summarize_context` 默认 | `False` | `True`，摘要落库 | 是（额外模型调用，产生成本） |
| 工具 schema 计算 | 每轮 | 每 Run 一次 | 否（内部） |
| token 估算 | 字符 `str()` | 以 usage 校准 | 否（内部） |
| `message.delta` 事件 | 每块一条 | 合并后按批次写入 | 是（SSE 粒度变化） |
| `parallel_reads` 默认 | `False` | `True`（仅对白名单工具） | 是 |
| 跨 Run 的历史 tool 行 | 全部回放 | 不回放（P10） | 已确认 |
| 摘要存储 | 每会话一行，覆盖更新 | 追加式，`supersedes_id` 链（P11） | 已确认 |

API 契约本身（请求与响应结构）不变。`run_events` 的 `message.delta` 粒度变粗，前端需要确认能接受。

## 已确认的决定

1. **"轮次"指 Run**，不指引擎内的一次模型调用。
2. **Run 内的 tool 行保留在 `messages` 中作为唯一来源**，不另存 JSON 副本用于展示。
3. **摘要表采用追加式**，保留 `supersedes_id`。
4. **P2 方向**：超过阈值的工具输出外置，模型只拿预览与句柄，并提供分页读取工具（读取工具本身不再外置）。外置内容保持 `[untrusted]` 标注，读取走授权与审计。
5. **P2 阈值可配置**：阈值、预览长度、分页大小等参数作为智能体版本的配置项，接入现有 Native 设置机制（`NativePolicy` / `ExecutionBudget`），与模型、压缩参数一起在发布时快照。先给默认值（阈值 2000 字符），基线数据出来后调整默认值。规格见 design.md 第十四节。

5. **P1 位置**：工作记忆放在消息列表末尾（不是插在某条 user 之后，那样会切断工具调用与结果的相邻关系）。
6. **P3 默认值**：目标为默认开启摘要压缩。切换默认值的前提是评测样例确认回答质量没有下降（见 tasks.md 第六节）。
7. **P6 合并窗口**：`message.delta` 按 150ms 或 256 字符合并，先到即发；接受 SSE 粒度变粗。
8. **P9 白名单**：并行只读工具在工具定义中显式声明，由平台注册时校验，不按名称硬编码。

以上决定全部确认，剩余的 P2 阈值待基线数据确定。

## 影响

- **文档**：`docs/architecture.md` 2.2（上下文、压缩）与 2.12（事件与持久化）需要同步修改。路线图第 3 步新增性能验收项。
- **数据库**：P2 需要 artifact 存储（若已有 `artifacts` 表则复用，否则需要新表，需单独确认）。P3 复用 `context_summaries`，无新表。
- **评测**：P1、P2、P3 改变模型输入，必须在 `evals/` 中跑对比样例，确认回答质量不下降，再开启默认值。
- **兼容**：所有开关都通过 `NativePolicy` 控制，默认值在验证后才改。
