# 前端开发规范

本文适用于 `apps/web` 的页面、组件、路由、状态管理和 API 接入。项目总约束见根目录 [AGENTS.md](../../AGENTS.md)。

## 技术栈与组织

- 使用 Vue 3、TypeScript、TDesign（`tdesign-vue-next`）、pinia、vue-router、vue-i18n、axios 和 Vite 工具链，与 WeKnora 前端一致（2026-11-03 确认）。新组件优先使用 `<script setup lang="ts">` 与 Composition API；避免无必要引入第二套组件库或状态方案。
- `apps/web` 为 pnpm workspace：公共基础能力在 `core/src/`，员工工作台在 `workspace/src/`，企业管理应用在 `enterprise/src/`。公共包不得导入应用，两个应用不得互相导入。各项目页面放在 `src/views/`，可复用组件放在 `src/components/`，请求封装放在 `src/api/`，跨页面组合逻辑放在 `src/composables/`，共享类型放在 `src/types/`。目录边界按实际规模渐进建立，不为占位而复制业务逻辑。
- 单文件组件保持单一职责。页面负责组合和导航；复杂交互拆到 composable；纯展示组件通过 props/emits 交互，不直接调用全局 API 或持有隐式跨页面状态。
- 后端 API 通过类型化客户端/模块封装。组件不得自行拼接重复 URL、定义与服务端冲突的 DTO，或绕过统一错误处理。

## 用户配置入口

- 遵循根 AGENTS.md 的「用户前端优先」：日常配置默认提供用户设置入口，配套后端持久化、校验、个人/空间范围及权限；不得仅要求用户编辑环境变量、配置文件或手写 API。
- 保留参考项目原有功能和逻辑的同时，可以扩展配置易用性、合理默认值和管理流程。确需仅在部署端配置的项目必须有具体理由及文档，不把部署主密钥暴露为普通用户设置。

## 页面与接口协作

- 相关页面按业务聚合到 `views/<业务>/`；页面负责组合展示，查询、提交和跨组件联动复杂时提取就近 composable。有实际复用后再提升为共享模块，不强制拆分简单页面。
- 页面、路由、组件或 API 模块迁移时同步静态导入、动态加载、样式引用、测试与文档；删除前确认没有独立用途。
- 选择关联资源时显示名称等可读信息，通过已有 API 加载有权访问的记录并提交稳定 ID；不要求用户手工填写内部 ID。
- 协议固定状态使用与后端一致的类型；可配置业务选项通过已有配置或资源接口加载。不照搬其他项目尚不存在的字典、lookup 或 Kit 框架。
- 修改接口时同时核对路径、参数、分页、错误及事件契约；类型化封装不能替代运行时的响应校验。

## 类型、数据与状态

- TypeScript 开启严格类型检查；避免 `any`、无边界类型断言和未经校验的 API 响应。API 请求/响应、Run 事件和资源状态使用明确的联合类型或接口。
- 将服务端事实与本地交互状态分开。不要把权限、Run 最终状态或资源版本只保存在客户端作为可信依据。
- 加载、空结果、部分结果、失败、无权限和重试状态都要有明确 UI。异步请求处理取消、重复触发和组件卸载；避免旧响应覆盖较新的页面状态。
- 对 Run/SSE 等流式功能按稳定事件 ID/sequence 消费，处理断线续读与重复事件；客户端重连不能重新提交执行任务。

## 交互与视觉

- 使用 TDesign 的交互模式和全局样式。保持按钮、表单、反馈、弹窗、表格和状态标签的一致性；引入新视觉模式前先检查现有页面和设计文档。
- 表单提供标签、必填/格式提示、字段级错误和提交中状态；破坏性操作需清楚说明对象和后果，并使用合适的确认交互。
- 长任务明确展示当前状态、阶段和可用操作；运行失败、等待审批、取消中和取消完成需要区分。
- 页面在窄屏与常见桌面尺寸下保持可用；避免仅依赖颜色传达状态。为键盘操作、焦点顺序、可读标签和对比度提供基本无障碍支持。
- 文本使用用户语言描述业务结果，不向普通用户泄漏 SDK、队列、数据库等实现细节；开发诊断通过受控日志/诊断信息呈现。

## 开源界面参考

- **WeKnora 是首要的平台 Web 参考**。对照固定版本 `e1f9a6166` 的 Vue 3 前端，重点看 Agent、聊天、知识库、集成、工具箱、组织/设置等页面，以及流式进度、工具结果卡片、引用和产物呈现。Nexus 的前端同样采用 Vue 3，可优先借鉴其页面组织与交互细节；要保留参考实现中与平台能力相关的有效行为，并按 Nexus 的身份、空间和 Runtime 契约做兼容扩展。源码：[WeKnora frontend](https://github.com/Tencent/WeKnora/tree/e1f9a6166/frontend)。
- 企业设置菜单按配置、空间、发布集成、数据与扩展、权限、系统分组。分组标题和直属链接布局沿用本地 WeKnora，具体子项与顺序见管理端 README。工具箱职责严格参照 WeKnora 的技能和 MCP 注册拆分，MCP 发布归发布集成。来自 WeKnora 的界面必须先核对固定版本对应页面源码，严格沿用其布局、组件、卡片、抽屉与样式；仅按 Nexus 已实现的接口和权限适配，不凭空重新设计。新增或调整页面须在模块设计文档中记录来源文件及必要差异。
- **GenericAgent 是 Native 使用流程参考**。对照固定版本 `a9a36b4` 的 `frontends/stapp.py`、`stapp2.py`、`conductor.py`、终端与桌面入口，保留并扩展其对话连续性、会话/模型切换、运行进度、后台任务、停止控制、工具结果和多入口复用等用户可见能力。其界面与单机 Agent 状态耦合，迁移到 Nexus 时通过平台 API 和 Run/Event 契约实现，不把单机状态边界带入多用户 Web。源码：[GenericAgent frontends](https://github.com/lsdefine/GenericAgent/tree/a9a36b4/frontends)。
- **Dify** 适合参考平台导航、Agent/应用配置、知识库与运行记录的整体信息架构；**LibreChat** 适合参考 Agent 配置、工具/Skills/MCP 选择和聊天工作台；**Open WebUI** 适合参考 Workspace 资源管理；**Langflow** 适合参考节点画布和流程编辑器。**Flowise** 仅作为画布交互案例，仓库已归档，不作为活跃依赖。参考：[Dify](https://github.com/langgenius/dify)、[LibreChat](https://github.com/LibreChat-AI/LibreChat)、[Open WebUI](https://github.com/open-webui/open-webui)、[Langflow](https://github.com/langflow-ai/langflow)、[Flowise](https://github.com/FlowiseAI/Flowise)。
- 以上项目用于核对可观察行为和交互模式，不要求采用其 React、Svelte、Streamlit 或桌面技术栈。采用不同实现时不得删减已确认的核心流程；把流程和能力映射到 Vue 3/TypeScript/TDesign，并补齐兼容行为。

## 安全边界

- 前端不保存或展示模型供应商、MCP、渠道等秘密；凭据创建/轮换流程只传递一次性输入并遵循后端返回策略。
- 客户端隐藏按钮只改善体验，不构成授权。服务端拒绝无权请求后，前端应显示明确状态并清理失效数据。
- Markdown、代码、文件名和事件正文均视为不可信输入；通过安全组件渲染，禁止直接注入未净化 HTML。

## 验证与交付

- 页面逻辑复杂时为用户关键路径补充组件或端到端覆盖；保持测试关注可观察行为，不锁定无关实现细节。
- 前端改动按根目录 AGENTS.md 执行 `pnpm install --frozen-lockfile` 和 `pnpm build`，聊天交互变化时还须执行 `pnpm test:browser` 并按需更新行为用例；提交前检查类型错误、控制台错误、窄屏布局与键盘交互。
- 只改文档时不要求安装前端依赖，检查链接、格式和差异即可。规划占位页需显式标注能力尚未接入。
