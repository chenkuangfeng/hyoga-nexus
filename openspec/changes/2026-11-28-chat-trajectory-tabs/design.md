# 设计

聊天页顶部仅显示靠左的三个标签，会话头部标题和快捷操作从该页移除。轨迹表由独立持久化模型请求记录驱动，不读取 RunEvent。Runtime 在请求发出前保存模型输入和工具目录快照，请求结束后按同一记录 ID 补写输出、供应商 usage、状态和 Run 累计 token；记录只允许从 running 转为一个终态。开始和结束写入都校验 Run 租约。API 先使用现有 Run 授权再读取记录。前端按请求序号展示紧凑列表，点击一行打开详情检查器。当前正在执行的 Run 通过轻量轮询读取新记录，完成后停止轮询。历史 Run 没有新表记录时显示明确空状态，不从事件推测伪记录。

实现参考 DeepSeek Harness `packages/client/ui-trajectory/src/client/TrajectoryTable.tsx` 的两列事件/内容表、可键盘选择的记录行与点击检查器，以及 `trajectory-record.ts` 的类型化记录详情。Nexus 使用数据库模型请求快照而不是将 RunEvent 直接投影为轨迹行；不复制参考项目的完整虚拟化时间轴。

活动行使用会话已持久化的 `MessageRecord` 呈现用户与助手文本，工具结果以 opaque call ID 与模型响应快照中的调用配对；Run 轮次用于展示，不用于调用归属，因恢复执行后轮次不会从 1 重新开始。消息接口仅返回 assistant 消息内的调用 ID，不额外暴露整份 `runtime_metadata`。模型请求 usage 汇总到对应助手活动行；顶部缓存命中卡片汇总 `usage.cache_read`，仅当输入用量有效时计算占比。模型请求计数仍按独立轨迹表记录计算。

模型请求快照中含 `<user_memory source="recall">` 时，额外展示记忆召回活动。这是本 Run 的模型上下文组成部分，不代表模型调用了 `read_memory` 工具；显式记忆工具仍作为普通工具活动显示。召回在 Run 准备时执行一次，同 Run 后续模型请求可能继续携带相同内容。

列表先按会话中 Run 的首次活动时间排序并分组；每组显示 Run 序号及短 ID，再以每条用户输入作为可折叠活动分组。未选中活动时列表铺满可用空间，选中后显示右侧检查器标签：活动、工具/技能、模型请求。工具/技能默认只列名称，展开单项后显示完整参数和结果。表格列固定为活动、内容、Token，数据行高 15px；用单行省略控制长文本，Token 列在数据可用时标明实际值或估算值，详情检查器继续提供完整正文。
