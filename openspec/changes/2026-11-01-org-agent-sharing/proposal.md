# 组织授予空间角色：组织成员通过角色使用空间内的智能体

## 状态

待确认（2026-11-01 修订）。修订内容：组织不再直接分配智能体，改为"组织 → 空间（带角色）→ 角色 → 智能体"。确认前不进入实施。

## 背景

用户组织管理（`2026-11-01-user-org-management`）已实现组织树与空间绑定。本变更解决：空间绑定组织后，组织成员如何获得空间内的角色，并通过角色使用智能体。

## 核心链路

1. 平台管理员把空间绑定到组织节点（已实现）。
2. 空间的 owner 或 admin 为该绑定授予一个或多个**自定义角色**（`tenant_roles`）。
3. 角色通过 `tenant_agent_grants` 决定能用哪些智能体、以及 view/run 权限（已有机制）。
4. 组织子树内的人员，实时获得这些角色，不写入成员表，不需要同步。

智能体只通过角色获得访问，不再有"组织直接分配智能体"的表。

## 范围

范围内：

- **把角色分配给组织**：空间 owner 或 admin 为某个绑定节点授予自定义角色。
- **有效权限**：人员的有效权限 = 个人成员记录的权限 ∪ 其所在子树绑定授予的角色权限。
- **空间可见性**：组织子树内的人员，登录后能在空间列表中看到该空间，并看到其角色允许的智能体。
- **聊天记录与记忆的可见性**：沿用已确认的规则（见下文）。
- **组织成员切换到空间使用智能体**：会话与记忆写入智能体所在的空间，owner 为该用户。

范围外：

- 把组织授予 owner 或 admin 身份。
- 修改 owner、admin、member 三种成员字段。它们保持现状。
- 把组织人员写入成员表（个人显式加入的入口保留，见下文）。
- 跨集团分配（当前只支持单集团）。

## 成员字段与角色

- **owner、admin、member** 仍是成员记录上的字段，本次不改动。
- 组织授予的只能是**自定义角色**。组织来源的人不会获得 owner 或 admin 的权限。
- 个人显式加入（`from-organization`）仍然可用，它写入成员表，成员字段为 member，并可以再分配个人角色。

## 权限计算

- 有成员记录：权限 = 成员字段与个人角色（现有逻辑）∪ 所在子树绑定授予的角色。
- 没有成员记录但在绑定子树内、且子树有授予角色：权限 = 子树绑定授予的角色。这类人不是成员，不能进行成员管理。
- 其他情况：无权限，返回 NotFound。

`tenant_user_roles` 仍然只挂在成员记录上，不改外键。分配给组织的角色走单独的计算路径。

## 聊天记录与记忆的可见性（已确认）

- **普通用户**：只能看到自己的聊天记录和记忆，可按智能体筛选。
- **空间管理员**（owner 与 admin）：可以看到其管理的空间里的全部聊天记录和记忆。
- **平台管理员**：可以看到全部聊天记录和记忆，可按组织、智能体、空间筛选。

已确认的细节：

- 组织成员在空间里的会话显示"组织访问"标识（默认方案）。
- 记忆（`memory_entries`、`memory_drafts`）与检查点（`session_checkpoints`）按同样规则开放。
- 平台管理员按组织筛选时，以会话创建时记录的组织节点为准。

注意：通过组织获得角色的人不是空间管理员，因此看不到空间里其他人的会话。

## 与现有模型的关系

- 新增 `tenant_org_roles`：绑定节点与自定义角色的关联，引用 `tenant_org_bindings`。
- 删除原草案中的 `organization_agent_grants`。
- `tenant_agent_grants`、`tenant_user_roles`、`tenant_memberships` 的结构不变。
- `resource_grants` 不变。

## 影响

- 数据库：新增 `tenant_org_roles`，`sessions` 增加 `org_unit_id`（可空），一次迁移。
- 权限：空间成员判断、权限计算、智能体权限计算、空间列表都要合并分配给组织的角色。
- API：授予、撤销分配给组织的角色；空间侧的分配给组织的角色视图；会话与记忆的读取范围调整。
- Web：空间设置中"分配给组织的角色"区域；空间列表的组织来源标记。UI 按 AGENTS.md 使用 `ui-ux-pro-max` 技能。
- 文档：更新 `docs/architecture.md`、`docs/roadmap.md`、`packages/platform/docs/`。

## 需要你确认

1. **谁授予分配给组织的角色**：空间的 owner 与 admin 授予（默认）。绑定仍由平台管理员完成。
2. **分配给组织的角色只能是自定义角色**，不能授予 owner 或 admin 身份（默认）。
3. **组织来源的人不写入成员表**，权限与列表实时计算（方案 2，已选）。
4. **会话的组织节点记录方式**：创建时快照写入 `sessions.org_unit_id`（默认，便于审计）。若你希望减少改动，可以改为查询时按当前归属计算，不加字段。
5. **"组织访问"标识**：默认显示。
