# 观澜数据平台探讨记录

状态：讨论整理稿，不是已批准的功能设计或实施承诺。本文归属 P6「观澜数据平台」，记录 AkShare 作为候选股票数据源生态的参考方式。具体数据源、市场覆盖、授权、稳定性、字段契约和实施计划仍需在 P6 设计与数据源验证中确认。

## AkShare 的定位

[AkShare](https://github.com/akfamily/akshare) 是 Python 金融数据接口库，可作为观澜评估外部数据源接入方式时的参考。它应处于数据源适配层，为领域数据服务提供候选数据；它不是 Agent、Skill、知识库或本项目的领域数据契约。

## 可借鉴的接入原则

- **通过领域适配器接入**：由 `guanlan/data` 的 provider/adapter 封装外部接口，将外部字段映射到项目自己的行情、财务、交易日历等领域契约。Agent 和 Skill 调用项目工具，不直接依赖 AkShare 的函数或返回类型。
- **统一来源和时点语义**：规范化数值、单位、市场/证券标识和日期，保留 provider、获取时间、数据对应时间、复权/口径等必要元数据；无法确认的字段或时点应明确标记，不要推断补齐。
- **为数据源变化准备降级**：外部公开页面或接口可能变化，采集需要有超时、错误分类、缓存新鲜度和经过验证的备用源策略。备用源结果要标注实际来源及降级状态，不能静默混成同一数据质量。
- **逐接口验证适用边界**：检查实际数据覆盖市场、历史范围、更新频率、稳定性、使用条款和商业使用限制；不把“库中存在接口”当作 SLA 或授权保证。

## P6 与 P7 的边界

P6 负责数据源验证、采集与调度、领域数据规范化、质量和时点管理，以及稳定查询接口。是否选用 AkShare、用于哪些市场和数据类型，都应在 P6 按实际接口逐项验证后决定。

P7 的股票研究技能消费 P6 提供的结构化数据和工具，不绑定某个供应商。研究研报等文本证据进入知识库，与行情/财务数值数据分开管理；回测结果也应关联数据版本与来源。

本文不表示当前仓库已实现 AkShare 接入或任何数据采集能力。
