# 技能加载与脚本执行（路线图 7.1 第一批：内联加载、版本绑定、开发模式下的脚本执行）

## 状态

草稿（待确认）。未确认前不编码。确认的决定见第 6 节；待确认的细节见第 7 节。

## 原因

路线图第 7 步"技能与 MCP"尚未开始。`packages/skills` 下的 `loader`、`registry`、`versions`、`bindings`、`guard`、`projection`、`review` 都是占位模块；`skills/` 下的 `SKILL.md` 都标注为"规划中，尚未实现"。智能体无法使用技能。

用户要求：技能可以包含脚本并由系统运行；智能体有一个全局配置项，默认开启脚本运行。由于 `docs/architecture.md` 2.9 节规定任意代码执行只能在通过隔离验收的执行后端中开放，本变更把脚本执行限定在显式开发模式下（本机单用户），多用户部署时不开放。隔离验收仍由 2.9 节负责，本变更不关闭它。

## 现状核对

| 项目 | 现状 | 本变更处理 |
| --- | --- | --- |
| `packages/skills` | 全部为占位模块 | 实现加载、版本、绑定、门禁、运行入口 |
| `skills/` 目录 | 5 个 `SKILL.md`，标注"规划中"，frontmatter 为 `name` + `description` | 作为内置技能的内容来源，格式保持兼容 |
| 智能体配置 | 草稿与版本有 `budgets` 等 JSON 字段（`AgentRecord`、`AgentVersionRecord`） | 新增 `skill_scripts` 配置，参与内容哈希 |
| 资源绑定 | `ResourceBindingRecord`（`kind`、`resource_id`、`resource_version_id`） | 复用，`kind='skill'`，`resource_version_id` 指向技能版本，不新增绑定表 |
| 审批 | 审批绑定配置哈希（`platform/runs/approvals.py`） | 脚本调用复用同一审批流程 |
| 执行后端 | `sandbox` 包提供 `local` 后端，仅开发模式（2.9 节） | 脚本经 `CommandExecutorPort` 的 `local` 后端运行，门禁关闭时不注册 |
| 模型工具 | 内置工具按 `BUILTIN_TOOL_NAMES` 与授权注册（`native/policy.py`） | 新增 `load_skill`、`read_skill_file`、`run_skill_script` |

## 范围

范围内：

1. **技能定义与解析**：`packages/skills/loader` 解析 `SKILL.md` frontmatter（`name`、`description`、`scripts`、`tools` 依赖声明）与正文；校验名称（单段，字母、数字、`-`、`_`）、长度上限（名称 64、简介 1024）、保留词。
2. **不可变版本**：`skill_versions` 保存正文、资源文件、依赖声明与内容哈希，发布生成新版本，已发布版本不可修改。
3. **来源**：第一版只支持两种来源：仓库内置技能（`skills/`，发布时导入）和管理员安装的技能。模型提交草稿不在本变更范围内（第 7 节）。
4. **内联加载（渐进披露）**：
   - 系统提示只放已绑定技能的名称与简介（简介截断到 1024 字符，按词边界截断），每个会话冻结一次，与记忆快照的做法一致。
   - `load_skill(name)` 返回正文，作为工具结果进入上下文。
   - `read_skill_file(name, path)` 只读取该技能版本内的文件；路径规范化后必须位于技能目录内，越界直接拒绝。
5. **智能体配置**：`skill_scripts.enabled`，默认 `true`。修改后生成新的智能体版本，参与内容哈希；审批绑定配置哈希，配置变化后挂起的脚本审批失效。
6. **门禁**：脚本执行可用的条件为以下全部满足：
   - 配置文件中显式开启 `[skills] allow_local_scripts = true`；
   - 认证模式为 `development`，API 绑定 `127.0.0.1`；
   - 执行后端为 `local`。
   
   门禁关闭时 `run_skill_script` 不出现在工具列表中（与 2.9 节一致），智能体配置的 `enabled` 不起作用。界面显示"当前环境不可用"，而不是"已开启"。配置不能绕过门禁。
7. **脚本声明与运行**：
   - `SKILL.md` frontmatter 的 `scripts` 列表声明每个脚本的 `name`、`path`（位于 `scripts/` 下）、`interpreter`（白名单：`python3`、`bash`、`node`）、`args` 的 JSON Schema、`timeout`（默认 60 秒，上限 300 秒）、`risk_level`（固定为 `high`）。
   - 运行时使用不可变版本的临时副本，执行前校验内容哈希；工作目录限定在副本内；环境变量只保留白名单项，不注入任何凭据；标准输出与标准错误各限 64 KB；超时则终止进程组。
   - 每次调用需要审批。审批请求包含脚本哈希、参数摘要与配置哈希。
8. **审计**：每次脚本调用记录为一次工具调用，包含技能版本、脚本名、脚本哈希、参数摘要（不含明文敏感字段）、退出码、耗时、是否超时、输出是否截断。
9. **发布校验**：发布技能版本时检查 `scripts` 声明的解释器在白名单内、脚本文件存在且哈希可计算、依赖的工具名存在。智能体发布时检查绑定技能的依赖工具已由该智能体绑定满足，缺失则拒绝并说明原因。静态扫描只作为提示，不作为安全保证，结果记入发布记录。

范围外：

- 沙箱隔离验收（2.9 节）；本变更的脚本不具备隔离，仅限开发模式。
- 多用户环境下的脚本执行。
- 模型提交技能草稿与审核发布流程（7.1 后续）。
- 语义检索技能、关键词检索技能（技能数量超过 50 个后再评估）。
- fork 执行模式。
- 技能级 secret 绑定。
- 内联 shell（`!\`cmd\``）与模板变量展开。
- MCP（7.2、7.3）。
- 内置技能的批量内容编写：本变更只要求两个示例技能验证端到端流程，内容由后续任务补充。

## 设计

### 包结构（`packages/skills`）

- `loader`：解析与校验 `SKILL.md`，不做 I/O 以外的副作用。
- `versions`：生成不可变版本与内容哈希。
- `bindings`：把"智能体版本 → 技能版本"的绑定展开为本次 Run 可见的技能集合。
- `guard`：发布校验与静态提示扫描。
- `runner`：脚本运行入口，只接受已校验的版本和脚本声明，经 `CommandExecutorPort` 调用 `local` 后端。
- `projection`、`review` 本变更不实现。

依赖方向：`skills` 只依赖 `core` 与 `sandbox` 的端口，不导入 `platform`；平台侧的存储与授权放在 `nexus_platform` 中，通过端口注入。

### 数据

- `skills`：名称、所有者（租户或管理员）、来源（`builtin` / `installed`）、信任级别、创建时间。
- `skill_versions`：技能、版本号、正文、依赖声明（JSON）、内容哈希、发布人、发布时间，不可修改。
- `skill_version_files`：版本号、相对路径、大小、哈希、内容（文本或引用），单文件与总大小设上限。
- 绑定复用 `ResourceBindingRecord`（`kind='skill'`）。

迁移：新增上述三张表，属于持久化模型变更，需要用户确认后执行。

### 运行流程

1. Run 准备阶段解析智能体绑定的技能版本，生成系统提示中的索引（名称与简介）。
2. 模型调用 `load_skill` 获取正文；需要资源时调用 `read_skill_file`。
3. 模型调用 `run_skill_script`：
   - 工具存在性检查（门禁与智能体配置）；
   - 技能绑定检查；
   - 审批（写入审批记录，等待用户决定）；
   - 复制版本副本、校验哈希、运行、收集输出；
   - 写入审计，结果作为工具结果返回。
4. 每一步都重新查询数据库授权，不信任快照或模型参数。

### 与现有规则的关系

- 技能不授予权限。脚本只能完成它本身能做的事，且每次调用都经过审批。
- 脚本运行不改变 2.9 节的门禁规则，只是在门禁打开时提供能力。

## 接口与兼容性

- **新工具**：`load_skill`、`read_skill_file`、`run_skill_script`。未绑定技能或门禁关闭时不出现在工具列表中，既有智能体行为不变。
- **智能体配置**：新增 `skill_scripts.enabled`，默认 `true`（仅在门禁打开时有效）。既有智能体版本缺省视为 `enabled=true`，但因门禁关闭而不生效，行为与改动前一致。
- **事件**：新增 `skill.loaded`、`skill.script.started`、`skill.script.completed`。既有事件顺序不变。
- **配置文件**：新增 `[skills] allow_local_scripts`，默认 `false`。
- **HTTP**：新增技能与版本的只读接口（列表、详情、版本内容）；技能安装与发布接口仅管理员可用。

## 测试

- `loader`：frontmatter 合法与非法样例、名称与长度限制、保留词、越界路径。
- `versions`：内容哈希稳定；已发布版本不可修改。
- 门禁：三个条件各自缺失时工具均不出现；配置 `enabled=false` 时不出现。
- 运行：超时终止进程组、输出截断、环境变量白名单、副本哈希不一致时拒绝运行、审批拒绝时不运行。
- 审批：配置哈希变化后挂起审批失效。
- 绑定：未绑定技能的 `load_skill` 返回"不可用"，不泄露技能是否存在。
- 迁移往返（SQLite）。PostgreSQL 验证随 2.9。
- 不改变既有 Native golden 基线（`tests/test_native_engine_golden.py`）。

## 已确认的决定

以下由用户在对话中确认：

1. 执行方式：第一版只支持内联加载；脚本执行只在显式开发模式下开放（方案 1）。
2. 智能体配置：`skill_scripts.enabled`，默认开启，但只在门禁打开时生效。

## 待确认的细节（推荐值）

请在确认提案时逐项回复，未回复的按推荐值执行：

1. **门禁条件**：推荐采用上文三个条件同时满足，缺一不可。
2. **解释器白名单**：推荐 `python3`、`bash`、`node`。
3. **资源限制**：推荐超时默认 60 秒、上限 300 秒；输出 64 KB；单次运行最多 10 个脚本调用。
4. **审批粒度**：推荐每次调用都审批。脚本级"本次会话内放行"留到后续。
5. **内置示例**：推荐用两个示例技能验证端到端（一个纯内联，一个含脚本），内容另行编写。
6. **迁移**：推荐新增三张表，迁移随本变更一起提交，并在确认后执行。
7. **依赖工具校验**：推荐发布时只校验工具名是否存在，权限仍在运行时检查。
