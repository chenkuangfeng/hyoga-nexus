# Web 外壳改用 TDesign：侧栏、菜单与设置导航

## 状态

待确认。确认前不编码。确认后按 `tasks.md` 实施；功能清单与布局样式见 `design.md`，需要确认的项见本文件"需要你确认的项"。

## 背景

- 当前 `apps/web` 使用 Element Plus，20 个 Vue 文件使用 `el-*` 组件，导航是按权限分组的四组结构（工作台、空间、个人、平台管理）。
- WeKnora 的顶层菜单与设置分组与之不同，且它的前端完全基于 TDesign（`tdesign-vue-next`）。要达到"界面与 WeKnora 对齐"，外壳和导航必须与其一致，组件库也需要一致，否则每个组件都要手工模拟。
- 用户决定：组件库改为 TDesign；先完善外壳和菜单，包括设置中的全部分区；具体页面在实施到对应路线图步骤时再设计开发。

## 决定（取代已有提案中的相关条目）

1. **组件库改为 TDesign**（`tdesign-vue-next`，与 WeKnora 同版本；图标 `tdesign-icons-vue-next` 0.4.4）。本决定取代：
   - `2026-11-02-weknora-parity` 决定 1（"保留 Element Plus，不换 TDesign"）；
   - `2026-11-02-web-shell-layout` 范围外中"不引入 WeKnora 的 TDesign 组件或其配色"。
2. **顶层导航与 WeKnora 一致**：新建对话（下挂最近会话）、知识库、制品库、智能体、自动化、工具箱、组织、设置、退出。原四组分组（工作台、空间、个人、平台管理）取消，现有页面迁入设置或组织下（见 `design.md` 第 5 节）。
3. **设置包含 WeKnora 的全部分区与分组**（23 个设置项 + 集成下 7 个子项），分组结构沿用 WeKnora `views/settings/Settings.vue` 的七组。未实现的分区提供占位页，说明对应路线图步骤。
4. **本阶段只做外壳、导航、占位页与已有页面的迁移**，不实现知识库、智能体编辑器、自动化等新功能的业务界面，也不新增后端 API。

## 范围

范围内：

- **外壳**：TDesign 布局（侧栏 + 内容区），侧栏展开/折叠/拖拽调宽，窄屏抽屉。布局细节见 `design.md` 第 2 节。
- **顶层菜单**：第 1 节决定 2 中的 9 个入口，含新建对话的会话子列表（结构与入口，会话管理操作沿用 `2026-11-02-session-management`）。
- **设置**：分组导航与 23 个分区 + 7 个集成子项的路由与标题；每个分区要么迁入已有页面，要么显示占位页。清单见 `design.md` 第 4、5 节。
- **已有页面迁移**：`views/settings/*`、`views/auth/*`、`views/chat/*`、`views/OverviewView.vue` 等从 Element Plus 改为 TDesign，移除 `element-plus` 依赖。
- **路由**：沿用 `vue-router`（已存在）。旧路径（`/space/models` 等）保留重定向，`legacyHashRoutes` 同步更新。
- **测试**：更新 `tests/web/*.mjs` 中依赖 Element Plus 选择器与旧导航地址的用例；新增导航与占位页的用例。
- **i18n**：导航与分区标题走 `vue-i18n`（中文、英文同时补齐）。

范围外：

- 不实现任何分区的业务功能（知识库、沙箱、MCP、渠道等），占位页只说明状态与路线图步骤。
- 不改变 API、权限判断、数据模型或 Runtime 行为。权限仅影响"是否显示入口"，后端 RBAC 仍是最终依据。
- 不做全局命令面板（⌘K 全局搜索）；侧栏搜索按钮仅打开现有会话搜索。
- 不做深色主题切换入口（由 `2026-11-03-dark-theme` 负责），本阶段只保证 TDesign 的颜色走 token，便于其接入。

## 需要你确认的项

每项给出建议，你可以直接选择或修改。

1. **设置的呈现方式**：
   - A. 独立页面 `/settings/:section`（建议）：可深链、可刷新，与现有路由一致；视觉上采用 WeKnora 的左侧分组导航 + 右侧内容区。
   - B. 弹窗（WeKnora 的做法）：与 WeKnora 一致，但地址栏无法直接定位到分区，需要用查询参数维持深链。
2. **原排除项是否显示在导航中**：Ollama、WeKnora Cloud、嵌入式对话（embed）、CLI、Chrome 扩展、Claw 技能。`2026-11-02-weknora-parity` 已决定排除这些功能。
   - A. 不显示（建议，与已确认的排除决定一致）；
   - B. 显示为占位页，标注"暂不实现"。
3. **未实现的顶层菜单**（知识库、制品库、智能体、自动化、工具箱）是否显示：
   - A. 显示占位页（建议），让导航结构与 WeKnora 一致；
   - B. 没有实现前隐藏。
   - 制品库依赖沙箱能力，建议保持能力开关（沙箱未启用时隐藏）。
4. **Element Plus 迁移范围**：建议本阶段一次性迁移全部现有页面并移除 Element Plus，避免两套组件库并存（样式冲突、包体积翻倍）。代价是 20 个文件中的表单、弹窗、下拉都要改写，是本阶段最大的工作量。
5. **侧栏是否可拖拽调宽**：WeKnora 支持，建议本阶段实现（默认 260px，允许 200–400px，宽度存入 localStorage）。
6. **扩展能力的位置**（本仓库已有、WeKnora 没有的页面）：建议放入设置对应分区，见 `design.md` 第 5 节表格。特别是"原生运行设置"与"会话查询"，它们的归属需要你确认。

## 工作量（粗估）

单人加 AI 辅助，约 2–3 周：外壳与菜单 1 周；设置 30 个分区的导航与占位 0.5 周；现有页面迁移到 TDesign 并移除 Element Plus 约 1 周；测试与中英文文案 0.5 周。估计未经实际验证，取决于第 4 项的决定。

## 验收

- 所有顶层菜单与设置分区都能从导航到达，地址可直接访问并可刷新。
- 每个未实现分区显示统一的占位页，写明状态与路线图步骤；已迁入的页面功能与迁移前一致。
- 权限：管理员专属入口仅对对应角色显示；非授权用户访问地址时被重定向，后端权限不变。
- 宽度 375px、768px、1024px、1440px 下无横向滚动；侧栏可用键盘展开、折叠与切换。
- `apps/web` 中不再有 `element-plus` 依赖（若第 4 项选择迁移）。
- `pnpm build`（含 `vue-tsc`）与 `tests/web/*.mjs` 全部通过；`uv run --locked pytest` 不受影响。
- 中文与英文的导航与占位文案齐全。
