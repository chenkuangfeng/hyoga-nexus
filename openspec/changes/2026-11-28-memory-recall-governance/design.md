# 设计

## 1. 注入与召回策略

`budgets.memory` 增加 `profile`，仅显式为 true 时将已审核 Profile 注入模型；`recall` 改为自动逐轮召回开关，默认关闭。关闭自动召回不移除 `search_memory` / `read_memory` 工具，智能体仍可按需调用。会话索引快照只含有限条目目录，不含 Profile 正文；Profile 正文独立按当前 Run 设置生成，避免旧快照绕过关闭设置。

## 2. 事实身份与更新

记忆提议支持 `subject`、`attribute`、`scope` 与 `intent`。规则层将其规范化形成事实键，作为候选匹配和草稿的审计元数据；现有 topic、指纹、包含、冲突、相似逻辑保留为候选提示。只有显式目标 ID/base_version，或规范化事实键唯一匹配时才转为编辑；主题相同本身不再自动覆盖。提议更新须附来源证据；证据与来源消息 ID仍由服务器验证/关联。审核发布继续执行版本冲突保护。

## 3. 轨迹

`memory.used` 来源区分 `profile`、`auto_recall`、`tool_search`、`tool_read`。上下文来源只显示条目标题、版本及必要来源，不伪装成模型请求；工具调用仍按真实工具消息显示。详情通过持久化消息和 Run 轨迹请求快照关联。

## 4. 检索质量

向量仍是当前发布版本的派生数据，关键词/向量排名融合保持现状。新增确定性 eval 样例覆盖同义检索、同主题不同属性、否定纠正、时效范围、删除后不再召回和按需工具读取。阈值调整须基于评测结果，不凭单例提高相似度阈值。

## 5. 持久化与兼容

提议新增字段用可空列追加迁移；旧条目字段为空时只按精确指纹、明确 entry_id 或人工选择处理，不用旧 topic 自动推断新的事实身份。Agent JSON budget 新键无数据库迁移。用户已有的会话快照继续只作为目录快照；Profile 注入依据当前 Agent 版本显式设置实时判断。

## 6. 配置职责建议（待实施）

个人设置只保留“是否启用长期记忆”一个开关，适用于该用户在当前空间的记忆读取与写入；关闭后不删除其已保存记忆，只停止未来注入、召回和自动写入。个人记忆列表仍保留查看、审核、导出、归档等数据控制操作。

空间管理员配置空间是否启用记忆、自动/显式写入策略、抽取模型、容量与淘汰规则、向量模型、检索和保留策略；这些规则在企业管理端维护，服务端按空间统一执行。智能体配置只负责该智能体是否允许使用记忆、是否启用主动召回/Profile 注入及可用记忆工具，不维护空间级模型或容量。部署级密钥、存储、供应商连接和硬性安全上限由平台运维配置。

迁移时应将当前按用户保存的自动抽取模型与容量策略归并到空间策略，保留个人开关与已有记忆数据；需定义已有成员配置冲突时的迁移优先级及回滚方式，再单独实施数据库迁移和管理界面调整。
