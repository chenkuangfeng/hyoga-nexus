# 企业级员工智能体平台（SaaS 多租户）

## 状态

草案第二版（2026-11-11）。方向与此前的待确认项已由用户全部答复（见“已确认的方向”）；本版按答复调整了方案，等待用户对本版的最终确认后开始编码。

## 背景

现有底座里，运行时契约、ToolGateway 单调守卫、执行时复核授权、三类授权分离（ResourceGrant / ActionGrant / ActionApproval）、派发账本与审计都可以直接用于企业场景。偏 To C 的部分集中在“谁说了算”：

| 维度 | 现状（代码位置） | 企业场景的缺口 |
|---|---|---|
| 空间形态 | 自助注册可选个人空间或企业空间（`auth/accounts.py` `register`），登录默认进入个人空间；个人空间不属于任何企业 | 员工的内容和费用游离在企业之外；需要来回切换空间 |
| 企业微信 | 每个部署只有一个自建应用（`configs [wecom]`、`auth/wecom.py`），只做扫码登录与绑定，不自动开户，不同步通讯录 | 每家企业接入自己的企微自建应用；员工首次从企微进入即自动开户；部门、人员、在职状态随企微同步 |
| 私有内容 | 会话、记忆按本人隔离；自建智能体默认只有创建者可见（`agents/access.py`）；**知识库对本空间全体成员可读**（`knowledge/access.py` `can_read`） | 企业内缺少“只有我能看”的知识库 |
| 组织与授权 | `org_units` 每企业一棵树，但组织位置不参与授权（`2026-11-03-enterprise-personal-spaces` 决定 7） | 智能体与知识库无法按部门开放 |
| 企业管控 | 没有企业级策略；企业空间内可用个人模型与个人 Key；共享空间可以跨企业共享 | 企业需要统一控制自建、模型、外部共享与数据留存 |
| 知识库维护 | 只有空间 owner、admin 与库创建者能写（`can_write`） | 智能体的创建者要能维护自己智能体所用的知识库 |
| 前端 | `apps/web` 是一个 Vite 应用（WeKnora 副本）；一个 `Settings.vue` 混合了员工设置、空间管理与部署运维；保留了大量没有 Nexus 后端的 WeKnora 功能（助手、Ollama、WeKnora Cloud、CLI、Chrome 插件、Claw 技能、桌面壳）；本机 `pnpm build` 因内存不足失败 | 员工端与管理端要分开、各自精简；员工端要适配企微 H5 |
| 平台管理 | `/platform-admin` 与跨企业的 `/admin/*` 接口能看到所有企业的智能体与会话 | SaaS 下平台运维不应通过 Web 看到企业数据 |
| 成本 | 只有并发上限与后台模型限流 | 没有按企业、部门、个人的 Token 预算与用量报表 |
| 部署 | 默认 SQLite，PostgreSQL 目标环境验收（路线图 2.9）暂跳过 | SaaS 必须以 PostgreSQL 为事实源，多 worker 部署 |

## 已确认的方向（2026-11-11）

1. **SaaS 多租户，租户即企业**：一套部署服务多家企业，所有数据按企业（`tenants.kind = 'enterprise'`）隔离；不引入“企业 → 部门工作区”的空间层级，部门差异通过组织驱动授权表达。
2. **企业微信为主身份源与主入口，只支持自建应用**：每家企业在企微后台创建自己的自建应用，把凭据配置到 Nexus；支持扫码与企微内免登、首次进入自动开户、通讯录同步，并把企微作为对话入口（承接路线图 9.1）。不做代开发应用与第三方应用。
3. **取消独立个人空间，改为企业内的个人区**：员工私有的会话、记忆、智能体、知识库、产物都在企业内，归企业所有，按本人私有使用。现有个人空间数据：开发库直接删除。
4. **只有企业，没有试用或套餐之分**：自助注册即创建一家企业，注册人为 owner。只有一个成员的企业就是普通企业。
5. **员工自建智能体默认开放**：企业策略提供开关，可按企业关闭或限定部门。
6. **知识库维护**：自己创建的智能体，由创建者本人维护其绑定的知识库；其余知识库由企业管理员（owner、admin）与库创建者维护。
7. **个人模型默认关闭**：企业管理员可以按企业打开。**企微自动开户的默认角色为 `contributor`**。
8. **不做离职资产移交，不做审批路由**：离职只撤销企业成员身份，资产原样留在企业内；工具执行前的确认维持现状，由 Run 发起人本人确认。
9. **取消平台管理界面**：能按企业配置的（向量库、存储、解析引擎）并入企业管理后台；必须全部署统一的只通过 `configs/nexus.toml` 与命令行管理。删除跨企业的清单接口。平台运营（开通、停用、计费）不考虑。
10. **删除没有 Nexus 后端的 WeKnora 功能**：助手、Ollama、WeKnora Cloud、CLI、Chrome 插件、Claw 技能等（清单见决定 7）。
11. **前端拆成三个 Node 项目**：基于 pnpm workspace，`core`（共用组件、状态、hooks、请求层等通用部分，不单独部署）、员工工作台、企业管理后台。后端 API 保持一个服务。

## 决定

1. **租户形态**：
   - 只创建企业租户，不增加套餐或试用字段。自助注册时企业名称选填，不填则默认为“{显示名}的企业”，企业编码不填则自动生成，注册人为 owner。
   - 已登录用户仍可以再创建企业或加入其他企业，一个账号可以属于多家企业（沿用现状）。
   - 删除 `kind = 'personal'`：迁移删除现有个人空间及其数据（开发库），`kind` 只保留 `enterprise` 与 `system`。
2. **企业策略（`enterprise_policies`，每企业一行）**：只能收紧，不放宽平台已有的守卫。首批字段：
   - `self_build_agents`：`all`（默认）、`org_units`（只有列出的部门可以自建）、`none`；
   - `personal_models`：成员能否使用自己的模型与 Key，默认 `false`；
   - `external_sharing`：智能体、知识库能否共享到含其他企业的共享空间，默认 `false`；
   - `retention_days`：会话与运行事件的保留天数，空值表示不清理。
3. **企业内的个人区**：
   - 知识库增加 `visibility`：`private`（创建者，以及按决定 8 获得维护权的智能体创建者）或 `tenant`（全企业成员可读）；E4 再增加按部门、成员开放。新建知识库默认 `private`。企业 owner、admin 对私有库与对私有智能体一样有完全权限，用于治理。
   - 私有知识库绑定到其他人可用的智能体时，发布检查会拦截：库的可见范围必须覆盖智能体的使用范围。这沿用“共享智能体不扩大底层资源权限”的原则。
   - 会话、记忆、自建智能体、产物沿用现有的本人隔离规则。
4. **企业微信自建应用按企业接入**：
   - 新增 `tenant_wecom_apps`（每企业一行）：`corp_id`、`agent_id`、加密保存的应用 `secret` 与通讯录同步 `secret`、回调 `token` 与 `encoding_aes_key`，以及最近一次同步状态。`configs [wecom]` 删除，改为全部在企业管理后台配置。
   - 登录：扫码与企微内网页免登都按 `corp_id` 找到企业，再按 `(wecom, corp_id, userid)` 找到账号。**首次进入自动开户**：成员在自建应用的可见范围内、且已经同步到本企业时，创建账号并加入企业（`source = 'wecom'`，角色 `contributor`），不设置本地密码。
   - 通讯录同步：每天全量一次，加上回调增量。同步部门（`org_units.source = 'wecom'`）、成员、主部门、在职状态。手动维护的部门不受影响。
   - 离职：撤销企业成员身份，下一次请求与下一次工具调用即被拒绝；资产不移交。
5. **组织驱动授权**：智能体共享与资源授权的接收方，从“角色”扩展为“角色、部门（含子树）、成员”三种。部门授权在每次判断时按当前组织关系展开，调岗后下一次调用即生效。部门本身仍不继承空间角色（沿用 `2026-11-03` 决定 8）。
6. **企业级管理角色**：内置角色增加 `security_admin`（工具风险策略、企业策略）和 `auditor`（只读审计，默认看不到对话正文）。两者复用 `tenant_roles` 与 `authz/catalog.py`，新增 API 权限 `policy:manage` 与 `audit:read_content`。
7. **前端：三个 Node 项目与功能精简**（结构见 `design.md` 第 4 节，功能清单见第 5 节）：
   - `apps/web` 改为 pnpm workspace 根，下设 `core`（`@nexus-web/core`）、`workspace`（`@nexus-web/workspace`，员工工作台）、`admin`（`@nexus-web/admin`，企业管理后台）。`core` 以源码形式被两个应用引用，不单独构建与部署。
   - 员工工作台适配桌面与手机，是企微 H5 的入口；对外嵌入页 `embed.html` 作为工作台项目的第二个 Vite 入口保留（后端另提案）。企业管理后台只做桌面。
   - 两个应用各自构建、各自部署为静态站点：默认同域名不同路径（工作台在 `/`，管理后台在 `/admin/`），共用登录令牌；以后可以改为独立域名。
   - 删除：`/platform-admin` 与 `views/system/` 下的平台页面；助手（`components/assistant/`、助手设置）、Ollama、WeKnora Cloud 设置；集成页中的 CLI、Chrome 插件、Claw 技能、WeKnora API Key、WeKnora IM 渠道页（由管理后台的企业微信页取代）；工具箱中的本地浏览器连接；桌面壳绑定（`src/wailsjs/`、`/auth/auto-setup`）；以及上述功能独占的依赖、文案和测试。
   - 入口由 `/auth/me` 返回的 `entries`（`workspace`、`admin`）决定，前端不自行推断。管理类接口统一加前缀 `/api/v1/tenants/{id}/admin/...`，权限判断仍在每个接口内。
8. **知识库维护**：`can_maintain_content` 成立的条件是：调用者满足 `can_write`（企业 owner、admin 或库创建者）；或者调用者是某个本企业智能体的创建者（`agents.created_by`），且该智能体的草稿或已发布版本绑定了这个知识库。经角色授权获得智能体 `manage` 权限的人不因此获得维护权。开放的操作只限内容维护（上传、删除、重新解析文档，编辑分块与问答）。库的设置、删除、可见范围与共享仍属于企业 owner、admin 与库创建者。共享来的库在接收方仍然只读。
9. **取消平台管理界面**：删除跨企业的 `/api/v1/admin/tenants`、`/admin/summary`、`/admin/agents`、`/admin/sessions` 接口；`users.is_platform_admin` 只保留给命令行与内置技能导入接口。部署级配置的去向见 `design.md` 5.4。企业自行配置的外部向量库与存储后端连接，与模型调用共用同一套网络出口策略（默认只允许公网 HTTPS，拒绝私有地址）。
10. **SaaS 部署前提**：PostgreSQL 为事实源，`split` 模式加多 worker，Redis 事件通道。路线图 2.9 由“暂跳过”改为本提案的前置门禁。SQLite 保留给开发与单机部署。

## 范围

阶段划分见 `tasks.md`。每个阶段开始前，在 `design.md` 补齐该阶段的接口与表结构，并经用户确认。

- E0 知识库维护开放给智能体创建者（决定 8）。
- E1 租户与个人区：注册即创建企业、删除个人空间、私有知识库、企业策略、企业级管理角色、删除跨企业接口、PostgreSQL 门禁（决定 1、2、3、6、9、10）。
- E2 前端重构：pnpm workspace 三项目、功能精简、员工工作台与企业管理后台（决定 7）。
- E3 企业微信自建应用：按企业接入、免登与自动开户、通讯录同步、离职撤销成员身份、消息渠道（决定 4）。
- E4 组织驱动授权：智能体与知识库按部门、成员开放（决定 5）。
- E5 成本与配额：企业、部门、个人三级的 Token 预算与用量报表。超出后拒绝新 Run，进行中的 Run 不受影响。
- E6 数据治理：留存清理、审计导出。

范围外：

- 平台运营界面：企业审核开通、停用、上限设置、计费与支付。
- 离职资产移交、审批路由（上级或资源负责人审批、审批超时、审批待办、企微审批卡片）。
- 对外嵌入页的后端实现（另提案，功能清单先列在 `design.md` 5.3）。
- 企微代开发应用与第三方应用、飞书、钉钉、SAML、LDAP、SCIM。
- 知识库文档级 ACL 与源系统权限同步。
- 企业智能体目录与发布审核。

## 验收

- 自助注册创建企业，注册人为 owner，可以立即邀请成员、接入企微；不存在个人空间；登录后进入上次使用的企业，属于多家企业时可以切换。
- 新建知识库默认只有本人和企业 owner、admin 可见；改为全企业可见后，其他成员可读。绑定私有库的智能体，在共享给其他人时被发布检查拦截。
- 智能体创建者可以维护其智能体绑定的知识库内容，不能删除库、修改设置、可见范围或共享；只经角色授权获得 `manage` 的人不能维护；解除绑定后失去维护权。
- 企业策略关闭自建后，没有资格的成员创建智能体返回 403；`personal_models` 关闭时个人模型不能选择、不能执行；`external_sharing = false` 时不能共享到含其他企业的共享空间。
- `apps/web` 下 `pnpm -r build` 产出工作台与管理后台两份静态产物；工作台产物不含管理后台代码；`core` 没有独立产物。工作台在手机宽度下可用；没有治理权限的成员进入管理后台被拒绝，管理接口返回 403。
- 决定 7 列出的 WeKnora 功能在代码、路由、文案与依赖中均已移除。
- `/platform-admin` 与跨企业的 `/admin/*` 接口已删除；企业管理员把向量库或存储指向私有地址时被拒绝。
- 在企微自建应用可见范围内的成员首次扫码或免登，即自动进入企业；不在范围内的成员被拒绝。离职同步后，该成员的下一次请求与下一次工具调用都被拒绝。
- 按部门共享的智能体：调入该部门的人立即可用，调出的人立即不可用。
- `uv run --locked pytest` 覆盖以上后端分支；浏览器测试覆盖两个应用；PostgreSQL 目标环境通过路线图 2.9 的全部项目。
