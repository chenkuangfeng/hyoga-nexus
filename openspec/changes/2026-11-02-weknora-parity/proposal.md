# 对齐 WeKnora 的界面与功能，并在其上扩展

## 状态

已确认（2026-11-01）。功能清单与映射见 design.md。各阶段在开始前各自拆分为子提案，经用户确认后再编码。

## 背景

用户要求：完全参照 WeKnora（`Tencent/WeKnora`，MIT 许可）的界面，覆盖其功能，然后在这些功能上扩展本仓库已有的能力（记忆治理、组织访问、运行状态机、所有者密钥）。

分析结果：WeKnora 的前端约有 160 个视图与 96 个组件，使用 TDesign（`tdesign-vue-next`，99 个文件）、Pinia 与 vue-i18n；后端是 Go 服务，包含文档解析、向量与图检索、沙箱、浏览器自动化和 IM 渠道。它不是一次界面替换能完成的范围，需要分阶段。

本仓库已有的部分：外壳与侧栏、认证（账号密码与企业微信）、空间、角色、组织、模型设置、记忆、对话与模型分支、Native 运行与审批。路线图第 6、7、8、9 步分别覆盖知识库、技能与 MCP、沙箱、渠道。

## 已确认的决定

1. **组件库**：保留 Element Plus，不换 TDesign。界面的布局、间距、配色、导航与交互按 WeKnora 复刻（以截图逐页比对）。
   > 待确认的理解：用户原话为"不换，完全模拟它"。这里理解为"保留 Element Plus，在其上完整复刻 WeKnora 的视觉与交互"。若用户指的是别的意思（例如保留现有页面而只复刻侧栏），在第 1 阶段子提案开始前再次确认。
2. **实施顺序**：第 1 阶段外壳与对话；第 2 阶段设置与系统管理；第 3 阶段知识库（路线图第 6 步）；第 4 阶段技能、MCP、沙箱（路线图第 7、8 步）；第 5 阶段智能体编辑器、制品、自动化、工具箱；第 6 阶段渠道（路线图第 9 步）。
3. **排除项（本轮先跳过）**：Ollama 分区、WeKnora Cloud 分区、CLI 与 Chrome 扩展落地页、小程序（miniprogram）、嵌入式聊天（embed）、开发用的 Markdown 测试页。
4. **后端实现**：WeKnora 的 Go 后端不复制代码，按其逻辑在本仓库的 Python 后端重写（符合 AGENTS.md 的参考规则）。
5. **语言**：中文与英文一次加齐，使用 i18n 框架（vue-i18n 或等价方案）管理所有界面文案，不再只做简体中文。

## 范围

范围内（按阶段，见 tasks.md）：

1. **界面复刻**：按 WeKnora 的布局、组件与交互重做各页面，包括顶级导航（新建对话与最近会话、知识库、制品库、智能体、自动化、工具箱、组织、设置）。
2. **对话**：会话置顶、重命名、清空、批量管理；工具结果卡片；审批与追问卡；深度思考；子智能体与后台任务展示。
3. **设置**：WeKnora 的分区结构；保留能在本仓库实现的分区，其余标明为计划。
4. **知识库**（路线图第 6 步）、**技能与 MCP**（第 7 步）、**沙箱**（第 8 步）、**渠道**（第 9 步）：按路线图实施，界面与 WeKnora 对齐。
5. **系统管理**：用户、审计日志、运行队列、平台 API 密钥的界面。
6. **扩展**：在对齐的界面中加入本仓库的能力（记忆审核与快照、组织访问标记、运行状态与所有者密钥）。

范围外：见决定 3。

## 验收

- 每个纳入阶段的页面与 WeKnora 对应页面的布局、导航与主要交互一致（以截图逐页比对）。
- 中文与英文的界面文案齐全，切换语言后无遗漏的硬编码文案。
- 每个阶段有 OpenSpec 子提案，确认后实施；功能契约与权限变化不得绕过确认。
- 后端功能有 pytest 覆盖；界面有浏览器测试。
- 扩展能力（记忆、组织、运行）在对齐后的界面中可用，且不改变已有的权限判断。
