# 实施路线图

状态：2026-10-31。架构与模块设计见 [architecture.md](architecture.md)；本文件只记录最终计划的步骤、子步骤、验收与门禁。计划调整通过 OpenSpec 变更提案管理，不在此记录。

## 1. 原则

- 步骤按序号依次推进；一个步骤可包含若干子步骤，子步骤完成后打勾。
- 每个步骤结束时必须有可验收结果；验收未通过不进入依赖它的步骤。未通过的门禁须明确记录并告知用户。
- 外部依赖（PostgreSQL、真实模型、Codex/Claude 账号、观澜数据源）未验证前，不宣称对应功能可用。
- 涉及 API 契约、权限规则、持久化模型或 Runtime 行为变化的调整，先通过 OpenSpec 提案并获确认，再修改本路线图。
- 参考项目只借鉴设计并按需等价翻译，不整体嵌入；迁移时保留来源、版本与许可声明，记录在迁移提交或代码文件头中。

## 3. 步骤

### 1. 工程骨架

### 2. 平台底座

- **目标**：身份、空间、授权、智能体、会话、幂等运行与事件的本地实现。
- **子计划**：
  - [x] 2.1 身份与空间：用户、外部身份、租户与成员关系。
  - [x] 2.2 认证：本地账号密码、服务端会话、企业微信绑定与登录（OpenSpec `local-login-and-wecom`，已归档）。
  - [x] 2.3 授权：租户角色、菜单与 API 授权，智能体级授权，资源授权。
  - [x] 2.4 智能体与会话：智能体版本、Session、会话分叉。
  - [x] 2.5 运行：幂等 Run、事件、Outbox、租约领取、取消、审批与输入。
  - [x] 2.6 模型设置：供应商、个人与空间范围、加密 Key、默认模型、连接测试。
  - [ ] 2.7 PostgreSQL 目标环境验证：迁移往返、并发领取、租约恢复、崩溃后 interrupted 转换、同 Session 单活跃 Run。
- **验收**：本地（SQLite）测试通过。2.7 暂跳过（用户决定当前版本使用 SQLite）。

### 3. Native 基础闭环

### 4. 核心契约与平台收敛

- **目标**：锁定运行时契约，补齐平台底座的 PostgreSQL 验收与后续能力所需的数据结构。
- **子计划**：
  - [ ] 4.1 `nexus_core.runtime` 定义 `AgentRuntime` 端口、`RunEvent` 类型、`RuntimeCapabilities`，与现有 Native 契约对齐。
  - [ ] 4.2 增量迁移：`action_grants`（与 `resource_grants` 分离）、`run_snapshots`（等待审批的版本化快照）。
  - [x] 4.3 `memory` 独立包，规则与存储端口分离。
  - [ ] 4.4 PostgreSQL 目标环境集成测试（见 2.7）。
  - [ ] 4.5 架构文档与仓库断链检查。
- **验收**：契约测试通过；目标 PostgreSQL 上测试全部通过，并记录环境、版本与结果；`git diff --check` 通过。
- **依赖**：3。
- **阻碍**：需要目标 PostgreSQL 环境（当前暂跳过）。

### 5. Native 引擎补齐

- **目标**：拆分引擎组件，补齐与 GenericAgent、WeKnora 的行为差距。
- **子计划**：
  - [ ] 5.1 拆分 `RunOrchestrator`、`TurnExecutor`、`CompletionJudge`、`ToolDispatcher`、`ContextAssembler`，每个组件有独立测试。
  - [ ] 5.2 完成判断：截断续写、空响应重试、重复内容停滞、不完整工具调用。
  - [ ] 5.3 前缀冻结：系统提示与工具 schema 在 Run 内不变。
  - [ ] 5.4 工具结果投影与 Spill 工件存储（工件只在 run 级目录）。
  - [ ] 5.5 证据句柄登记 `[ID:n]`，供步骤 8 使用。
  - [ ] 5.6 行为矩阵：关键行为逐条映射到测试，记录于 `packages/runtimes/docs/`。
- **验收**：行为矩阵全部通过；现有 Native 测试保持通过；无隔离后端时执行类工具不可见。
- **依赖**：4。

### 6. Codex 适配器

- **目标**：以 `openai-codex` SDK 管进程，事件与审批经 app-server 协议获取。
- **门禁**：确认 SDK 是否暴露底层 JSON-RPC 通道。结论决定连接方案，方案变更通过 OpenSpec 记录。
- **子计划**：
  - [ ] 6.1 能力探测（版本、`initialize` 能力）。
  - [ ] 6.2 会话映射（`runtime_session_bindings`）、`thread/start`、`thread/resume`、`thread/fork`。
  - [ ] 6.3 事件映射与终态映射。
  - [ ] 6.4 审批桥：命令与文件变更审批转为 `approval.requested`；`acceptForSession` 先经 `action_grants` 批准。
  - [ ] 6.5 取消（`turn/interrupt`）与 `interrupted` 终态。
  - [ ] 6.6 平台 MCP 服务的运行令牌（与步骤 9 共用）。
  - [ ] 6.7 测试：假 app-server 协议测试；真实 Codex CLI 集成测试（账号可用时）。
- **验收**：同一契约测试集在 Native 与 Codex 上终态一致；审批可拒绝；取消生效；原生文件与 shell 限制在工作区内；无法约束的能力标记 unverified 且不可绑定。
- **依赖**：5；Codex 账号与 CLI 版本。

### 7. Claude Code 适配器

- **目标**：以 `claude-agent-sdk` 封装 `ClaudeSDKClient`。
- **门禁**：读取官方文档，核对 `can_use_tool`、hooks、`resume`、`fork_session` 的实际行为并锁定版本，结果同步更新 [architecture.md](architecture.md) 第 2.4 节。
- **子计划**：
  - [ ] 7.1 `can_use_tool` 审批桥；`disallowed_tools` 禁用原生工具。
  - [ ] 7.2 会话 resume 与 fork。
  - [ ] 7.3 工具桥（复用步骤 6 的 MCP 服务）。
  - [ ] 7.4 测试：复用步骤 6 的契约测试集。
- **验收**：契约测试通过；原生工具禁用测试通过；未核对的能力保持 unverified。
- **依赖**：6；本机 Claude Code CLI 与账号。

### 8. 知识库

- **目标**：文档生命周期、混合检索、引用；图谱作为可选增强。
- **子计划**：
  - [ ] 8.1 知识库、文档、版本、解析与索引任务、文本块与引用契约；上传、去重、版本；可恢复的后台解析（文本、Markdown、PDF）。
  - [ ] 8.2 Pre-Filter 授权后再检索；关键词与向量混合；`search_knowledge`、`read_document`、`list_documents`；证据登记。
  - [ ] 8.3 管理页与检索测试入口；评估集。
  - [ ] 8.4 （可选，按库启用）图谱抽取、归一、版本切换、有界图检索、降级。
- **验收**：同一智能体可绑定多个库；无权资源不泄漏；基础检索不依赖图谱；撤权、删除、索引重建同步生效；图服务故障时降级可见。
- **依赖**：5。
- **待确认**：向量服务与图数据库产品，在 8.1 前的技术验证后确定。

### 9. 技能与 MCP

- **目标**：版本化技能、渐进披露、依赖校验；MCP 按工具启用。
- **子计划**：
  - [ ] 9.1 技能：版本、`SKILL.md` 与资源、依赖声明、发布前依赖校验、来源检疫、草稿与审核发布。
  - [ ] 9.2 MCP 客户端：发现工具、按工具启用、凭据引用、高风险工具审批。
  - [ ] 9.3 MCP 服务端：运行令牌，每次调用复核权限。
- **验收**：两个技能与授权 MCP 工具协同执行；缺失权限或依赖时明确报错并阻止发布；撤权后下一次调用拒绝；产物可按授权下载。
- **依赖**：5、8。

## 5. 测试与评估

- 每个步骤运行涉及的单元与集成测试，以及前端构建（`npm run build`）；聊天交互变化时运行 `npm run test:browser`。

- 策略回测与软件回归分开记录。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Codex app-server 为实验性或版本变化快 | 适配器失效 | 锁定版本；能力探测；契约测试 |
| Claude SDK 的权限与 resume 行为与摘要不一致 | 审批或会话错误 | 步骤 7 前读官方文档，未核对不承诺 |
| 外部 Runtime 原生工具越权 | 数据泄露或误操作 | 工作区隔离、禁用原生工具；无法约束则不允许绑定 |
| 账号或模型不可用 | 无法验收 | 由用户提供；未验收不宣称 |
| 参考项目许可证 | 合规风险 | 迁移前核对许可证并保留声明；非 MIT/Apache 项目仅借鉴设计 |
| 范围过大 | 交付延迟 | 严格按步骤验收推进；Native 与 Codex 先行 |
| Native 迁移引入的复杂度 | 行为回归 | 行为矩阵与组件测试；拆分后逐组件验证 |
| 仅在 SQLite 上验证 | PostgreSQL 环境下行为未知 | 部署到 PostgreSQL 前补做 2.7 |
