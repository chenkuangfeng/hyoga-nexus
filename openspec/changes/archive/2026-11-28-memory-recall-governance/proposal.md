# 记忆按需召回与事实治理

## 动机

目前每次 Run 都会注入记忆索引，Profile 正文也可能自动进入模型上下文；开启自动召回时，每个用户输入还会触发关键词/向量检索。用户希望由智能体在确有需要时主动搜索长期记忆，同时避免同主题但不同事实被错误合并，并能在轨迹中看清记忆来源。

## 范围

1. 将 Profile 常驻注入、逐轮自动召回、模型主动搜索读取拆成独立行为与设置；默认不注入 Profile、不逐轮自动召回，记忆工具仍按现有权限执行。
2. 保留受限的索引目录和按需读取，控制提示词占用，并确保新设置对新旧会话一致生效。
3. 加强记忆提议的事实身份字段与证据要求，只有明确同一事实时才建议更新；模糊候选作为提示，不静默覆盖。
4. 轨迹区分 Profile 注入、自动召回、主动搜索、主动读取，并展示条目、版本与来源。
5. 记录检索渠道与结果质量所需的非敏感观测，补充离线评估样例和可调检索策略。
6. 梳理记忆设置的职责边界：个人管理自己的启用开关和记忆数据；空间管理员维护空间级总开关、写入模式与检索策略；智能体版本维护自动提炼模型和容量策略；部署密钥与硬性限制由运维管理。旧成员配置作为历史 Agent 的兼容默认值。

## 非目标

- 不删除已发布记忆或历史版本，不自动发布草稿。
- 不让管理员或其他用户跨越所有者边界读取个人记忆。
- 不引入新的向量数据库；继续使用现有向量与关键词后端。
