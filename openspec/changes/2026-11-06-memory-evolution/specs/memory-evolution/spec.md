# 规格：长期记忆演进

来源：`openspec/changes/2026-11-06-memory-evolution`（草案，待确认）。

## 需求

### R1 不自动发布
- 抽取、合并、兴趣晋升、外部提供方产生的内容只能成为草稿；只有所有者审核后才能发布。
- 草稿在发布前不进入任何系统提示、常驻块、主动召回或检索结果。

### R2 抽取来源与证据
- 自动抓取只从来源属于白名单的用户消息中提取；助手消息只能作为只读上下文，工具消息不进入抽取请求。
- 窗口内没有用户消息时，跳过任务，不调用模型。
- 抽取项必须带至少一条原文证据，且证据规范化后必须是对应用户消息的子串，否则丢弃。
- 重要度 ≤2 且置信度为 low 的项不建草稿，只在审计中计数。

### R3 更新优先于新增
- 抽取项的主题或内容匹配到已发布条目时，生成带 `base_version` 的更新草稿。
- 规范化后被已有内容包含的新内容视为重复。
- 疑似冲突和近似重复只作为草稿上的提示，不阻止创建草稿。

### R4 被拒内容
- 拒绝草稿时，墓碑记录主题；最近被拒的主题会提供给抽取模型。
- 与墓碑指纹相同的内容不得再次成为草稿。

### R5 快照与注入
- 会话快照包含容量头、`profile` 常驻块（不超过 1000 字，用资料标签包裹）和索引；创建后不变。
- 索引超长时按重要度、最近使用、更新时间排序后截断。
- 每轮主动召回只注入本轮用户消息一侧，不改变系统前缀，也不写入消息表；最多 5 条、600 字。

### R6 可见性与确认
- 本轮注入或读取的记忆以 `memory.used` 事件记录。
- 前台草稿以 `memory.draft_proposed` 事件记录，所有者可以在对话内发布或拒绝；已处理的草稿返回冲突。

### R7 维护
- 语义合并只产生 `merge` 草稿；发布时追加保留条目的版本并归档其余条目，任一条目版本变化时返回冲突。
- 被拒草稿保留 30 天，已结束的抓取任务保留 14 天；审计、版本、墓碑永久保留。

### R8 历史会话检索
- `search_conversations` 和 `read_conversation` 只返回调用者本人在本空间、且有权查看的历史会话消息，并排除当前会话。
- 记忆关闭时，这两个工具不可用。

### R9 语义能力与扩展
- 未配置 Embedding 或向量调用失败时，检索结果与只用关键词时一致。
- 兴趣只以草稿形式产生，被拒主题不再计数。
- 文档亲和度加权不超过 1.15 倍，只在知识检索可用后启用。
- 外部记忆提供方失败或超时时，Run 照常完成，且其写入只能成为草稿。

### R10 开关
- 三级开关中任一级关闭时，本变更新增的注入、工具、事件、抓取、合并、计数、向量生成全部停止；已有数据保留。
