# 设计

聊天页顶部仅显示靠左的三个标签，会话头部标题和快捷操作从该页移除。轨迹活动步骤由持久化会话消息及工具结果构成，不读取 RunEvent；独立模型请求记录用于把请求/响应快照和用量关联到具体助手消息或工具调用。Runtime 在请求发出前保存模型输入和工具目录快照，请求结束后按同一记录 ID 补写输出、供应商 usage、状态和 Run 累计 token；记录只允许从 running 转为一个终态。开始和结束写入都校验 Run 租约。API 先使用现有 Run 授权再读取记录。前端按消息步骤展示紧凑列表，选中单条消息或工具活动时，详情检查器只显示本步骤信息及其关联模型请求。当前正在执行的 Run 通过轻量轮询读取新记录，完成后停止轮询。历史 Run 即使没有新表记录，仍显示持久化消息步骤，不从事件推测伪请求详情。

实现参考 DeepSeek Harness `packages/client/ui-trajectory/src/client/TrajectoryTable.tsx` 的两列事件/内容表、可键盘选择的记录行与点击检查器，以及 `trajectory-record.ts` 的类型化记录详情。Nexus 使用持久化消息/工具结果作为步骤，并以数据库模型请求快照补充对应请求信息，不将 RunEvent 直接投影为轨迹行；不复制参考项目的完整虚拟化时间轴。

活动行使用会话已持久化的 `MessageRecord` 呈现用户与助手文本，工具结果以 opaque call ID 与模型响应快照中的调用配对；Run 轮次用于展示，不用于调用归属，因恢复执行后轮次不会从 1 重新开始。消息接口仅返回 assistant 消息内的调用 ID，不额外暴露整份 `runtime_metadata`。模型请求 usage 汇总到对应助手活动行；顶部缓存命中卡片汇总 `usage.cache_read`，仅当输入用量有效时计算占比。模型请求计数仍按独立轨迹表记录计算。

模型请求快照中含 `<user_memory>` 内容时，额外展示记忆活动，覆盖 system 消息中的常驻画像以及 user 消息中的按需召回。这是本 Run 的模型上下文组成部分，不代表模型调用了 `read_memory` 工具；显式记忆工具仍作为普通工具活动显示。相同的记忆块在同一 Run 的多个模型请求中去重，列表仍以请求快照为依据，不读取 RunEvent。

列表先按会话中 Run 的首次活动时间分组，但不显示独立的 Run ID 数据行；Run 边界通过用户输入行上的 1px 中性色细线标出。每条用户输入作为可折叠活动分组标题，子活动使用缩进和中性层级线。未选中活动时列表铺满可用空间，选择单条消息或工具活动后，右侧仅显示该步骤内容及直接关联的模型请求、用量；工具步骤默认打开工具详情，不关联当前步骤的标签隐藏。工具/技能默认只列名称，展开单项后显示完整参数和结果。表格列固定为活动、内容、Token，数据行高 20px；用单行省略控制长文本，Token 列在数据可用时标明实际值或估算值，详情检查器继续提供完整正文。
