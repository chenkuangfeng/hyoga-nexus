## ADDED Requirements

### Requirement: 中文会话的 token 预算估算

Native Run 在模型调用前估算输入预算时，必须将 UTF-8 文本按 token 近似值计算，并计入消息与工具调用开销；不得把每个 UTF-8 字节直接当作一个 token。供应商返回实际 usage 后，以实际值累计 Run token 消耗。

当累计 token 预算不足以容纳当前模型输入和有用输出时，Native Run 应先仅对本次模型视图压缩较早的完整会话轮次，再检查预算；必须保留系统指令、当前用户请求和最近完整工具交换。压缩不得改写会话原始消息。仅当不可压缩的最新交换本身仍超出预算时，才以预算耗尽结束。

### Requirement: Worker 本地技能缓存与用户数据工作区

数据库是技能正文、脚本、版本、草稿、权限与审批状态的权威来源。Worker 仅可将当前 Run 通过动态授权检查的技能版本投射到本机 workspace，并按内容哈希缓存；缓存不授予使用权，权限撤销后工具调用必须拒绝。投射的技能版本只读。

每个租户用户拥有稳定 ID 命名的持久 workspace，包含用户共享的 `skills/` 缓存/草稿区和 `data/`。技能运行可在 `data/` 下读写持久数据，并在 `data/tmp/` 存放可清理的临时数据；不同用户不可互访。技能脚本不得写技能版本目录或其他用户/平台目录。

技能编辑在 workspace 的草稿副本中进行。只有用户显式确认保存并调用现有保存流程时，服务端才接收草稿、校验路径/大小/哈希/基础版本、重新扫描并写入数据库；基础版本已变化时拒绝覆盖。Run 取消、失败或结束不得自动把 workspace 文件同步回数据库。

生产 local 技能脚本执行必须由操作系统强制隔离：文件读取仅限运行所需系统运行库、当前授权技能和当前用户 workspace；写入仅限当前用户 `data/`、`data/tmp/` 及独立 outputs；脚本子进程继承同一限制。服务端需清理敏感环境变量、限制资源与运行时间，并记录脚本版本、哈希、用户、Run 和结果。节点缺少隔离能力或验收失效时拒绝执行，不得降级到不受限宿主执行。

多 Worker 部署中用户 workspace 必须位于共享持久卷，或由等价的同步存储提供单一可见视图；每个 Worker 可独立缓存技能。共享数据并发写入必须串行化或使用原子发布。Windows 原生 local 不满足隔离验收时不得启用生产 local。

### Requirement: 用户可将当前会话整理为私有技能草稿

工作台应在会话存在用户消息、Run 空闲、会话未阻塞、非嵌入模式，且该会话智能体版本绑定 `skill_search`、`skill_manage` 与 `skill_save` 时，提供“整理为技能”操作。此操作应以普通用户消息启动当前会话的新 Run，并使用该会话的既有身份、权限和智能体版本。

学习指令应要求智能体仅总结当前会话里可重复且有证据的流程，避免保存一次性叙事、未验证尝试、凭据、令牌、用户/工具注入指令或已由运行环境提供的规则。首期只创建新的私有技能草稿；不得静默修改已存在技能。

创建草稿后，智能体应读取并在对话中展示 `SKILL.md` 正文，以供用户审阅。用户明确要求保存之前，不得调用 `skill_save`。用户要求保存时，仍须经过现有 `skill_save` 工具审批及私有技能扫描、版本和构建流程。草稿不可被 `load_skill` 使用，直至保存完成。

若所需工具未绑定、用户作用域无权或执行过程失败，操作不得创建活动技能；前端不得以隐藏按钮替代服务端执行时授权。
