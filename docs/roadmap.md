# 实施路线图

状态：2026-10-31。架构与模块设计见 [architecture.md](architecture.md)；本文件只记录大步骤、子步骤、验收与门禁。中间调整不在此记录，通过 OpenSpec 变更提案管理。

## 1. 原则

- 每个大步骤结束时必须有可验收结果；验收未通过不进入依赖它的步骤。未通过的门禁须明确记录并告知用户。
- 外部依赖（PostgreSQL、真实模型、Codex/Claude 账号、观澜数据源）未验证前，不宣称对应功能可用。
- 涉及 API 契约、权限规则、持久化模型或 Runtime 行为变化的调整，先通过 OpenSpec 提案并获确认，再修改本路线图。
- 参考项目只借鉴设计并按需等价翻译，不整体嵌入；迁移时保留来源、版本与许可声明（见 [architecture.md](architecture.md)）。

## 4. 框架重构（R0–R9）

### R0 清理与契约

- **目标**：确认架构文档，锁定 core 契约。
- **子步骤**：
  - [x] 架构文档以模块与参考来源为核心重构。
  - [ ] `nexus_core.runtime` 定义 `AgentRuntime` 端口、`RunEvent` 类型、`RuntimeCapabilities`，并与现有 P2 契约对齐。
  - [ ] 契约测试与断链检查。
- **验收**：契约测试通过；仓库无断链；`git diff --check` 通过。
- **依赖**：无。

### R1 平台底座收敛

- **目标**：补齐 PostgreSQL 验收，为计划能力准备数据结构。
- **子步骤**：
  - [ ] 增量迁移：`action_grants`（与 `resource_grants` 分离）、`run_snapshots`（等待审批的版本化快照）。
  - [x] `memory` 独立包，规则与存储端口分离。
  - [ ] 在 `NEXUS_TEST_POSTGRES_URL` 上运行集成测试：迁移往返、并发领取、租约恢复、同 Session 单活跃 Run。
- **验收**：目标 PostgreSQL 上全部通过，并记录环境、版本与结果。
- **依赖**：R0。
- **阻碍**：需要目标 PostgreSQL 环境（当前暂跳过）。

### R2 Native 引擎补齐

- **目标**：拆分引擎组件，补齐与 GenericAgent、WeKnora 的行为差距。
- **子步骤**：
  - [ ] 拆分 `RunOrchestrator`、`TurnExecutor`、`CompletionJudge`、`ToolDispatcher`、`ContextAssembler`，每个组件有独立测试。
  - [ ] 完成判断：截断续写、空响应重试、重复内容停滞、不完整工具调用。
  - [ ] 前缀冻结：系统提示与工具 schema 在 Run 内不变。
  - [ ] 工具结果投影与 Spill 工件存储（工件只在 run 级目录）。
  - [ ] 证据句柄登记 `[ID:n]`，供 R5 使用。
  - [ ] 行为矩阵：关键行为逐条映射到测试，记录于 `packages/runtimes/docs/`。
- **验收**：行为矩阵全部通过；现有 P2 测试保持通过；无隔离后端时执行类工具不可见。
- **依赖**：R0、R1。

### R3 Codex 适配器

- **目标**：以 `openai-codex` SDK 管进程，事件与审批经 app-server 协议获取。
- **门禁**：确认 SDK 是否暴露底层 JSON-RPC 通道。结论决定连接方案，方案变更通过 OpenSpec 记录。
- **子步骤**：
  - [ ] 能力探测（版本、`initialize` 能力）。
  - [ ] 会话映射（`runtime_session_bindings`）、`thread/start`、`thread/resume`、`thread/fork`。
  - [ ] 事件映射与终态映射。
  - [ ] 审批桥：命令与文件变更审批转为 `approval.requested`；`acceptForSession` 先经 `action_grants` 批准。
  - [ ] 取消（`turn/interrupt`）与 `interrupted` 终态。
  - [ ] 平台 MCP 服务的运行令牌（与 R6 共用）。
  - [ ] 测试：假 app-server 协议测试；真实 Codex CLI 集成测试（账号可用时）。
- **验收**：同一契约测试集在 Native 与 Codex 上终态一致；审批可拒绝；取消生效；原生文件与 shell 限制在工作区内；无法约束的能力标记 unverified 且不可绑定。
- **依赖**：R2；Codex 账号与 CLI 版本。

### R4 Claude Code 适配器

- **目标**：以 `claude-agent-sdk` 封装 `ClaudeSDKClient`。
- **门禁**：读取官方文档，核对 `can_use_tool`、hooks、`resume`、`fork_session` 的实际行为并锁定版本，结果写入 [architecture.md](architecture.md)。
- **子步骤**：
  - [ ] `can_use_tool` 审批桥；`disallowed_tools` 禁用原生工具。
  - [ ] 会话 resume 与 fork。
  - [ ] 工具桥（复用 R3 的 MCP 服务）。
  - [ ] 测试：复用 R3 的契约测试集。
- **验收**：契约测试通过；原生工具禁用测试通过；未核对的能力保持 unverified。
- **依赖**：R3；本机 Claude Code CLI 与账号。

### R5 知识库

- **目标**：文档生命周期、混合检索、引用；图谱作为可选增强。
- **子步骤**：
  - [ ] 知识库、文档、版本、解析与索引任务、文本块与引用契约；上传、去重、版本；可恢复的后台解析（文本、Markdown、PDF）。
  - [ ] Pre-Filter 授权后再检索；关键词与向量混合；`search_knowledge`、`read_document`、`list_documents`；证据登记。
  - [ ] 管理页与检索测试入口；评估集。
  - [ ] （可选，按库启用）图谱抽取、归一、版本切换、有界图检索、降级。
- **验收**：同一智能体可绑定多个库；无权资源不泄漏；基础 RAG 不依赖图谱；撤权、删除、索引重建同步生效；图服务故障时降级可见。
- **依赖**：R2。
- **待确认**：向量服务与图数据库产品，在本步骤技术验证后确定。

### R6 技能与 MCP

- **目标**：版本化技能、渐进披露、依赖校验；MCP 按工具启用。
- **子步骤**：
  - [ ] 技能：版本、`SKILL.md` 与资源、依赖声明、发布前依赖校验、来源检疫、草稿与审核发布。
  - [ ] MCP 客户端：发现工具、按工具启用、凭据引用、高风险工具审批。
  - [ ] MCP 服务端：运行令牌，每次调用复核权限。
- **验收**：两个技能与授权 MCP 工具协同执行；缺失权限或依赖时明确报错并阻止发布；撤权后下一次调用拒绝；产物可按授权下载。
- **依赖**：R2、R5。

### R7 沙箱后端

- **目标**：评估候选后端，选择通过隔离验收的实现。
- **子步骤**：
  - [ ] `CommandExecutorPort` 与 `FileStorePort` 的实现（候选：docker、ssh）。
  - [ ] 租约、虚拟路径映射、原子写入、产物收集。
  - [ ] 隔离验收：CPU、内存、时间、输出限制；网络隔离；用户隔离；清理；崩溃后残留检查。
- **验收**：隔离验收全部通过后，才注册任意代码与文件写入工具；未通过则工具不可见。
- **依赖**：R6。
- **待确认**：部署环境与可用的容器运行时。

### R8 渠道与治理

- **目标**：IM 渠道接入与运行评估。
- **子步骤**：
  - [ ] 企业微信优先，随后微信、QQ：消息标准化、身份映射、会话映射、去重、鉴权、回复限制、重试。
  - [ ] 运行评估集：固定任务、检索引用正确率、技能选择准确率。
  - [ ] 记忆与技能草稿的审核流程。
- **验收**：授权用户从渠道发起任务并获得可追溯回复；其他用户不能混入会话；评估集可重复运行。
- **依赖**：R2；企业微信可在 R6 后提前。
- **待确认**：各渠道接入方式与账号条件。

### R9 股票研究（最后一期）

- **目标**：观澜数据平台与股票研究技能合并交付。
- **子步骤**：
  - [ ] 数据适配器与调度：行情、交易日历、财务、公告、热点、龙虎榜；逐接口验证；失败重试与降级标注。
  - [ ] 数据时点与来源：每条数据保留 provider、获取时间、数据时点、复权口径。
  - [ ] 领域工具通过公共协议注册。
  - [ ] 研究流程：步骤 4、5、7、8 是否必选在本步骤确认。
  - [ ] 研报与规则入库审核，版本化。
  - [ ] 回测（`guanlan/backtesting`）：复权、交易成本、停复牌、退市与未来信息泄漏。
- **验收**：报告中每个数值与结论可追溯到来源、时点与版本；无权数据不可检索或读取；回测记录基准、成本与时间段；至少一个数据源通过逐接口验证并有失败与降级测试。
- **依赖**：R5–R8。
- **实施前需用户提供**：观澜数据源账号或授权信息；目标市场、标的范围、历史回溯与更新频率；研报与规则样例。
- **启动前**：通过 OpenSpec 提案并获用户确认。

## 6. 测试与评估

- 每个步骤运行涉及的单元与集成测试，以及前端构建（`npm run build`）；聊天交互变化时运行 `npm run test:browser`。
- 涉及鉴权、取消、重复投递、资源删除或恢复时，增加对应集成场景。
- 评估（`evals/`）：固定智能体任务、检索与引用、技能工具选择、Runtime 能力契约。
- 策略回测与软件回归分开记录。
- 未执行的测试在交付说明中列明，不以部分通过代替完整验收。

## 7. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| Codex app-server 为实验性或版本变化快 | 适配器失效 | 锁定版本；能力探测；契约测试 |
| Claude SDK 的权限与 resume 行为与摘要不一致 | 审批或会话错误 | R4 前读官方文档，未核对不承诺 |
| 外部 Runtime 原生工具越权 | 数据泄露或误操作 | 工作区隔离、禁用原生工具；无法约束则不允许绑定 |
| 账号或模型不可用 | 无法验收 | 由用户提供；未验收不宣称 |
| 参考项目许可证 | 合规风险 | 迁移前核对许可证并保留声明；非 MIT/Apache 项目仅借鉴设计 |
| 范围过大 | 交付延迟 | 严格按步骤验收推进；Native 与 Codex 先行 |
| Native 迁移引入的复杂度 | 行为回归 | 行为矩阵与组件测试；拆分后逐组件验证 |
| 仅在 SQLite 上验证 | PostgreSQL 环境下行为未知 | 部署到 PostgreSQL 前补做 R1 门禁 |
