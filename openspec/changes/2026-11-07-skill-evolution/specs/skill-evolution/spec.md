# 规格：技能演进

来源：`openspec/changes/2026-11-07-skill-evolution`（第六版，待确认，确认并实施后归档）。

## 需求

### R1 作用域与内置资源
- 技能按租户（空间）组织，分三层：内置（系统租户）、空间技能库、私有（租户内某个用户）。
- 内置技能与内置工具对所有空间有效（含个人空间），指**可分配**：出现在目录里并可绑定到智能体，不需要启用步骤或授权行；智能体是否使用取决于是否绑定。普通空间不能创建、修改或撤销内置资源。
- 高影响工具分组仍受分组可用性、智能体开关、`tool_access`、参数守卫与审批约束，不因全局生效而默认出现。
- 空间管理员可对本空间停用某个内置资源：目录不再列出，发布智能体版本时拒绝绑定，调用时授权拒绝；不影响其他空间与已发布的智能体版本。
- 空间自有的技能与工具只在本空间可用，只能分配给本空间的智能体；其他空间的智能体不能绑定、不能读取。
- 系统租户不可登录、不可加入，不出现在任何租户、成员、组织、注册或汇总列表中。
- 升级内置技能产生新版本；既有智能体版本绑定的旧版本不变，编辑器提示有新版本。
- 私有技能不登记为平台资源，不可绑定、不可授权，只有所有者的会话可见。名字在本人私有、本空间库、内置范围内唯一；库后来发布同名技能时，该名字解析为库技能，私有同名标记已被取代。
- 既有租户登记的工具绑定行为不变。

### R2 存储与运行
- 技能版本保存 zip 包与行内的名字、简介、正文；资源按条目读取；二进制资源可保存，读取工具对二进制只返回元信息。
- 技能目录采用 `skill://名字/SKILL.md` 路径格式并声明其为描述性数据；简介超过 600 字符被截断；总长超限时只列名字。
- `sandbox_exec` 可带 `skill_name`：选中技能的依赖环境，设置 `NEXUS_SKILL_DIR` 与 `NEXUS_SKILL_OUTPUT_DIR`；技能不在本会话可用范围内时拒绝。技能不再声明脚本，`run_skill_script` 不再提供。
- 脚本的审批沿用 `sandbox_exec` 的风险等级与 `tool_access`；`skill_name` 不改变风险等级。
- 脚本失败时在结果里附恢复方向；不做命令黑名单。
- 名字为小写字母、数字、连字符，1–64 字符，不含保留词；已发布的旧名字不受影响。frontmatter 接受已知可选键，未知键保留并提示，保守修复后标记。
- `model_invocable` 为假的技能不出现在索引中，`load_skill` 与 `read_skill_file` 也拒绝；`user_invocable` 被保存与校验。
- 会话索引在首个 Run 冻结；中途变化通过追加的差异说明告知，不重写系统提示、不改工具块。

### R3 安装与来源
- 上传 zip、远程来源、对话保存、内置导入走同一条流水线：隔离区暂存、规范化校验、扫描、依赖环境构建、验证关、原子换入。
- 规范化校验拒绝：条目、总字节、单文件超限，压缩比超过 100，路径穿越、绝对路径、符号链接、重复路径，缺少根目录 `SKILL.md`。
- 版本在 `ready` 之前不可被绑定或索引，`current_version_id` 只在 `ready` 后移动；任一步失败时旧版本继续服务，暂存目录与临时容器被清理。
- 依赖环境由 `requirements.txt` 与 `package.json` 构建，按版本哈希与档位指纹存放并只读挂载；档位没有对应环境时脚本不可用并说明原因。
- 验证关只做确定性检查：源文件可读、Python 源文件可解析、清单列出的包已装；不推断 `import` 能否解析；`note` 保留，`problem` 拒绝。
- 构建带心跳；周期任务把超时的 `installing` 标为 `failed`，清理残留暂存目录与带标签容器；同一技能同时只允许一个进行中的安装。
- 远程来源仅管理员可用且每次确认；抓取前做出站地址校验并逐跳复核，跳转不超过 3 次，有超时与字节上限；来源 URL、版本与摘要被记录；非法输入统一返回 `skill_source_invalid`。
- 技能带来源（`builtin` / `admin` / `import` / `agent` / `user`），版本记信任级、扫描器版本与结构化发现。放行矩阵：`builtin` 放行；`admin` 遇 `dangerous` 须显式确认并审计；`import` 遇 `caution` 或 `dangerous` 阻止，管理员可留理由放行；`agent` 与 `user` 进入共享审核；私有技能遇 `dangerous` 拒绝保存。扫描器升级后旧版本标为需重扫，重扫只追加结果。
- 扫描不替代运行时授权：技能不授予任何权限。

### R4 沙箱档位
- 部署配置可定义多个命名档位，类型为 `local`、`docker`、`bwrap`；`default_profile` 默认为 `local`；档位只能由运维定义，智能体只能选择已定义的档位名，已发布的智能体版本固定其档位。
- `local` 档位仅当 `allow_local` 开启且认证为开发模式时可用，否则可用性为 `sandbox_local_not_allowed`，沙箱工具组与技能脚本不出现；不因此启动失败。
- 档位参数有明确默认值与校验；非法值只报键名；`docker` 的网络只接受 `none` 与 `bridge`；`docker` 的加固（只读根、`cap-drop ALL`、`no-new-privileges`、非 root）不可关闭；不支持向 `docker run` 透传任意参数；显式转发的环境变量名含敏感词时被拒绝。
- 沙箱工具组与技能脚本的可用性、隔离验收及其报告均按智能体所选档位判定；报告指纹含档位参数。
- 技能的 `execution`（`sandbox` 默认 / `local`）是声明而非权限：声明 `sandbox` 要求所选档位为 `docker` 或 `bwrap`（开发模式下 `local` 档位也满足）；声明 `local` 仅限内置来源、所选档位为 `local` 且 `allow_local_scripts` 开启；不满足时脚本不可用并说明原因，不回退；其他来源声明 `local` 在保存或发布时被拒绝。
- 没有 `profiles` 时，旧的扁平 `[sandbox]` 键映射为名为 `default` 的档位，旧配置继续有效。
- bwrap 档位的已知缺口（无进程数限制、无 CPU 配额、不支持后台命令）在配置说明与管理接口中如实标注。

### R5 私有技能与对话式创建
- 模型通过 `skill_manage` 编辑可变草稿，写入限定在一个草稿内；`patch` 匹配必须唯一；写入前必须在本 Run 内读过该草稿；附属文件只能在固定子目录；草稿数、私有技能数与大小有上限。
- `skill_save` 把草稿保存为私有技能的新不可变版本，每次需用户确认，走与上传相同的流水线；通过后**立即生效**，不设审核队列；`dangerous` 拒绝保存。
- `skill_rollback` 可把当前版本指回任一旧版本；删除私有技能是归档，可恢复。
- 修改既有技能带基础版本哈希，保存时当前版本已变则拒绝；模型编辑文本时未触及的二进制资源保持原字节。
- 建议性 lint 随结果返回，永不阻止保存。
- 本人的 Run 的技能索引包含其启用的私有技能；其他用户、其他租户不可见、不可读；会话中创建或保存的技能经工具结果与追加的差异说明对该会话可用。
- 含脚本或依赖清单的技能保存时，所选档位必须能构建环境，否则只能保存为纯指令。

### R6 共享到空间库
- 私有技能可共享到空间库（复制为库技能）：管理员直接发布；成员需要 API 权限 `skills:submit` 并经管理员审核；审核与发布需要 `tools:manage`。
- 提交带基础哈希，通过时哈希不符或同名已存在则置 `superseded`；待审总数、每用户每小时提交数、每用户同时待审数有上限。
- 成员只能查看、撤回自己的提交，他人的提交对其返回不存在；拒绝须填理由；`agent` / `user` 来源遇 `dangerous` 在提交时拒绝。
- 审核页提示通过后本空间所有智能体可用；提交内容按纯文本展示；通过后版本记录提交人；提交、撤回、通过、拒绝、放行均写审计。

## 兼容
- 既有技能、绑定、会话快照与智能体版本的行为不变；新增字段与新表有默认值；迁移可升可降。
- `run_skill_script` 与 `scripts` 声明退役：已发布版本中的该绑定在运行时被忽略并记事件，新发布校验提示改为绑定 `sandbox_exec`。
