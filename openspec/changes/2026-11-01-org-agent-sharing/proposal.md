# 组织可见智能体：空间分配给组织后的智能体可见与可用

## 状态

已确认（2026-11-01）：组织分配、会话与记忆归属（方案 A）、聊天记录与记忆的可见性规则，以及上述细节。进入实施前，仍需按 tasks.md 逐项完成。

## 背景

用户组织管理（`2026-11-01-user-org-management`）已实现组织树与空间绑定。本变更解决下一步：平台管理员把空间分配给组织节点后，该组织的人能使用这个空间里的智能体。组织树保持不变；分公司可以在自己的组织节点下分配自建的空间。

## 范围

范围内：

- **分配**：平台管理员（或分公司管理员，见下文）把某个智能体分配给组织节点。被分配的智能体对该节点的子树可见。
- **权限上限**：组织侧只能拿到智能体的 `view` 与 `run`，不能编辑、发布或管理。
- **资源随空间走**：智能体依赖的工具、知识库、模型凭据等资源属于智能体所在的空间。组织成员通过智能体使用它们，不能直接读取或引用这些资源本身，也看不到凭据内容。
- **绑定不需要空间 owner 同意**：分配由组织侧单方面完成。
- **分公司自建空间**：分公司可以创建自己的空间，并在自己的组织节点下分配。

范围外：

- 把空间已有的会话或记忆开放给组织。组织成员只能访问自己在该空间中产生的会话与记忆。
- 跨集团分配（当前只支持单集团）。
- 组织成员自行发布或修改智能体。
- 智能体版本的自动同步策略（沿用智能体当前发布版本，见设计）。

## 需求

1. 平台管理员可以把智能体分配给任意有效组织节点；被分配的智能体对该节点子树的人员可见。
2. 组织侧的权限上限为 `view` 与 `run`。`edit`、`publish`、`manage` 不会因分配而授予。
3. 分配不改变空间的成员关系，也不把组织人员写入 `tenant_memberships`。
4. 组织成员使用被分配的智能体时，智能体依赖的工具、知识库和模型凭据按智能体所在空间的配置执行，组织成员不能读取这些资源或凭据。
5. 分配与撤销都写入审计：组织侧写 `org_audit_records`，空间侧写 `audit_records`。
6. 停用的组织节点不接受新的智能体分配，已有分配保留但标注为停用。
7. 分公司管理员分配智能体时，只能在自己的管理范围内操作（边界规则由 C+ 分层授权决定，本变更依赖该决定，见设计"依赖"）。

## 会话与记忆的存放位置（第 2 项，已确认方案 A）

组织成员通过切换到智能体所在的空间来打开智能体。会话与记忆保存在智能体所在的空间，跟随智能体的空间归属。

- 组织成员在该空间内产生的会话与记忆，`tenant_id` 为该空间，`owner_user_id` 为组织成员。
- 这些数据受该空间的保留、导出和删除规则管理。
- 组织成员只能访问自己产生的会话与记忆。空间已有的他人会话不开放给组织。

## 与现有模型的关系

- 智能体仍属于空间（`agents.tenant_id`），版本、草稿与资源绑定不变。
- 组织分配是新增的一层：智能体 × 组织节点，权限上限固定为 `view` 与 `run`。
- 空间内的角色授权（`tenant_agent_grants`）不变。组织分配不写入空间角色。
- 资源授权（`resource_grants`）目前不支持智能体类型，本变更不改变它。

## 影响

- 数据库：新增分配表（设计见 design.md），一次迁移。
- 权限：新增组织侧的智能体可见与运行判断；权限键目录是否新增，见设计。
- API：分配、撤销、组织侧的智能体列表与运行接口。
- Web：空间设置中的智能体分配区域；组织侧的可用智能体列表。UI 按 AGENTS.md 使用 `ui-ux-pro-max` 技能。
- 文档：更新 `docs/architecture.md`、`docs/roadmap.md`、`packages/platform/docs/`，并同步 OpenSpec 规格。

## 聊天记录的可见性（已确认，2026-11-01）

这一节是权限变更：空间管理员的可见范围从"只看自己的会话"扩大到"看本空间全部会话"。实施前需要确认。

- **普通用户**：只能看到自己的聊天记录，并可以按智能体筛选。
- **空间管理员**（空间的 owner 与 admin）：可以看到其管理的每个空间里的全部聊天记录。
- **平台管理员**：可以看到全部聊天记录，并可以按组织、智能体、空间筛选。

记忆也按同样规则开放（已确认，2026-11-01）：

- **普通用户**：只能看到自己的记忆。
- **空间管理员**（owner 与 admin）：可以看到其管理的空间里的全部记忆（`memory_entries`、`memory_drafts`）。
- **平台管理员**：可以看到全部记忆，并可以按组织、智能体、空间筛选。

## 已确认的细节（2026-11-01）

1. 组织成员在空间里的会话显示"组织访问"标识，便于空间管理员识别。
2. "空间管理员"包括 owner 与 admin 两种角色。
3. 平台管理员按组织筛选时，以会话创建时记录的组织节点为准（默认方案）。
4. 记忆开放给空间管理员（见上一节）。
