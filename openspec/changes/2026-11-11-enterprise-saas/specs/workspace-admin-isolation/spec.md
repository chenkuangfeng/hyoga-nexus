# 工作台旧部门管理隔离

### ADDED Requirements

#### Requirement: 部门写页面由管理应用承接
工作台 SHALL 移除旧部门管理页面及设置导航，不再随设置页加载其组织读写实现；已迁移的部门维护由独立 admin 应用提供。

- **WHEN** 用户访问旧部门设置书签或内部旧快捷调用
- **THEN** 工作台展示迁移说明，不请求组织数据或提供组织写操作，有当前企业 admin 入口时提供显式管理应用链接，否则说明权限不足。

#### Requirement: 独立应用与兼容书签
迁移说明 SHALL 不自动跨应用导航。开发链接使用当前主机的管理应用端口，生产尊重应用 base；admin SHALL 继续校准身份及组织权限。

- **WHEN** 当前企业或服务端 entries 变化
- **THEN** 链接可见性随当前企业更新；旧书签不会因为移除导航而丢失迁移说明。

#### Requirement: 保留未完整迁移能力
清理 SHALL 保留尚未承接的实际能力，及共享空间、加入企业、企业切换和个人设置。退出企业与审计已分别由账户资料和管理端承接，旧企业信息/成员治理页可移除；其他管理配置和完整产物隔离仍为后续任务。

#### Requirement: 旧成员治理页面隔离
工作台 SHALL 移除旧成员治理页面、独占审批组件和设置导航，由管理端现有成员、审批及审计页面承接。

- **WHEN** 访问旧 members 书签或内部快捷调用
- **THEN** 展示迁移说明，按当前企业 admin 入口提供显式 members/audit 链接，不自动跨应用导航，也不读取或写入成员/邀请/申请/审计数据。
- **WHEN** 当前企业或入口变化
- **THEN** 链接可见性及时更新；共享空间成员管理、个人邀请/加入和退出企业不受清理影响。
