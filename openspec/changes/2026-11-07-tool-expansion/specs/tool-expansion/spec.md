# 规格：工具扩展

来源：`openspec/changes/2026-11-07-tool-expansion`（待确认，确认并实施后归档）。

## 需求

### R1 工具分组与开关
- 每个工具定义声明 `group`；目录、编辑器和门控从注册表读取，不另维护分组表。
- 工具组有两层门控：可用性（部署侧事实，不满足则工具不出现，并给出稳定原因代码）与智能体开关（`tool_groups_enabled`）。任何一层不满足，该组工具都不进入工具定义，直接调用返回 `tool_authorization_denied`。
- 开关只能收紧：通过门控后，每次调用仍须通过实时授权、访问级别、参数守卫和审批。
- `sandbox`、`web`、`collab`、`schedule`、`media` 组默认关闭；既有智能体版本不因本变更获得新工具。
- `BUILTIN_TOOL_NAMES`、注册表与分组声明保持一致，不一致时测试失败。

### R2 沙箱组
- 只有在部署启用（`[sandbox].enabled`）且最近一次隔离验收对当前镜像与配置通过时，`sandbox` 组才可用；否则工具不出现，不是返回错误。
- 验收覆盖资源限制、网络隔离、租户隔离、清理、崩溃残留与连通探测，结果持久化，API 与 worker 读取同一份。
- 模型只看到虚拟路径；越界路径（含符号链接逃逸）被拒绝；公开结果不含宿主路径。
- 沙箱默认无网络；网络只能由部署配置打开，打开后命令类工具风险升为 `destructive`。
- 命令有墙钟超时、输出上限，超时或取消时终止整个进程组；写入为原子替换；同一路径的写入串行。
- `/outputs` 下的文件在 Run 结束时登记为产物，下载走授权检查；授予与下载写审计。
- 沙箱可用时，`run_skill_script` 经同一后端执行。

### R3 调度
- 工具可声明 `concurrency(arguments)`，结果为 `parallel`、`exclusive` 或带 key 的 `serial`；未声明时沿用 `read_only` 且 `idempotent` 的现有判定，现有行为不变。
- 同 key 的调用串行，不同 key 可并行；结果与生命周期事件按模型顺序。
- 参数解析失败的调用按独占处理。

### R4 渐进加载与 schema 清洗
- 绑定工具的 schema 估算超过阈值时，延迟工具只列目录，经 `tool_search` / `tool_describe` / `tool_call` 使用；Run 内工具块不变。
- `tool_call` 展开为真实工具后执行完整网关管线；未绑定、被组开关过滤或未授权的工具不能经桥接调用。
- 发给供应商的 schema 经清洗副本，注册的定义不被修改；被改写的属性名在调用时还原。

### R5 Web 组
- `web_fetch` 对每一跳（含重定向）校验解析后的地址，拒绝回环、私网、链路本地与元数据地址；有协议、端口、大小与超时限制。
- 搜索与抓取的正文带外部内容前缀，并经注入扫描。
- 搜索后端可插拔；未配置后端时 `web` 组不可见。

### R6 Wiki 组
- Wiki 工具属于 `wiki` 组（子组读、编辑、问题），不属于 `base`；仅当智能体绑定了 Wiki 类型知识库时出现。
- 读为 `read`；写、替换、改名为 `write`；删除为 `destructive`。

### R7 协作与定时（阶段 G，实施前补全）
- `delegate_task` 的子 Run 工具集是父级的子集，不继承 `collab` 组，审批冒泡到父会话，预算从父级扣除。
- `cronjob` 创建的任务无人值守运行，不得使用需要审批或询问用户的工具；提示入库前扫描；每用户有数量与频率上限。
