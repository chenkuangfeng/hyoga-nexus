# 规格：模型管理（类型化模型与默认模型）

来源：`openspec/changes/archive/2026-11-02-model-management`。本规格描述当前实现的行为，修改需先提案。

## 需求

### R1 模型类型
- 模型档案的类型只能是 `chat`、`embedding`、`rerank`、`vision`、`speech` 之一，其他值返回 422。
- 类型在创建时确定；编辑已有模型时提交不同类型返回 409，不静默改写。
- 已有模型迁移后类型为 `chat`。

### R2 按类型的默认模型
- 默认模型按作用域（个人、空间）和类型各保存一个，互不影响。
- 版本的类型必须与槽位类型一致，否则返回 409。
- 空间默认只能指向空间共享的模型；个人模型不能作为空间默认。
- 设置读取结果为 `defaults[scope][type] = version_id`，未设置的槽位不出现。
- 新建智能体只使用 `chat` 类型的默认模型（个人优先，其次空间）。
- 更改默认模型不改变已发布的智能体版本和已有会话。

### R3 未保存配置的连接测试
- `POST /api/v1/tenants/{tenant_id}/model-settings/test` 测试表单中的配置，不写入数据库。
- 授权与保存一致：编辑已有供应商需要管理权限；新建空间共享供应商需要 `models:manage`，否则 403。
- 新建供应商必须提供 Key，否则 422，且错误信息不包含 Key。
- 提供 `provider_id` 且省略 `api_key` 时复用该供应商已保存的 Key；更换地址时必须提供新 Key。
- 对话、向量化和重排使用对应运行时适配器测试；视觉和语音返回 `unsupported_for_type`，不连接供应商。
- 同一供应商 10 秒内只能测试一次（已保存供应商用 `last_test_at`）；草稿测试按（空间，用户）在进程内限制 10 秒。
- 响应只包含 `ok`、`message` 及可选的错误码，不回显生成内容或供应商原始错误。
- 每次测试写入审计记录 `provider.connection_test`，不包含表单内容。

### R4 已保存模型的连接测试
- 沿用原有行为：每 10 秒一次，15 秒总超时，失败时返回安全的错误码与文案。
- 对话、向量化和重排使用与草稿测试相同的适配器；视觉和语音返回 `unsupported_for_type`。
- 向量请求被拒时返回 `model_request_rejected`，提示核对 `/embeddings` 能力和向量模型 ID。认证、限流、超时和网络故障使用各自的稳定错误码。

### R5 设置页
- 顶部类型标签页显示"全部"及各类型数量；卡片只显示当前类型的模型。
- 添加卡片打开抽屉，类型默认为当前标签（"全部"时为对话）。
- 抽屉中服务商下拉末尾为"自定义（OpenAI 兼容接口）"；选择后在抽屉内填写名称、地址和 Key，保存时先建供应商再建模型。模型保存失败时，供应商已建立的情况下重试不会重复创建。
- 编辑模型时类型不可改，测试连接复用已保存的 Key（前提是不替换地址）。
- 非对话类型隐藏协议与高级开关，只发送默认协议。
- 默认设置为"类型 × 作用域"表格；空间默认仅管理员可改。
- 智能体的模型下拉只列出对话模型。
- API Key 只在提交时发送，提交后清空，不回显、不写入浏览器存储。

### R6 迁移
- 迁移 `0a7c3e9d1b5f` 为 `model_profiles` 增加 `model_type`（默认 `chat`），并重建 `model_defaults`，主键加入 `model_type`，已有行归为 `chat`。
- 降级时只保留对话默认值，删除 `model_profiles.model_type`。
- 往返升降级在 SQLite 上验证通过；PostgreSQL 未验证（见 `verification.md`）。

### R7 未指定思考强度
- Chat Completions 遇到空字符串思考强度时省略 `reasoning_effort`，使用服务商默认行为。
- 保存模型时，显式提交空字符串会清除新版本的思考强度选项。请求省略字段时沿用旧版本的有效设置。

## 不在本规格内
- Ollama 来源与本地模型下载。
- 服务端模型目录与管理员目录编辑。
- 模型调试器与协议兼容覆盖 JSON。
- 知识库业务调用、视觉与语音适配器。
- 知识库、智能体对模型的引用检查与删除保护。
