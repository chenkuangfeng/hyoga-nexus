# 规格：技能演进

来源：`openspec/changes/2026-11-07-skill-evolution`（待确认，确认并实施后归档）。

## 需求

### R1 来源与信任
- 技能带来源（`builtin` / `admin` / `import` / `agent`），版本记录信任级、扫描器版本与结构化扫描结果。
- 发布按放行矩阵处理：`builtin` 总是放行；`admin` 遇 `dangerous` 须显式确认并审计；`import` 遇 `caution` 或 `dangerous` 阻止，管理员可留理由放行；`agent` 遇 `caution` 进人工审核、遇 `dangerous` 拒绝。
- 被阻止时返回稳定错误码和发现列表（规则、级别、文件、行号）；公开结果不含完整可疑内容。
- 扫描器升级后，旧版本在列表中标为需重扫；重扫只追加结果，不修改已发布内容。
- 扫描不替代运行时授权：技能不授予任何权限。

### R2 目录与调用方控制
- 技能名为小写字母、数字、连字符，1–64 字符，不含保留词；已发布的旧名字不受影响。
- `model_invocable` 为假的技能不出现在模型的技能索引中，`load_skill` 与 `read_skill_file` 也拒绝。
- `user_invocable` 被保存与校验；用户侧入口待斜杠命令设计后接入。
- 智能体可逐个关闭已绑定的技能；变化产生新的智能体版本，已发布版本与已冻结的会话快照不变。

### R3 沙箱内执行
- 沙箱可用时，本会话绑定且启用的技能按内容哈希只读投射到 `/skills/<name>@<hash12>/`；沙箱内不能写入该路径。
- 其他会话、其他租户与未绑定的技能不在投射目录中；文件数与总字节有上限，超限时技能脚本不可用而内联加载不受影响。
- `run_skill_script` 在投射路径下运行脚本，参数经 stdin，每次调用仍需审批；不自动安装依赖。
- 沙箱不可用时保持开发门禁。

### R4 模型创作与审核
- 模型只能通过 `skill_propose` 提交草稿，不能修改已发布版本；修改须带基础版本哈希。
- 审核通过时若技能当前哈希与基础哈希不符，或新建时同名技能已存在，提交置 `superseded` 并要求重新提交。
- 待审提交总数与每用户每小时提交数有上限，超限返回稳定错误码。
- 审核由管理员完成，拒绝须填理由；通过时重新校验依赖与扫描，再按既有发布流程生成新的不可变版本。
- 提交、通过、拒绝、放行发现均写审计；提交内容按纯文本展示。

### R5 导入
- 管理员可导入内置技能目录；同名的非内置技能不被替换；重复导入报告未变化。
- 压缩包导入产生 `import` 提交并走审核；超过文件数、字节数上限，或含路径穿越、符号链接的包被拒绝。
- 不支持联网安装。

### R6 使用记录
- `load_skill` 成功时记录使用；长期未用且未固定的技能被标为 `stale`，归档由管理员决定。
- 归档的技能不进新会话的索引，历史版本与已有会话快照不变，可恢复。

## 兼容
- 既有技能、绑定、会话快照与智能体版本的行为不变；新增字段与新表有默认值；迁移可升可降。
