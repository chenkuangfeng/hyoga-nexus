# 会话上下文检查点

### 修改：更新工作检查点

`update_working_checkpoint` 成功时必须保存当前任务检查点，并将内容作为会话级上下文摘要写入追加式摘要链，切点推进到当前 Run 最新的持久化消息。原始会话消息保留不变。当前 Native Run 的后续请求立即折叠切点前的模型历史，同时保留触发检查点的完整 assistant 工具调用和工具结果交换。
模型工具 Schema 必须只公开 `key_info` 一个检查点参数。为兼容旧调用，网关在 Schema 校验前把 `content` 归一为 `key_info`；两者同时提供时以 `key_info` 为准，不得因别名值冲突而拒绝有效检查点。

#### 场景：后续 Run 续接压缩上下文

- **当** 新 Run 读取到授权有效的摘要
- **那么** 模型上下文使用该摘要和切点后的消息，不再包含摘要覆盖的旧消息
- **并且** 若工作检查点已包含在同一摘要中，不重复注入

#### 场景：当前 Run 立即折叠

- **当** Native Run 成功执行 `update_working_checkpoint`
- **那么** 该 Run 的下一次模型请求立即使用检查点摘要
- **并且** 当前 assistant 工具调用与完整工具结果仍按原顺序保留

#### 场景：当前 Run 尚无消息

- **当** 更新检查点时当前 Run 没有已持久化消息
- **那么** 保存工作检查点，但不创建无有效边界的摘要

#### 场景：保留审计和历史

- **当** 检查点推进摘要边界
- **那么** 原始消息、工具调用、Run 轨迹和事件仍可按现有授权读取
- **并且** 不允许摘要边界倒退
