# 后端开发规范

本文适用于 Python 服务端、平台底座、Runtime、工具/MCP/知识库适配器、worker、持久化与 API。项目总约束见根目录 [AGENTS.md](../AGENTS.md)。

## 参考实现与能力保持

- 开始核心框架工作前，阅读 [参考项目与取舍](../docs/reference-analysis.md)，并对照其中固定版本的 WeKnora、GenericAgent 源码和测试。README 或二手总结不能代替实现核对。
- 平台编排、资源组织、生命周期、权限/策略、会话事件等对照 WeKnora 的实际实现；Native 执行、模型响应循环、工具分发、StepOutcome、生命周期钩子、任务队列与记忆/SOP 对照 GenericAgent 的实际实现。
- 先列出参考实现的行为、状态转换、错误处理和扩展点，再设计本项目接口。不得为了缩短代码、减少对象或方便当前验收而删除或合并已有能力语义。
- 改动只能增加能力或增加适配层，保持既有行为和接口兼容。若 Python 栈、多租户隔离或安全要求需要改变实现形态，必须记录映射关系、兼容边界及验证方式；安全加固可以收紧未授权行为，但不能静默移除合法能力。
- 实际复用源码前，核对许可证、版本和归属要求；优先学习模式，不复制整个项目或未经审查的实现。

## 语言、模块和依赖

- 第一方服务端代码使用 Python 3.11+、类型注解和清晰的异步边界。公共接口使用稳定 DTO/协议，不把数据库 ORM、HTTP 框架、队列或厂商 SDK 类型泄漏到 `core`。
- `core` 只放跨包稳定标识、错误、事件、数据契约和协议，不依赖其他本地包、数据库、队列或 Runtime SDK。
- `platform` 管理身份、空间、授权、资源配置、Agent 版本、Session、Run、持久化和审计；`runtimes` 执行任务。外部 Runtime 的循环由其 Adapter 驱动，不在外面再套 Native 循环。
- `tools`、`skills`、`mcp`、`knowledge`、`sandbox` 和 `connectors` 各自守住目录职责。通用包不得导入 `guanlan`；由 API/worker 组合入口显式装配观澜扩展。
- 新依赖只在实现实际使用时加入，并固定/锁定版本。不得把参考项目的语言、完整依赖栈或部署拓扑直接引入本项目。

## 领域与执行

- 以明确的领域对象和服务表达身份、空间、配置版本、资源绑定、会话、运行、事件和工具调用；跨层通过依赖注入或协议连接，避免模块级可变全局状态。
- Agent 配置和资源版本可追溯；已发布版本不可原地改写。每个 Run 保存启动配置快照，同时在真实资源执行点重新验证当前权限。
- 所有后台工作显式表达状态、输入、重试策略、幂等键、超时、取消和失败原因。重复投递必须可安全处理；结果未知的有副作用操作不得盲目重放。
- Runtime 事件先持久化再对外投递，结构化携带稳定 ID、顺序和 schema 版本。事件重放只重读历史，不重新执行任务。
- 凭据只使用引用或短时句柄。不得写入代码、配置样例、提示词、Run 快照、事件、异常或日志。
- 技能指令不能扩大权限；工具、知识检索和文档读取均在执行时按主体、空间、Run 与当前授权重新校验。

## API、错误与可观测性

- HTTP 层只处理协议转换、输入校验、认证上下文和响应映射；业务规则放在平台/领域服务。
- API 使用版本化路径和显式 schema。错误提供稳定错误码、可读信息和 request/trace ID；避免跨空间对象枚举。
- 日志记录关联 ID、状态变化和诊断信息，不记录秘密或无必要的用户内容。审计事件与调试日志分开。
- 流式 API 断线恢复依靠持久事件游标，不把连接生命周期当作任务生命周期。

## 测试与交付

- 测试放在 `tests/`，按单元、集成和端到端边界组织；评估样例放在 `evals/`，股票回测放在 `guanlan/backtesting/`。
- 核心变更需覆盖参考行为和新增扩展，重点检查权限隔离、状态转换、重试/幂等、取消、故障恢复、事件顺序和秘密保护。
- 代码验证按根目录 AGENTS.md 执行锁文件安装及相关 pytest 检查；文档变更做链接和 diff 检查。不要把空包、协议草案或模拟实现描述为已完成能力。
