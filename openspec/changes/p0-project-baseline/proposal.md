# Proposal: P0 架构与项目结构基线收尾

状态：已完成静态核对；未发现需要增加或修改代码的 P0 缺口。2026-10-24。

## 问题陈述

路线图将 P0 定义为架构与项目结构阶段：建立可安装的工作区、健康检查、规划能力目录和现有前端入口，并使架构计划可审阅。仓库已有对应文档、Python workspace、FastAPI 健康/能力端点、Vue 能力目录页及 worker 占位，但尚未以一个明确的 P0 基线契约核对实现状态；目录骨架也容易被误认为业务功能已完成。

## 提议变更

- 固化 P0 的最小项目基线和可观察行为，明确哪些可运行、哪些仍是规划占位。
- 盘点现有骨架，只修复达到该基线所必需的安装、启动、健康检查、能力状态展示或文档差异。
- 不提前实现 P1 平台服务、持久化、身份/授权、Agent CRUD、Session/Run 或事件系统。
- 以已确认的架构、资源模型和 Runtime 契约作为 P0 设计约束；业务包保持占位，不因本变更添加未使用依赖。

## 范围

**包含**：根工作区开发安装入口；API 健康检查和明确标为计划中的能力目录；Vue 3/Element Plus 初始化页；worker 的明确占位状态；README 与路线图的实现状态一致性。

**不包含**：业务功能、数据库/迁移、身份认证、权限系统、模型调用、运行时 SDK、知识库、技能/MCP 执行、队列、渠道和观澜数据功能。

## 影响

- API、worker、Web 初始化骨架及根开发说明。
- 不改变 `core`、`platform`、`runtimes` 的职责边界；不引入新的业务依赖。
- P1 已有 OpenSpec 设计保持独立，不在本变更中实现或改写其数据/事件契约。

## 评审点

实施结论：当前仓库已有本提案所列的项目基线，故本变更不增加功能代码；架构和路线图已同步标明基线落地及本次未进行运行验证。后续如运行验收发现差异，应另开 OpenSpec 变更。
