# 当前会话整理为技能

## 动机

仓库已有私有技能草稿、不可变版本、扫描和保存审批，但用户不容易知道如何让智能体把刚完成的流程整理成技能。提供明确的会话入口，使学习过程复用 Native Run 与已有技能工具，不新增旁路写文件能力。

## 范围

- 在工作台会话页提供“整理为技能”入口，仅当会话所属智能体绑定 `skill_search`、`skill_manage` 与 `skill_save` 时展示。
- 入口以普通用户消息请求智能体总结当前会话中的可复用流程并创建私有草稿。
- 指令要求智能体在创建后读取并展示完整 `SKILL.md`，等待用户审阅和明确要求后，才调用现有 `skill_save`。
- 延续 `skill_save` 的工具审批、来源扫描、私有所有权和版本构建流程。

## 非目标

- 不做回合结束后的自动复盘、后台学习作业或静默生成草稿。
- 不自动发布技能、不扩大技能工具权限、不创建企业共享技能。
- 不添加外部 URL / 本地目录学习面板；资料读取能力由当前智能体已有工具决定。
- 不新增 API、数据库表或记忆模型。

## 后续实施范围：技能工作区与受限 local 执行

- 数据库继续保存技能版本、草稿、权限和审批状态；Worker 在 Run 时把授权技能版本按内容哈希投射到本地 workspace 缓存。
- 为每个租户用户维护持久目录 `users/<user-id>/{skills,data}`，`data/tmp` 存放可清理临时文件；`data` 在同一用户的技能之间共享，技能源码与版本目录只读。
- 技能文件修改在 workspace 草稿区进行，只有显式调用保存工具才上传并提交数据库，需校验基础版本哈希并沿用扫描、审批及冲突保护。
- 生产 local 脚本必须在操作系统强制的文件边界内运行，仅能读取运行必需的系统文件和技能版本，只能写当前用户的 `data`、`data/tmp` 与交付目录；无法证明隔离的节点拒绝 local 执行。
- 多 Worker 部署的用户 workspace 数据目录必须是共享持久存储；技能缓存可以在各 Worker 本地独立建立。

## 扩展非目标与兼容

- 不把数据库中的技能正文迁移成文件系统权威数据，不自动同步任意 workspace 改动，也不让技能写入其他用户或平台技能目录。
- `local` 生产执行只在经隔离验收的 Linux 节点启用；Windows 原生 local 执行不宣称具备隔离能力，继续使用 Docker/托管档位。

## 验收

- 具备对应技能工具的非空闲工作台会话显示可访问的学习按钮；无工具、无会话、运行中或嵌入模式下不可触发。
- 点击后以普通用户消息发起一轮学习；失败仍由现有 Run 错误流程展示。
- 模型先保存为私有草稿并在聊天工具结果中展示完整正文；只有后续用户明确要求保存并通过现有审批，才会进入版本扫描和发布流程。
- 入口文案支持所有现有 Web 语言。
