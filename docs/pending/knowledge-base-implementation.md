# P3 Python 知识库实施步骤

状态：分阶段实施计划，尚未批准为编码任务。本文细化 `docs/roadmap.md` 的 P3；进入功能编码前仍需按仓库约定建立 OpenSpec 提案并获用户确认。参考 WeKnora 固定版本 `e1f9a6166` 的知识库与图谱工具边界，以及本地 RAGFlow `e5a5060c4`（`dev-20261024`）的知识编译和图谱检索配置模式；仅借鉴行为和设计，不复制第三方实现。

## 目标边界

P3 为平台提供 Python 知识库能力：文档生命周期、异步解析与索引、关键词/向量混合检索、引用和可选知识图谱增强。图谱增强与基础 RAG 分阶段交付；普通知识库不需要启用图谱，也不依赖图谱服务才能完成问答。

职责边界：

- PostgreSQL 保存知识库/文档元数据、版本、权限关联、索引任务状态、块定位与来源引用等关系事实。
- 独立向量服务承载向量索引与相似度检索，保存可回链到知识库、文档版本和文本块的标识。
- 独立图谱服务负责图谱构建/查询 API；图存储由独立图数据库承载。`packages/knowledge` 通过适配器调用向量和图谱服务，统一处理权限范围、检索编排、融合、引用和降级。具体向量产品、图数据库、图谱服务部署规格留待 P3 OpenSpec/技术验证确定。
- 原始文件走可替换对象存储接口。结构化股票行情、财务数据和平台记忆不进入文档知识库或其图谱。

## 分阶段步骤

### P3.1 知识库与文档生命周期

1. 定义知识库、文档、不可变文档版本、解析/索引任务、文本块、来源定位和引用契约。
2. 实现创建/更新/删除、上传、去重和版本流程；原文件保留于对象存储，数据库保存元数据与状态。
3. 将解析和分块作为可恢复后台任务，记录阶段、重试、失败原因和幂等标识；首期按路线图支持文本、Markdown、PDF，扫描 PDF 的 OCR 范围另行确认。
4. 每个文本块关联来源文件、文档版本、页码/章节等可用定位信息；重建索引使用新索引版本，避免新旧块混用。

### P3.2 基础混合 RAG 与引用

1. 用同一批有版本和来源的文本块分别构建关键词索引与向量索引；通过独立向量服务适配器隐藏厂商 Schema。
2. 检索开始时确定调用者有权访问的知识库/文档范围，之后才对该范围执行关键词和向量检索，不能先全局召回再只在展示层过滤。
3. 合并关键词与向量候选，可选接入重排；保留召回通道、分数、来源和索引版本，形成可诊断的检索结果。
4. 提供 `search_knowledge`、`read_document`、`list_documents` 等统一能力。答案引用可回到文档版本和文本块定位；删除、撤权和索引替换同步影响可检索性。
5. 基础 RAG 应在无图谱服务时完整可用；向量服务异常时按已定义策略返回可解释的降级结果，不得绕过权限或伪造引用。

### P3.3 图谱模型与异步构建

1. 知识库可单独启用/关闭图谱，并配置实体类型、关系类型、抽取约束、别名/实体归一规则和模型配置版本。配置应明确方向、适用条件与禁止推断内容，避免过宽泛 schema。
2. 文档版本解析和分块完成后，由后台图谱服务从来源块抽取实体、关系及描述；每个图元素都记录知识库、文档版本、来源块、抽取时间、抽取器/schema 版本和可用的置信信息。
3. 对实体做受控归一和消歧；不得仅凭名称相似就合并不同公司、证券、人物或事件。不能可靠归一的实体保留为不同实体，并保留原始提及名称。
4. 图谱写入按知识库和索引版本隔离，支持幂等重试、构建进度、失败原因、版本切换和删除清理。新版本构建完成后再切换可见版本，避免半成品图谱进入查询。
5. 原文块仍是证据事实源；抽取的节点/边是可追溯派生数据，不得脱离来源块单独作为权威事实。

### P3.4 图谱增强检索

1. 普通混合检索保持默认路径。仅当授权范围内存在启用且已完成索引的图谱知识库时，Agent 才能获得图查询能力；这沿用 WeKnora 按图谱能力范围提供工具的模式。
2. 图谱检索按查询解析实体，执行有界的实体匹配和关系扩展，取得相关关系、实体描述、社区/主题摘要（若启用）及其原文证据块。
3. 图谱证据必须重新按当前用户、空间、知识库和文档授权过滤；细粒度文档/标签权限下，只返回由授权来源块支持的实体关系。图查询不得成为知识库范围之外的旁路。
4. 将图谱候选与同范围关键词/向量候选去重、融合并可选重排。返回结果标明来源类型和截断信息，图关系和生成摘要都可追溯到原文引用。
5. 对种子实体、关系数、扩展跳数、证据块数量、耗时和模型调用设定上限；被截断时明确告知模型/用户，不能把有限邻域未返回某关系解释为“关系不存在”。
6. 图谱服务超时、索引缺失或服务不可用时，回退基础混合 RAG 并显式记录降级状态；权限拒绝不得回退成越权搜索。

### P3.5 管理、验证与启用

1. 文档管理页展示解析、索引和图谱构建状态；图谱配置页可管理实体/关系 schema 和开关。图谱可视化是可选运维能力，不阻塞引用式问答验收。
2. 提供检索测试入口，分别查看基础混合检索与图谱增强结果、来源块、排序/融合状态、截断和降级原因。
3. 建立固定评估集，覆盖关键词命中、语义召回、跨文档实体关系、多跳问题、引用准确性、权限隔离、文档更新/删除、索引重建和图服务故障降级。
4. 图谱仅在代表性语料评估有明确增益后按知识库启用；比较检索质量、延迟、LLM/Embedding 用量和维护成本。GraphRAG 索引可能增加构建成本和查询延迟，不能假定所有文档都适合构图。

## P3 验收增补

- 同一智能体可绑定多个知识库；无权限的库和文档不会通过向量或图谱路径泄漏。
- 基础知识库可通过关键词/向量混合检索生成可追溯答案，不依赖图谱服务。
- 启用图谱的知识库可回答跨文本块实体关系问题；节点、关系和摘要均能回溯到授权原文块。
- 图谱不可用或索引未完成时，普通 RAG 保持可用并显示降级；被截断的图查询不会造成错误的否定结论。
- 文档版本更新、删除、撤权和索引重建能同步处理向量索引与图谱索引，并防止旧版本继续被召回。
