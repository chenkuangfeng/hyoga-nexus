# 企业级员工智能体平台（SaaS 多租户）

## 状态

草案，待确认（2026-11-11）。下列“已确认的方向”来自用户 2026-11-11 的多轮回答；“需要你确认的项”确认之前不开始编码。

## 背景

现有底座里，运行时契约、ToolGateway 单调守卫、执行时复核授权、三类授权分离（ResourceGrant / ActionGrant / ActionApproval）、派发账本与审计都可以直接用于企业场景。偏 To C 的部分集中在“谁说了算”：

| 维度 | 现状（代码位置） | 企业场景的缺口 |
|---|---|---|
| 空间形态 | 自助注册可选个人空间或企业空间（`auth/accounts.py` `register`），登录默认进入个人空间；个人空间不属于任何企业 | 员工的内容和费用游离在企业之外；需要来回切换空间 |
| 企业微信 | 每个部署只有一个自建应用（`configs [wecom]`、`auth/wecom.py`），只做扫码登录与绑定，不自动开户，不同步通讯录 | 每家企业各自接入企微；员工首次从企微进入即自动开户；部门、人员、在职状态随企微同步 |
| 私有内容 | 会话、记忆按本人隔离；自建智能体默认只有创建者可见（`agents/access.py`）；**知识库对本空间全体成员可读**（`knowledge/access.py` `can_read`） | 企业内缺少“只有我能看”的知识库 |
| 组织与授权 | `org_units` 每企业一棵树，但组织位置不参与授权（`2026-11-03-enterprise-personal-spaces` 决定 7） | 智能体与知识库无法按部门开放 |
| 企业管控 | 没有企业级策略；企业空间内可用个人模型与个人 Key；共享空间可以跨企业共享 | 企业需要统一控制自建、模型、外部共享与数据留存 |
| 知识库维护 | 只有空间 owner、admin 与库创建者能写（`can_write`） | 智能体的管理员也要能维护该智能体所用的知识库 |
| 前端 | 一个 `Settings.vue` 混合了员工设置、空间管理与部署运维；按角色隐藏入口（`config/settingsAccess.ts`） | 员工端要轻、要适配企微 H5；管理端要与员工端分开 |
| 成本 | 只有并发上限与后台模型限流 | 没有按企业、部门、个人的 Token 预算与用量报表 |
| 部署 | 默认 SQLite，PostgreSQL 目标环境验收（路线图 2.9）暂跳过 | SaaS 必须以 PostgreSQL 为事实源，多 worker 部署 |

## 已确认的方向（2026-11-11）

1. **SaaS 多租户，租户即企业**：一套部署服务多家企业，所有数据按企业（`tenants.kind = 'enterprise'`）隔离；不引入“企业 → 部门工作区”的空间层级，部门差异通过组织驱动授权表达。
2. **企业微信为主身份源与主入口**：每家企业独立接入企微，支持扫码与企微内免登、首次进入自动开户、通讯录同步，并把企微作为对话入口（承接路线图 9.1）。
3. **取消独立个人空间，改为企业内的个人区**：员工私有的会话、记忆、智能体、知识库、产物都在企业内，归企业所有，按本人私有使用。
4. **只有企业，没有试用或套餐之分**：自助注册即创建一家企业，注册人为 owner。只有一个成员的企业就是普通企业。
5. **员工自建智能体默认开放**：企业策略提供开关，可按企业关闭或限定部门。
6. **知识库维护对智能体管理员开放**：对智能体有 `manage` 权限的人，可以维护该智能体所绑定的本企业知识库（范围见决定 8）。
7. **前端按使用对象拆分，取消平台管理界面**：Web 只有员工工作台与企业管理后台两个应用，放在同一工程；对外嵌入页 `/embed/:channelId` 保留为独立入口（后端另提案）。现有的平台管理 `/platform-admin` 取消：能按企业配置的（向量库、存储、解析引擎等）并入企业管理后台；必须全部署统一的（沙箱、网络出口、并发、注册开关、内置技能导入、平台管理员）只通过 `configs/nexus.toml` 与命令行管理，不提供 Web 界面。功能清单见 `design.md` 第 4 节。平台运营（企业开通、停用、计费）不考虑，以后需要时另做独立的运营台。
8. **不做离职资产移交，不做审批路由**：成员离职（企微同步到删除或移出可见范围）只撤销其企业成员身份，名下资产原样留在企业内，不移交。工具执行前的确认维持现状（由 Run 发起人本人确认），不增加上级或资源负责人审批、审批超时与待办。

## 决定（建议，待确认）

1. **租户形态**：
   - 只创建企业租户，不增加套餐或试用字段。自助注册时企业名称选填，不填则默认为“{显示名}的企业”，企业编码不填则自动生成，注册人为 owner。
   - 已登录用户仍可以再创建企业或加入其他企业，一个账号可以属于多家企业（沿用现状）。
   - `kind = 'personal'` 不再新建，现有数据的处理见需要确认的项 2。
2. **企业策略（`enterprise_policies`，每企业一行）**：只能收紧，不放宽平台已有的守卫。首批字段：
   - `self_build_agents`：`all`（默认）、`org_units`（只有列出的部门可以自建）、`none`；
   - `personal_models`：成员能否使用自己的模型与 Key，默认 `false`；
   - `external_sharing`：智能体、知识库能否共享到含其他企业的共享空间，默认 `false`；
   - `retention_days`：会话与运行事件的保留天数，空值表示不清理。
3. **企业内的个人区**：
   - 知识库增加 `visibility`：`private`（创建者，以及按决定 8 获得维护权的智能体管理员）或 `tenant`（全企业成员可读）；E4 再增加按部门开放。新建知识库默认 `private`，迁移时已有知识库设为 `tenant`，行为保持不变。企业 owner、admin 对私有库与对私有智能体一样有完全权限，用于治理。
   - 私有知识库绑定到其他人可用的智能体时，发布检查会拦截：库的可见范围必须覆盖智能体的使用范围。这沿用“共享智能体不扩大底层资源权限”的原则。
   - 会话、记忆、自建智能体、产物沿用现有的本人隔离规则。
4. **企业微信按企业接入**：
   - 新增 `tenant_wecom_apps`（每企业一行）：接入模式（`self_built` 自建应用，或 `custom_dev` 代开发应用）、`corp_id`、`agent_id`、加密保存的 `secret`、回调 `token` 与 `encoding_aes_key`，以及最近一次同步状态。`configs [wecom]` 只保留为开发与单企业部署的默认值。
   - 登录：扫码与企微内网页免登都按 `corp_id` 找到企业，再按 `(wecom, corp_id, userid)` 找到账号。**首次进入自动开户**：成员在企微应用的可见范围内、且已经同步到本企业时，创建账号并加入企业（`source = 'wecom'`，默认角色 `contributor`），不设置本地密码。
   - 通讯录同步：每天全量一次，加上回调增量。同步部门（`org_units.source = 'wecom'`）、成员、主部门、在职状态。手动维护的部门不受影响。
   - 离职：撤销企业成员身份，下一次请求与下一次工具调用即被拒绝；资产不移交（方向 8）。
5. **组织驱动授权**：智能体共享与资源授权的接收方，从“角色”扩展为“角色、部门（含子树）、成员”三种。部门授权在每次判断时按当前组织关系展开，调岗后下一次调用即生效。部门本身仍不继承空间角色（沿用 `2026-11-03` 决定 8）。
6. **企业级管理角色**：内置角色增加 `security_admin`（工具风险策略、企业策略）和 `auditor`（只读审计，默认看不到对话正文）。两者复用 `tenant_roles` 与 `authz/catalog.py`，新增 API 权限 `policy:manage` 与 `audit:read_content`。
7. **前端两个应用**（同一 Vite 工程，管理后台单独分包，员工端的产物不含管理页面代码；企微 H5 就是员工工作台，不另做应用）：
   - 员工工作台 `/workspace`：适配手机；企业管理后台 `/admin`：只做电脑端，凭治理权限进入。功能清单与每项归属见 `design.md` 第 4 节。
   - 入口由 `/auth/me` 返回的 `entries`（`workspace`、`admin`）决定，前端不自行推断。
   - 取消平台管理界面：删除 `/platform-admin` 及其页面，删除跨企业的 `/admin/tenants`、`/admin/summary`、`/admin/agents`、`/admin/sessions` 接口，平台运维不再通过 Web 看到任何企业的数据。`users.is_platform_admin` 只保留给命令行与内置技能导入接口使用。
   - 企业自行配置的外部向量库、存储后端连接，与模型调用共用同一套网络出口策略（默认只允许公网 HTTPS，拒绝私有地址），防止企业管理员借此访问部署内网。管理类接口统一加前缀 `/api/v1/tenants/{id}/admin/...`，便于以后在网关层单独设防；权限判断仍在每个接口内。
8. **知识库维护开放给智能体管理员**：`can_maintain_content` 成立的条件是：调用者满足 `can_write`；或者调用者对某个本企业智能体有 `manage` 权限，且该智能体的草稿或已发布版本绑定了这个知识库。开放的操作只限内容维护（上传、删除、重新解析文档，编辑分块与问答）。库的设置、删除、可见范围与共享仍属于企业 owner、admin 与库创建者。共享来的库在接收方仍然只读。
9. **SaaS 部署前提**：PostgreSQL 为事实源，`split` 模式加多 worker，Redis 事件通道。路线图 2.9 由“暂跳过”改为本提案的前置门禁。SQLite 保留给开发与单机部署。

## 范围

阶段划分见 `tasks.md`。每个阶段开始前，在 `design.md` 补齐该阶段的接口与表结构，并经用户确认。

- E0 知识库维护开放给智能体管理员（决定 8）。
- E1 租户与个人区：注册即创建企业、停止新建个人空间、私有知识库、企业策略、企业级管理角色、PostgreSQL 门禁（决定 1、2、3、6、9）。
- E2 前端两个应用：员工工作台与企业管理后台的拆分，取消平台管理界面（决定 7）。
- E3 企业微信：按企业接入、免登与自动开户、通讯录同步、离职撤销成员身份、企微 H5 手机适配、消息渠道（决定 4）。
- E4 组织驱动授权：智能体与知识库按部门、成员开放（决定 5）。
- E5 成本与配额：企业、部门、个人三级的 Token 预算与用量报表。超出后拒绝新 Run，进行中的 Run 不受影响。
- E6 数据治理：留存清理、审计导出。

范围外：

- 平台运营界面：企业审核开通、停用、上限设置、计费与支付。
- 离职资产移交、审批路由（上级或资源负责人审批、审批超时、审批待办、企微审批卡片）。
- 对外嵌入页的后端实现（另提案，功能清单先列在 `design.md` 第 4 节）。
- 企微第三方应用（服务商）模式、飞书、钉钉、SAML、LDAP、SCIM。
- 知识库文档级 ACL 与源系统权限同步。
- 企业智能体目录与发布审核。

## 需要你确认的项

每项都给出了建议。

1. **企微接入模式**：建议支持代开发应用与自建应用。第三方应用只返回加密的 `open_userid`、拿不到成员姓名，暂不支持。两种模式下各接口实际返回哪些字段，在 E3.0 核对官方文档；未核对的按 `unverified` 处理，缺失时降级为“只用 userid，姓名由员工首次登录时补全”。
2. **现有个人空间数据**：如果只是开发库，建议直接删除，并在迁移中移除 `personal` 取值；如果有需要保留的数据，建议把每个个人空间原地改为企业（`kind` 改为 `enterprise`，补企业编码），本人仍是 owner，数据不动。
3. **个人模型（决定 2 `personal_models`）**：建议默认关闭，由企业管理员按需打开。
4. **自动开户的默认角色**：建议 `contributor`。
5. **决定 8 的门槛**：建议只开放给智能体的 `manage`，不开放给 `edit`。

## 验收

- 自助注册创建企业，注册人为 owner，可以立即邀请成员、接入企微；不能再新建个人空间；登录后进入上次使用的企业，属于多家企业时可以切换。
- 新建知识库默认只有本人（以及按决定 8 获得维护权的人）和企业 owner、admin 可见；改为全企业可见后，其他成员可读。绑定私有库的智能体，在共享给其他人时被发布检查拦截。
- 企业策略关闭自建后，没有资格的成员创建智能体返回 403；`external_sharing = false` 时不能共享到含其他企业的共享空间。
- 员工工作台在手机宽度下可用，且不加载管理后台的代码；没有治理权限的成员访问 `/admin` 被拒绝，管理接口返回 403。
- `/platform-admin` 与跨企业的 `/admin/*` 接口已删除；企业管理员把向量库或存储指向私有地址时被拒绝。
- 在企微可见范围内的成员首次扫码或免登，即自动进入企业；不在范围内的成员被拒绝。离职同步后，该成员的下一次请求与下一次工具调用都被拒绝。
- 按部门共享的智能体：调入该部门的人立即可用，调出的人立即不可用。
- 对智能体有 `manage` 权限的成员可以维护其绑定知识库的内容，不能删除库、修改设置、可见范围或共享；解除绑定后失去维护权。
- `uv run --locked pytest` 覆盖以上分支；PostgreSQL 目标环境通过路线图 2.9 的全部项目。
