# 企业级员工智能体平台（SaaS 多企业）

## 状态

草案，待确认（2026-11-11）。下列“已确认的方向”来自用户 2026-11-11 的回答；“需要你确认的项”确认之前不开始编码。

## 背景

现有底座里，运行时契约、ToolGateway 单调守卫、执行时复核授权、三类授权分离（ResourceGrant / ActionGrant / ActionApproval）、派发账本与审计都可以直接用于企业场景。偏 To C 的部分集中在“谁说了算”：

| 维度 | 现状（代码位置） | 企业场景的缺口 |
|---|---|---|
| 企业生命周期 | 自助注册即开通企业空间（`auth/accounts.py` `register`），`tenants.status` 只有 `active` / `archived`；平台管理员只有只读汇总 | SaaS 运营方无法开通、停用企业，也不能设定企业的套餐与上限 |
| 企业微信 | 每个部署只有一个自建应用（`configs [wecom]`、`auth/wecom.py`），只做扫码登录与绑定，不自动开户，不同步通讯录 | 多企业各自接入企微；员工从企微首次进入时自动开户；部门、人员、上级、离职状态随企微同步 |
| 组织与授权 | `org_units` 每企业一棵树，但组织位置不参与授权（`2026-11-03-enterprise-personal-spaces` 决定 7） | 智能体与知识库无法按部门开放；调岗与离职不联动 |
| 审批 | 只有 Run 所有者能审批（`runs/approvals.py` `resolve`） | 高风险动作需要直属上级或资源负责人审批 |
| 企业管控 | 没有企业级策略；个人模型与个人 Key 在企业空间内可用；共享空间可以跨企业共享 | 企业需要统一控制自建、模型、外部共享与数据留存 |
| 知识库维护 | 只有空间 owner、admin 与库创建者能写（`knowledge/access.py` `can_write`） | 智能体的管理员也要能维护该智能体所用的知识库 |
| 成本 | 只有并发上限与后台模型限流 | 没有按企业、部门、个人的 Token 与费用预算和用量报表 |
| 部署 | 默认 SQLite，PostgreSQL 目标环境验收（路线图 2.9）暂跳过 | SaaS 必须以 PostgreSQL 为事实源，多 worker 部署 |

## 已确认的方向（2026-11-11）

1. **SaaS 多企业**：一套部署服务多家企业。沿用现有模型：企业即 `kind = 'enterprise'` 的租户，组织树、成员、角色、模型、智能体、知识库都按企业隔离。不再引入“企业 → 部门工作区”的空间层级，部门差异通过组织驱动授权表达（见决定 4）。
2. **企业微信为主身份源与主入口**：每家企业独立接入企微，支持扫码与企微内免登、首次进入自动开户、通讯录同步，并把企微作为对话与审批入口（承接路线图 9.1）。
3. **保留个人空间**：个人空间仍是账号自己的空间，不属于任何企业，也不受企业策略约束。企业数据不得流入个人空间（见决定 6）。
4. **员工自建智能体默认开放**：企业成员可以自建智能体，与现状一致；企业策略提供开关，可按企业关闭或限定部门。
5. **知识库维护对智能体管理员开放**：对智能体有 `manage` 权限的人，可以维护该智能体所绑定的本企业知识库（范围见决定 8）。

## 决定（建议，待确认）

1. **企业生命周期由平台运营方管理**：`tenants.status` 增加 `suspended`。企业开通有两种方式，由 `[platform].enterprise_signup` 控制：`open`（自助注册即开通，现状）、`review`（注册后为 `pending`，平台管理员审核开通，SaaS 推荐）。停用的企业：成员无法进入，Run 不再领取，定时任务暂停，数据保留。平台管理员可以设定每家企业的上限（成员数、并发会话、月度 Token），平台管理员的所有操作写入平台审计。
2. **企业策略（`enterprise_policies`，每企业一行）**：只能收紧，不放宽平台已有的守卫。首批字段：
   - `self_build_agents`：`all`（默认，决定 4）、`org_units`（只有列出的部门可以自建）、`none`；
   - `personal_models`：成员在企业空间内能否使用个人模型与个人 Key，默认 `false`；
   - `external_sharing`：智能体、知识库能否共享到含其他企业的共享空间，默认 `false`；
   - `retention_days`：会话与运行事件的保留天数，空值表示不清理。
3. **企业微信按企业接入**：
   - 新增 `tenant_wecom_apps`（每企业一行）：接入模式（`self_built` 自建应用，或 `custom_dev` 代开发应用）、`corp_id`、`agent_id`、加密保存的 `secret`、回调 `token` 与 `encoding_aes_key`，以及最近一次同步状态。`configs [wecom]` 只保留为开发与单企业部署的默认值。
   - 登录：扫码与企微内网页免登都按 `corp_id` 找到企业，再按 `(wecom, corp_id, userid)` 找到账号。**首次进入自动开户**：成员在企微应用的可见范围内、且已经同步到本企业时，创建账号并加入企业（`source = 'wecom'`，默认角色 `contributor`），不再要求先用密码登录后绑定。
   - 通讯录同步：每天全量一次，加上回调增量。同步部门（写入 `org_units.source = 'wecom'`）、成员、主部门、直属上级、在职状态。手动维护的部门不受影响。
   - 离职：企微删除成员或成员离开可见范围时，撤销其企业成员身份，并撤销其 ActionGrant、MCP OAuth 令牌和定时任务。名下的智能体、知识库与定时任务转给直属上级；没有上级时转给企业 owner。每一步写入审计。
   - 第三方应用模式不在本提案范围内（见需要确认的项 1）。
4. **组织驱动授权**：智能体共享与资源授权的接收方，从“角色”扩展为“角色、部门（含子树）、成员”三种。部门授权在每次判断时按当前组织关系展开，调岗后下一次调用即生效，与“执行时复核”原则一致。部门本身仍不继承空间角色（沿用 `2026-11-03` 决定 8）。
5. **审批人路由**：工具风险策略增加审批人：`self`（默认，即现状）、`manager`（直属上级，来自企微同步）、`resource_owner`、`role:<角色>`。非本人审批时，Run 进入 `waiting_approval` 并释放 worker，审批通过企微卡片与 Web 待办处理。审批超时（默认 24 小时）后拒绝，不自动放行。`destructive` 工具不能设为 `self`。
6. **个人空间与企业的边界**：企业的智能体、知识库、技能、产物不能共享、复制或导出到个人空间。会话分叉不能跨空间。企业成员在个人空间内使用的任何资源都与企业无关。这一条无需新表，在共享与分叉入口加校验，并补测试。
7. **企业级管理角色**：内置角色增加 `security_admin`（工具风险策略、审批路由、企业策略）和 `auditor`（只读审计，默认看不到对话正文）。两者是企业级（租户级）的内置自定义角色，复用 `tenant_roles` 与 `authz/catalog.py`，新增 API 权限 `policy:manage`。
8. **知识库维护开放给智能体管理员**：`knowledge/access.py` 的 `can_write` 增加一条：调用者对某个本企业智能体有 `manage` 权限，且该智能体的草稿或已发布版本绑定了这个知识库。开放的操作只限内容维护（上传、删除、重新解析文档，编辑分块与问答）。库的设置、删除和共享仍然只属于空间 owner、admin 与库创建者。共享来的知识库在接收方仍然只读。
9. **SaaS 部署前提**：PostgreSQL 为事实源，`split` 模式加多 worker，Redis 事件通道。路线图 2.9 的 PostgreSQL 目标环境验收由“暂跳过”改为本提案的前置门禁。SQLite 保留给开发与单机部署。

## 范围

阶段划分见 `tasks.md`。每个阶段开始前，在 `design.md` 补齐该阶段的接口与表结构，并经用户确认。

- E0 知识库维护开放给智能体管理员（决定 8，独立且改动小，先做）。
- E1 SaaS 企业底座：企业生命周期、企业策略、企业级管理角色、个人空间边界、PostgreSQL 门禁（决定 1、2、6、7、9）。
- E2 企业微信：按企业接入、免登与自动开户、通讯录同步、离职处理（决定 3），以及企微消息渠道（路线图 9.1）。
- E3 组织驱动授权与审批路由（决定 4、5），含企微审批卡片。
- E4 成本与配额：企业、部门、个人三级的 Token 预算与用量报表；超出后拒绝新 Run，进行中的 Run 不受影响。
- E5 数据治理：留存清理、审计导出、离职员工的记忆处理。

范围外：

- 企微第三方应用（服务商）模式、飞书、钉钉、SAML、LDAP、SCIM。
- 计费与支付；E4 只做用量和上限，不做收费。
- 知识库文档级 ACL 与源系统权限同步。
- 企业智能体目录与发布审核：由于员工自建默认开放，本提案不强制审核，等使用后再评估。

## 需要你确认的项

每项都给出了建议。

1. **企微接入模式**：建议优先支持代开发应用，并保留自建应用（适合单个大客户私有部署）。第三方应用拿不到成员姓名等字段，只返回加密的 `open_userid`，需要通讯录转译，暂不支持。代开发与自建两种模式下，各接口实际能返回哪些字段（姓名、直属上级、手机号）实施前要核对企微官方文档；未核对的字段按 `unverified` 处理，缺失时降级为“只用 userid，姓名由员工首登时补全”。
2. **企业开通方式**：建议 SaaS 默认 `review`，即平台审核后开通。
3. **个人模型（决定 2 `personal_models`）**：建议企业空间内默认关闭，由企业管理员按需打开。
4. **自动开户的默认角色**：建议 `contributor`。
5. **决定 8 的权限门槛**：建议只开放给智能体的 `manage`，不开放给 `edit`。“智能体管理员”是否还指别的角色（例如一个空间级的“智能体管理员”角色）？
6. **离职资产移交对象**：建议直属上级，没有上级时转给企业 owner。
7. **审批超时**：建议 24 小时后拒绝。

## 验收

- 平台管理员可以审核、开通、停用企业；停用后成员不能进入，不再领取新的 Run，恢复后数据完整。
- 企业策略关闭自建后，没有资格的成员创建智能体返回 403；个人空间不受影响。
- 企业资源不能共享、复制或分叉到个人空间；`external_sharing = false` 时不能共享到含其他企业的共享空间。
- 在企微可见范围内的成员首次扫码或免登，即可自动进入企业；不在范围内的成员被拒绝；离职同步后，该成员的下一次请求与下一次工具调用都被拒绝，名下资产已移交，审计完整。
- 按部门共享的智能体：调入该部门的人立即可用，调出的人立即不可用。
- 风险策略设为 `manager` 时，由直属上级在企微卡片中审批；本人不能审批；超时后拒绝。
- 对智能体有 `manage` 权限的成员可以维护其绑定知识库的文档，不能删除库、修改库设置或共享；解除绑定后失去维护权。
- `uv run --locked pytest` 覆盖以上分支；PostgreSQL 目标环境通过路线图 2.9 的全部项目。
