# 以 GenericAgent 与 WeKnora 核心源码重实现 P0–P2

## Why

用户要求从两个开源项目的实际核心代码出发重新实现，而不是继续按概念补接口或把现有测试通过视为迁移完成。当前代码已有可用闭环，但不能证明与两项目完整核心行为等价；平台 35 个 ORM 类集中在一个文件，运行准备/持久化、双协议状态、工具注册与执行仍有职责集中。

本变更以 Git `e63e29a` 为现有交付基线，采用“重新分析→源码迁移/等价翻译→逐批替换→行为验收”的方式重做平台与 Native 核心。现有修复作为兼容基线，不因重做而丢失错误终态、工具完整性、授权、幂等、事件重放和凭据保护。

## What Changes

- GenericAgent 固定 `a9a36b4b219593369de01c3e5973e56ac02e568b`：迁移 loop/StepOutcome/handler、生成器工具、模型协议与会话、上下文与工作记忆、收尾队列、hooks、项目上下文、长期记忆/SOP 流程的实际逻辑。可独立复用的 Python 算法复制后做最小适配，不凭概念重写。
- WeKnora 固定 `e1f9a6166a593a4804a2f99f1d942919c9cc8ea7`：按 Go 实现逐分支翻译 ReAct、完成/截断/空响应/重复保护、模型协议、压缩与校准、steer、工具读写屏障、挂起恢复、动作授权，以及平台 service/repository 的职责边界。
- 平台按领域分开实体、仓储、事务与应用服务；Native 按执行、模型、工具、上下文、记忆、hooks、审批恢复组织；入口和 `__init__.py` 只组合/兼容导出。具体类分布见 [设计](design.md)。
- 在每个实施批次记录来源版本/函数/哈希、执行分支、原测试、目标代码、直接复制或等价翻译、适配差异与可执行证据。未深读的文件与未验证的能力继续标为未完成。
- 重建实际业务链路，沿用兼容 facade/旧导入与现有数据；补齐必要的新快照/授权字段时使用增量迁移、版本化契约与前端设置，不清库或废弃现有会话。

## Capabilities

### New Capabilities

- `reference-core-rebuild`：可追溯的双参考核心实现、多模块职责分布、兼容替换与差分验收。

### Modified Capabilities

无已发布能力规格直接替换；既有 model-terminal-consistency 作为必过回归。P1/P2 活动变更仍单独追踪真实环境与完整验收，不因本提案提前归档。

## Scope

P0：保留 Python/uv/Vue 工程与应用组合入口，核对依赖方向、模块组织和来源归属，不无故重写构建基础。

P1：身份/空间、Agent 与模型配置版本、资源授权、Session/Message、Run/Event/Outbox、worker lease、动作审批/授权、仓储与事务，以及现有 API 的兼容整合。

P2：唯一 Native 循环、模型请求与完整会话状态、上下文/压缩/工作记忆、工具分发与生命周期、停止/steer、版本化快照和恢复、记忆/SOP 的合法读写流程、用户配置及既有对话/运行状态。

两项目知识库、MCP/技能资源、协作、定时、渠道等与核心调用链相关的代码都要分析并登记依赖；独立产品功能按原路线图阶段接入，不在没有资源服务时伪装成已实现。此前沙箱后端和六项执行/文件/浏览器工具的暂缓安排继续有效：分析其真实逻辑并保留差异，不能将接口或模拟工具说成迁移完成。若要解除暂缓，需要另行确认具体隔离方案。

## Confirmed intent and decisions for review

用户已经明确提出重做方向。本次具体实现方案尚待确认，尤其是 [设计中的冲突决策](design.md#两项目冲突与拟采用行为)：完成/失败口径、取消后不额外请求模型、hooks 的变换边界、记忆治理、动作授权与旧版本兼容。初轮证据见 [source-analysis.md](source-analysis.md)，全部核心文件深读仍有未完成项。

不恢复已删除的 `docs/pending` 审查文件或 `third_party` 目录；本次工作记录集中在这个 OpenSpec 变更中。源码复用需要的来源、版权和适用许可保留在目标模块文件头及包内文档，不提交整个上游仓库。
