# 前端开发规范

本文适用于 `apps/web` 的页面、组件、路由、状态管理和 API 接入。项目总约束见根目录 [AGENTS.md](../AGENTS.md)。

## 技术栈与组织

- 使用 Vue 3、TypeScript、Element Plus 和项目已采用的 Vite 工具链。新组件优先使用 `<script setup lang="ts">` 与 Composition API；避免无必要引入第二套组件库或状态方案。
- 页面放在 `src/views/`，可复用组件放在 `src/components/`，请求封装放在 `src/api/`，跨页面组合逻辑放在 `src/composables/`，共享类型放在 `src/types/`。目录边界按实际规模渐进建立，不为占位而复制业务逻辑。
- 单文件组件保持单一职责。页面负责组合和导航；复杂交互拆到 composable；纯展示组件通过 props/emits 交互，不直接调用全局 API 或持有隐式跨页面状态。
- 后端 API 通过类型化客户端/模块封装。组件不得自行拼接重复 URL、定义与服务端冲突的 DTO，或绕过统一错误处理。

## 类型、数据与状态

- TypeScript 开启严格类型检查；避免 `any`、无边界类型断言和未经校验的 API 响应。API 请求/响应、Run 事件和资源状态使用明确的联合类型或接口。
- 将服务端事实与本地交互状态分开。不要把权限、Run 最终状态或资源版本只保存在客户端作为可信依据。
- 加载、空结果、部分结果、失败、无权限和重试状态都要有明确 UI。异步请求处理取消、重复触发和组件卸载；避免旧响应覆盖较新的页面状态。
- 对 Run/SSE 等流式功能按稳定事件 ID/sequence 消费，处理断线续读与重复事件；客户端重连不能重新提交执行任务。

## 交互与视觉

- 使用 Element Plus 的既有交互模式和项目全局样式。保持按钮、表单、反馈、弹窗、表格和状态标签的一致性；引入新视觉模式前先检查现有页面和设计文档。
- 表单提供标签、必填/格式提示、字段级错误和提交中状态；破坏性操作需清楚说明对象和后果，并使用合适的确认交互。
- 长任务明确展示当前状态、阶段和可用操作；运行失败、等待审批、取消中和取消完成需要区分。
- 页面在窄屏与常见桌面尺寸下保持可用；避免仅依赖颜色传达状态。为键盘操作、焦点顺序、可读标签和对比度提供基本无障碍支持。
- 文本使用用户语言描述业务结果，不向普通用户泄漏 SDK、队列、数据库等实现细节；开发诊断通过受控日志/诊断信息呈现。

## 安全边界

- 前端不保存或展示模型供应商、MCP、渠道等秘密；凭据创建/轮换流程只传递一次性输入并遵循后端返回策略。
- 客户端隐藏按钮只改善体验，不构成授权。服务端拒绝无权请求后，前端应显示明确状态并清理失效数据。
- Markdown、代码、文件名和事件正文均视为不可信输入；通过安全组件渲染，禁止直接注入未净化 HTML。

## 验证与交付

- 页面逻辑复杂时为用户关键路径补充组件或端到端覆盖；保持测试关注可观察行为，不锁定无关实现细节。
- 前端改动按根目录 AGENTS.md 执行 `npm ci` 和 `npm run build`；提交前检查类型错误、控制台错误、窄屏布局与键盘交互。
- 只改文档时不要求安装前端依赖，检查链接、格式和差异即可。规划占位页需显式标注能力尚未接入。
