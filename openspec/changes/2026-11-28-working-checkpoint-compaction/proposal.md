# 工作检查点推进会话摘要

## 动机

`update_working_checkpoint` 当前只把模型提供的摘要写入 `session_checkpoints`，供后续 Run 作为额外系统上下文读取；它没有推进 `context_summaries` 的覆盖边界。因此，即使智能体明确整理了历史，后续 Run 仍会再次装入此前消息。

## 范围

- 成功更新工作检查点时，在同一事务中将检查点内容追加为会话上下文摘要，并覆盖到当前 Run 的最新已保存消息；当前 Native Run 后续请求也立即折叠上下文。
- 保留全部原始消息与追加式摘要链；当前 Run 与后续 Run 使用最新有效摘要及其边界后的消息，当前请求保留完整工具交换。
- 避免同一检查点同时以摘要和工作检查点两种形式重复注入。
- 更新工具说明、规格、文档和测试。

## 非目标

- 不删除或改写 `messages`、Run、工具调用或事件记录。
- 不改变基于上下文窗口阈值的自动压缩算法或 token 预算。
- 不将普通待办/短便笺自动视为完整会话摘要；工具调用者应提供用于续接任务的简明上下文。

## 验收

- 更新检查点后，新 Run 的模型请求包含检查点摘要，并省略切点前的原始消息。
- 同一 Run 的后续模型请求立即使用检查点摘要，并保留检查点之后的当前完整工具交换。
- 摘要不重复注入；不前移的摘要不会倒退或覆盖已有切点。
- 原始消息仍可在会话记录与轨迹中查看。
