# 模型管理：参考 WeKnora 的类型化模型页与添加流程

## 状态

提案草稿，待确认。确认前不编码。涉及持久化模型（模型类型、默认模型按类型拆分）和 API 契约（新增未保存配置的测试接口），按 AGENTS.md 须先确认。

## 背景

当前模型设置页 `apps/web/src/views/settings/ModelSettingsView.vue` 是"提供商 → 模型"两级列表，附默认模型、协议兼容和智能体创建区块。后端 `packages/platform/src/nexus_platform/models/provider_settings.py` 只允许三种对话协议（`openai_chat_completions`、`openai_responses`、`anthropic_messages`），默认模型只按"个人 / 空间"两个作用域保存，测试连接必须针对已保存的模型档案。

WeKnora 的"模型管理"（`03-features/06-models`，截图 `model-editor-catalog.png`、`settings-models.png`）把模型按类型组织：

- 类型：对话、Embedding、ReRank、视觉、语音，每类有计数标签页。
- 卡片网格，末尾为虚线"添加模型"卡片。
- 添加抽屉：类型切换、来源（API / Ollama）、服务商、模型名（目录下拉，显示上下文长度与推理、视觉标签）、Base URL、API Key、自定义请求头，以及"实际调用方式"面板。
- 底部"测试连接"可测试表单当前配置，无需先保存。
- 默认设置按 6 个类型分别指定模型。

参考项目：WeKnora（`Tencent/WeKnora`，`frontend/src/views/settings/` 与模型相关组件）。

## 范围

范围内（阶段 2 的一部分）：

1. **类型化列表**：页面顶部为类型标签页（全部、对话、Embedding、ReRank、视觉、语音，带计数）；内容为卡片网格，每张卡显示名称、服务商、协议或维度信息。删除现有的两级列表。
2. **添加与编辑抽屉**：
   - 顶部类型切换与来源切换（本阶段来源固定为 API，见范围外）。
   - 服务商下拉，列表为"自定义（OpenAI 兼容）"加现有服务商。
   - 模型名称输入，附前端静态预设下拉（名称、上下文长度、能力标签）；预设不改变后端数据。
   - Base URL、API Key（保持现有的只写加密存储）。
   - "实际调用方式"面板：只读展示协议（由 `protocol` 选项推出）、流式开关、温度、思考强度。数据来自已有字段，不新增接口。
   - 底部"测试连接""取消""保存并关闭"。
3. **测试连接**：支持测试表单中未保存的配置（见决定 2）。
4. **默认设置**：按模型类型分别指定默认模型（见决定 3），每次选择即时保存，显示当前生效模型及来源。
5. **类型字段**：模型档案增加 `model_type` 字段（`chat`、`embedding`、`rerank`、`vision`、`speech`），已有记录迁移为 `chat`。

范围外（另行提案）：

- Ollama 本地来源与本地模型下载。
- 服务端模型目录与管理员目录编辑（WeKnora 的 `models/catalog`），本阶段目录只用前端预设。
- 模型调试器（发起真实请求并展示脱敏请求与响应）。
- 协议兼容覆盖 JSON（WeKnora 的 compat 字段）。本阶段保持现有选项白名单。
- 其他非对话类型的运行时消费：Embedding、ReRank、视觉、语音在知识库阶段（路线图第 6 步）才有调用方。本阶段仅能配置与保存。
- 30 家内置服务商。本阶段保留现有服务商与"自定义"。
- 知识库、智能体对模型的引用检查与删除保护（依赖第 6 步）。

## 需要你决定的项

1. **非对话类型是否本阶段纳入**。
   - 选项 A：纳入 `model_type` 字段，Embedding、ReRank、视觉、语音可以添加和保存，但运行时尚无调用方。
   - 选项 B：只做对话类型，其他类型标签页隐藏，等第 6 步再加。
   - 建议：选 A，理由是类型字段是持久化变更，越早加入迁移越简单。非对话类型在抽屉中可选，卡片上标注"待知识库阶段启用"。
2. **测试连接是否支持未保存配置**。
   - 选项 A：新增 `POST /api/v1/tenants/{tenant_id}/model-settings/test`，请求体为表单配置，返回连接结果。这是 API 契约的新增接口。
   - 选项 B：保持现状，必须先保存再测试。
   - 建议：选 A。配置表单需要先测后存，否则错误配置会先落库。该接口沿用现有的限频（10 秒一次）与 15 秒超时，且不回显密钥与原始错误。
3. **默认模型是否按类型拆分**。
   - 选项 A：`model_defaults` 的主键增加 `model_type`，作用域（个人 / 空间）与类型共同决定默认。迁移时把现有记录归为 `chat`。
   - 选项 B：保持按作用域的单一默认，其他类型只能手选。
   - 建议：选 A，与 WeKnora 的 6 个默认槽位一致，并避免第 6 步再次迁移。
4. **目录是否前端静态预设**。
   - 选项 A：前端写死少量预设（约 10–20 条），不新增接口。
   - 选项 B：服务端目录接口，可由管理员维护。
   - 建议：选 A。服务端目录属于管理员功能，另行提案。

## 验收

- 类型标签页计数与卡片数量一致，切换类型不刷新整页。
- 添加抽屉中，"测试连接"在未保存时可用（若决定 2 选 A）；失败提示不包含密钥与原始供应商错误。
- 默认设置按类型保存，刷新后保持；迁移后已有的对话默认值保留。
- 现有的协议白名单、密钥只写加密与授权检查不变，`uv run --locked pytest` 相关用例全部通过（含迁移测试）。
- `npm run build` 通过；`tests/web` 中模型页的浏览器测试按新界面更新后通过。
- 375px、768px、1024px、1440px 宽度下无横向滚动。
