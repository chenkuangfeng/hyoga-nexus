# 空间角色分配给组织人员：组织成员通过空间角色使用智能体

## 状态

待确认（2026-11-01 修订）。修订内容：角色仍由空间定义，分配对象改为绑定组织子树内的具体人员，不再按节点整体分配。确认前不进入实施。

## 背景

用户组织管理（`2026-11-01-user-org-management`）已实现组织树与空间绑定。本变更解决：空间绑定组织后，组织中的人员如何获得空间内的角色，并通过角色使用智能体。

## 核心链路

1. 平台管理员把空间绑定到组织节点（已实现）。
2. 空间的 owner 或 admin 在本空间定义角色（`tenant_roles`，已有）。
3. 角色通过 `tenant_agent_grants` 决定能用哪些智能体，以及 view/run 权限（已有机制）。
4. 空间的 owner 或 admin 从绑定子树的人员中**选择具体人员**，把角色分配给他们。被分配的人不写入成员表。

同一个人可以拿到不同的角色；同一角色可以分配给不同部门的人。

## 范围

范围内：

- **空间内定义角色**：沿用现有的角色管理。
- **分配给组织人员**：从绑定子树中选人，分配空间内的角色。
- **有效权限**：成员记录的权限 ∪ 个人在组织中分配到的角色权限。
- **空间可见性**：被分配了角色、且仍在绑定子树内的人，登录后能在空间列表中看到该空间，并看到角色允许的智能体。
- **聊天记录与记忆的可见性**：沿用已确认的规则。
- **组织成员切换到空间使用智能体**：会话与记忆写入智能体所在的空间，owner 为该用户。

范围外：

- 把组织授予 owner 或 admin 身份。
- 修改 owner、admin、member 三种成员字段，它们保持现状。
- 把组织人员写入成员表。个人显式加入（`from-organization`）仍保留，它写入成员表，成员字段为 member。
- 节点级别的角色分配（按节点整体分配）。
- 跨集团分配（当前只支持单集团）。

## 成员字段与角色

- owner、admin、member 仍是成员记录上的字段，本次不改动。
- 组织人员分配到的只能是**自定义角色**。他们不会获得 owner 或 admin 的权限。

## 权限计算

- 有成员记录：权限 = 成员字段与个人角色（现有逻辑）∪ 组织分配给该人的角色。
- 没有成员记录，但被分配了角色、且仍在绑定子树内：权限 = 分配的角色。这类人不是成员，不能进行成员管理。
- 被分配了角色、但已不在绑定子树内：角色不生效，等同于无权限，返回 NotFound。
- 其他情况：无权限。

`tenant_user_roles` 仍然只挂在成员记录上，不改外键。组织人员的角色使用单独的表。

## 聊天记录与记忆的可见性（已确认）

- **普通用户**：只能看到自己的聊天记录和记忆，可按智能体筛选。
- **空间管理员**（owner 与 admin）：可以看到其管理的空间里的全部聊天记录和记忆。
- **平台管理员**：可以看到全部聊天记录和记忆，可按组织、智能体、空间筛选。

已确认的细节：

- 组织成员在空间里的会话显示"组织访问"标识（默认方案）。
- 记忆（`memory_entries`、`memory_drafts`）与检查点（`session_checkpoints`）按同样规则开放。
- 平台管理员按组织筛选时，以会话创建时记录的组织节点为准。

注意：没有成员身份的组织人员不是空间管理员，因此看不到空间里其他人的会话。

## 与现有模型的关系

- 新增 `tenant_org_user_roles`：空间内人员与角色的关联，人员必须在该空间的绑定子树内（分配时校验，访问时再次校验）。
- 删除原草案中的 `tenant_org_roles` 与 `organization_agent_grants`。
- `tenant_agent_grants`、`tenant_user_roles`、`tenant_memberships` 的结构不变。
- `resource_grants` 不变。

## 影响

- 数据库：新增 `tenant_org_user_roles`，`sessions` 增加 `org_unit_id`（可空），一次迁移。
- 权限：空间成员判断、权限计算、智能体权限计算、空间列表都要合并组织人员的角色。
- API：从绑定子树选人分配角色、撤销；空间侧的分配列表；会话与记忆的读取范围调整。
- Web：空间设置中的"人员角色"区域（从绑定子树选人，选角色）；空间列表的组织来源标记。UI 按 AGENTS.md 使用 `ui-ux-pro-max` 技能。
- 文档：更新 `docs/architecture.md`、`docs/roadmap.md`、`packages/platform/docs/`。

## 需要你确认

1. **谁分配角色给组织人员**：空间的 owner 与 admin（默认）。绑定仍由平台管理员完成。
2. **组织人员只能分配自定义角色**，不能授予 owner 或 admin 身份（默认）。
3. **组织人员不写入成员表**，权限与列表实时计算（已选）。
4. **人员离开绑定子树（调动或解绑）时**：角色立即失效，记录保留；再次回到子树时恢复（默认）。若希望立即删除记录，请告诉我。
5. **会话的组织节点**：创建时快照写入 `sessions.org_unit_id`（默认，便于审计）。若希望少改一些，可以改为查询时计算，不加字段。
6. **"组织访问"标识**：默认显示。
