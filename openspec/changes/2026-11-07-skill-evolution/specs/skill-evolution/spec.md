# 规格：技能演进

来源：`openspec/changes/2026-11-07-skill-evolution`（待确认，确认并实施后归档）。

## 需求

### R1 作用域与内置技能、内置工具
- 技能按租户组织，分三层：内置技能（系统租户）、租户技能库、私有技能（租户内某个用户）。
- 内置技能与内置工具对所有空间有效，含个人空间：任一空间的智能体可绑定并使用，不需要启用步骤或授权行；普通空间不能创建、修改或撤销它们。
- 内置工具的高影响分组仍受分组可用性、智能体开关、`tool_access`、参数守卫与审批约束，不因全局生效而默认出现。
- 空间管理员可对本空间停用某个内置技能或工具：目录不再列出，发布智能体版本时拒绝绑定，调用时授权拒绝；不影响其他空间，不改变已发布的智能体版本。
- 空间自有的技能与工具只在本空间可用，只能分配给本空间的智能体；其他空间的智能体不能绑定、不能读取。
- 既有租户登记的工具绑定行为不变。
- 系统租户不可登录、不可加入、不出现在任何租户、成员、组织、注册或汇总列表中。
- 升级内置技能产生新版本；既有智能体版本绑定的旧版本不变，编辑器提示有新版本。
- 私有技能不登记为平台资源，不可绑定、不可授权，只有所有者的会话可见。
- 名字在「本人私有、本租户技能库、内置」范围内唯一；技能库后来发布同名技能时，该名字解析为技能库的技能，私有同名标记已被取代。

### R2 来源与信任
- 技能带来源（`builtin` / `admin` / `import` / `agent` / `user`），版本记录信任级、扫描器版本与结构化扫描结果。
- 发布与保存按放行矩阵处理：`builtin` 总是放行；`admin` 遇 `dangerous` 须显式确认并审计；`import` 遇 `caution` 或 `dangerous` 阻止，管理员可留理由放行；`agent` 遇 `caution` 进人工审核、遇 `dangerous` 拒绝；`user` 无论 `safe` 或 `caution` 都进人工审核，遇 `dangerous` 拒绝；私有技能遇 `dangerous` 拒绝保存，`caution` 放行并展示发现。
- 被阻止时返回稳定错误码和发现列表（规则、级别、文件、行号）；公开结果不含完整可疑内容。
- 扫描器升级后，旧版本标为需重扫；重扫只追加结果，不修改已发布内容。
- 扫描不替代运行时授权：技能不授予任何权限。

### R3 对话式创建私有技能
- 模型通过 `skill_manage` 编辑可变草稿；草稿不进入索引，不能被 `load_skill` 读取。
- `patch` 的匹配必须唯一；写入前必须在本 Run 内读过该草稿；附属文件只能在固定子目录；草稿数、私有技能数与大小有上限。
- `skill_save` 把草稿保存为私有技能的新不可变版本，每次需用户确认；保存前扫描并校验依赖工具名；含脚本的草稿在沙箱投射可用之前拒绝保存。
- 本人的 Run 的技能索引包含其启用的私有技能；其他用户、其他租户不可见、不可读。
- 会话中创建或保存的技能，经工具结果与追加的差异说明对该会话可用，系统提示与工具块不变。

### R4 共享到技能库与审核
- 私有技能与外部包可提交到技能库；成员提交需要 API 权限 `skills:submit`（owner 拥有，admin 基线包含，其他成员须经角色授予）；审核与发布需要 `tools:manage`；管理员共享自己的技能时直接发布。
- 模型与成员的提交都不能修改已发布版本，修改须带基础版本哈希；审核通过时哈希不符或新建时同名技能已存在，提交置 `superseded` 并要求重新提交。
- 待审总数、每用户每小时提交数、每用户同时待审数有上限，超限返回稳定错误码。
- 成员只能查看、撤回自己的提交，他人的提交对其返回不存在；拒绝须填理由；通过时重新校验依赖与扫描，再按既有发布流程生成新的不可变版本，版本记录可追溯提交人。
- 提交与审核内容按纯文本展示；审核页提示通过后对本租户所有智能体可用。
- 提交、撤回、通过、拒绝、放行发现均写审计。

### R5 上传、下载与技能包
- 导入统一解析为规范包后校验：条目数、总解压字节、单文件大小、压缩比、路径穿越、符号链接、重复路径、根目录 `SKILL.md` 与 UTF-8；超限或不合规的包被拒绝。
- 私有范围的导入成为草稿，技能库范围的导入产生提交，内置技能只能由平台管理员导入。
- frontmatter 接受已知可选键，未知键保留并提示，保守修复后标记；导出使用标准格式。
- 版本文件可含二进制内容并受总量上限；读取工具对二进制只返回元信息；往返导出导入后内容哈希一致。
- 单个技能与技能包可导出 zip：私有仅所有者可下载，技能库按读权限，内置所有人可下载。
- 技能包是分发单位：应用到智能体展开为逐个技能的版本绑定，包本身不进入运行时；内置包随内置导入创建。
- 不支持联网安装。

### R6 沙箱内执行
- 沙箱可用时，本会话可用的技能按内容哈希只读投射到 `/skills/<name>@<hash12>/`，沙箱内不能写入；其他会话、其他租户与未授权的技能不在其中；文件数与总字节有上限，超限时技能脚本不可用而内联加载不受影响。
- `run_skill_script` 在投射路径下运行脚本，参数经 stdin，每次调用需审批，不自动安装依赖。
- 脚本只在沙箱内运行；沙箱不可用时生产环境不提供脚本工具，开发模式的门禁只对内置技能开放。
- 开放网络的沙箱执行技能脚本时，每次调用强制审批。

### R7 目录与调用方控制
- 技能名为小写字母、数字、连字符，1–64 字符，不含保留词；已发布的旧名字不受影响。
- `model_invocable` 为假的技能不出现在模型的技能索引中，`load_skill` 与 `read_skill_file` 也拒绝。
- `user_invocable` 被保存与校验；用户侧入口待斜杠命令设计后接入。
- 智能体可逐个关闭已绑定的技能；变化产生新的智能体版本，已冻结的会话快照不变。

### R8 使用记录
- `load_skill` 成功时记录使用；长期未用且未固定的技能被标为 `stale`，归档由所有者或管理员决定。
- 归档的技能不进新会话的索引，历史版本与已有会话快照不变，可恢复；不自动删除。

## 兼容
- 既有技能、绑定、会话快照与智能体版本的行为不变；新增字段与新表有默认值；迁移可升可降。
