# 规格：Worker 并发执行与 unknown 会话恢复入口

来源：`openspec/changes/2026-11-07-worker-concurrency`（待确认，确认并实施后归档）。

## 需求

### R1 并发执行
- `[worker].max_concurrent_runs`（默认 1）限制一个 worker 进程内同时执行的 Run 数；默认值下行为与变更前一致。
- 一个 Run 的取消、失败、超时只影响它自己；其余 Run 继续。
- 同一会话的 Run 仍按会话先进先出串行，不同会话之间并行。
- 领取受信号量限制：没有空位不领取，不持有无人执行的租约。

### R2 数据库访问
- 同步数据库访问不得在事件循环线程内执行；统一经专用线程池，大小可配置，启动时与连接池容量校验，不合理的配置阻止启动。
- 事件循环滞后超过租约检查间隔时记录警告。

### R3 控制与停止
- 取消唤醒不占用线程；三个通道后端都提供异步等待。
- 进程停止时所有 Run 按现有路径收尾（`cancelled`）并释放租约，总超时后不强杀，由租约到期回收。

### R4 嵌入模式
- 嵌入模式使用一个线程、一个事件循环；模型共享连接池被所有 Run 复用。
- `[deployment].embedded_workers` 弃用，读取时给出警告。

### R5 unknown 恢复
- 提供列出与解除 `unknown` 的接口和命令行；解除写审计，幂等；Run 所有者与租户 owner / admin 可解除，其他成员被拒。
- 定时任务会话的 `unknown` 在启动恢复时自动解除，并写审计（执行者为系统）。
- `[platform].auto_resolve_safe_unknown` 默认关闭；开启后仅对没有未完成的有副作用工具调用的 Run 自动解除，无法判定的一律视为不安全。
- 被 `unknown` 阻塞的会话在会话视图中带 `blocked` 说明；有权限者可在界面解除。
- 不自动重放任何被中断的 Run。
