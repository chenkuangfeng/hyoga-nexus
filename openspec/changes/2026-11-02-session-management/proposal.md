# 会话管理：置顶、重命名、清空与批量操作

## 状态

草稿，待确认。来源：`openspec/changes/2026-11-02-weknora-parity-phase1/`（第 1 阶段拆出的后端相关部分）。涉及 API 契约与持久化模型变化，确认前不编码。

## 背景

WeKnora 的侧栏支持会话置顶、重命名、清空与批量管理（见 WeKnora `frontend/src/components/menu.vue`）。本仓库的会话只能新建、打开和查看；侧栏已经按最近更新分组显示，但没有任何管理动作。

## 范围

1. **置顶**：会话可置顶，置顶的会话在侧栏"置顶"分组中显示在最前。
2. **重命名**：会话标题可修改，长度与现有标题一致（不超过 160 字符，具体以后端现有校验为准）。
3. **清空**：清除一个会话的全部消息与运行记录，会话本身保留。
4. **删除与批量删除**：删除会话，支持多选后批量删除。
5. **侧栏交互**：会话项悬停或聚焦时显示"更多"菜单（置顶、重命名、清空、删除）；多选模式由侧栏顶部的"管理"按钮进入。

## 需要你决定的项

1. **清空的含义**：只删除消息与运行记录（会话保留，记忆快照与审计记录不动），还是同时解除与智能体版本的绑定。建议：只删消息与运行记录，会话保留，审计记录保留。
2. **删除是否可恢复**：立即物理删除，还是进入回收站（保留 30 天）。建议：先做物理删除，与现有会话的保留策略一致；回收站另行提案。
3. **记忆的处理**：删除或清空会话后，该会话由自动捕获产生的草稿与记忆条目如何处理。建议：草稿保留并标注来源会话已删除；已发布的记忆不受影响。
4. **权限**：会话的所有者可以置顶、重命名、清空、删除自己的会话；空间管理员是否可以删除他人会话。建议：只允许所有者操作，管理员仍通过平台的会话查询查看。

## 设计要点（待确认后细化）

- 后端：`sessions` 表增加 `pinned_at`（可空时间戳）；新增 `PATCH /tenants/{t}/sessions/{id}`（标题、置顶）、`POST /tenants/{t}/sessions/{id}/clear`、`DELETE /tenants/{t}/sessions/{id}`，以及批量删除 `POST /tenants/{t}/sessions:batch-delete`。
- 所有操作写入审计日志；操作前检查所有者身份与空间成员关系。
- 运行中的会话不允许清空或删除，返回明确的错误码（不静默忽略）。
- 前端：侧栏新增"置顶"分组与会话菜单；多选模式使用侧栏内的复选框与底部操作条。
