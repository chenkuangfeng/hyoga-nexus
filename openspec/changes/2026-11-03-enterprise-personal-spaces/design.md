# 个人空间与企业空间：设计

本文件是 `proposal.md` 的详细设计。决定与待确认项以 proposal 为准；本文件只补充流程、结构与界面。

---

## 1. 空间与账号模型

### 1.1 两种空间

| 项 | 个人空间（`kind = personal`） | 企业空间（`kind = enterprise`） |
| --- | --- | --- |
| 创建方式 | 个人注册时自动创建 | 企业注册时创建，注册人为 owner |
| 成员 | 只有本人（owner） | 全局账号的成员身份（第 1.4 节） |
| 加入方式 | 无（不能被邀请，也不能申请） | 管理员创建、邀请，或成员申请后审批通过（第 1.5 节） |
| 组织树 | 无 | 企业自己维护（子公司、部门） |
| 角色 | owner 固定 | owner、admin、member，以及自定义角色 |
| 模型 | 个人模型（个人 Key）与个人默认 | 企业默认模型 + 成员个人 Key（沿用现有 scope 规则） |
| 登录 | 手机号或账号 + 密码，之后选择空间 | 同左，可见空间由成员身份决定 |

### 1.2 注册流程

注册页分两个 Tab：**个人**与**企业**。

- **个人**：手机号、密码（账号可选，默认用手机号）。提交后创建用户、个人身份（provider `password`，scope 空）、个人空间（`kind = personal`，注册人为 owner），直接进入对话页。
- **企业**：企业名称、企业编码（3–32 位小写字母、数字、连字符，全平台唯一，注册前检查）、管理员账号、手机号、密码。提交后创建企业空间（`kind = enterprise`）与管理员账号（手机号必须是新的，已存在时改为先登录再创建企业），管理员角色为 owner，直接进入企业设置的"企业信息"页。

注册失败返回统一的错误信息；企业编码重复时单独提示。手机号已存在时提示"该手机号已有账号"，已登录用户可以在空间选择页直接创建企业。这会暴露手机号是否已注册，见 proposal 需要确认的项第 7 条。

### 1.3 登录流程

- **统一登录**：手机号或账号 + 密码，与现有 `POST /api/v1/auth/login` 相同，不再需要企业编码。
- **空间选择**：登录成功后列出该账号的全部空间（个人空间与所属企业），显示类型与角色。只有一个空间时直接进入。默认进入上次使用的空间（记在账号偏好中）。
- **切换空间**：用户菜单中的"空间切换"切换当前空间；切换只改变前端上下文，所有接口仍带 `tenant_id`，后端按成员身份复核。
- **首次登录改密**：`users.must_change_password = true` 时，登录成功后只允许访问改密接口与退出；前端跳转到改密页。
- **锁定**：沿用 `local_credentials` 的失败次数与锁定时间，按账号计算。
- **错误信息**：账号或密码错误返回同一提示。

### 1.4 一人一账号

`users` 全局唯一，手机号全局唯一。个人空间与每个加入的企业都是这个账号的一种成员身份（`tenant_memberships`）。一个人在多个企业工作时只有一套登录凭据。

这取代了此前"企业账号与个人账号互相独立"的设计。风险点是管理员可能为已存在的手机号设置密码，因此规则是：管理员对已存在手机号的人只能发起邀请（第 1.5 节），不能设置密码或修改账号信息；只有手机号不存在时才创建账号并设置初始密码。

### 1.5 加入企业：申请与邀请

- **申请**：已登录用户在空间选择页的"加入其他企业"中输入企业编码，确认企业名称，填写理由（选填）并提交。同一人对同一企业只能有一条待处理申请；申请人可以撤回。
- **审批**：企业管理员在"成员 → 待审批"（三级对话框）中查看申请。通过时选择部门（必选）与角色（默认 `member`，可选 `admin`，不能指定 `owner`），写入 `tenant_memberships`（`source = application`）与主部门记录。拒绝时填写原因，冷却期内（建议 7 天）同一人不能再次申请。
- **邀请**：管理员输入手机号或账号。账号存在时发出邀请（`direction = invitation`），选择部门与角色；用户在空间选择页接受或拒绝；接受后写入成员（`source = invitation`）。手机号不存在时，管理员创建账号（设置初始密码，首次登录改密），直接加入（`source = manual`）。
- **退出**：成员可在空间设置中退出企业（owner 除外）。成员记录标记为 `revoked`，部门记录与审计保留；个人空间与其他企业不受影响。
- **审计**：申请、撤回、审批（通过或拒绝及原因）、邀请、接受、退出均写入审计，记录操作人与对象。

## 2. 组织、部门与成员

### 2.1 组织树归属企业

- `org_units.tenant_id` 必填，每个企业一棵树（一个根节点，`parent_id` 为空）。
- 根节点名称默认为企业名称，可修改。
- 节点规则沿用 `2026-11-01-user-org-management`：层级不限、同级名称唯一、不能移到子孙节点下、停用节点不能作为新归属、删除前不能有子节点或人员。
- `org_units.source`：`manual`（企业管理员维护）或 `wecom`（预留，本阶段只用 `manual`）。

### 2.2 成员与部门的关系

```
tenant_memberships (tenant_id, user_id, role, source=manual)   ← 空间身份
        │
        └── user_org_units (tenant_id, user_id, unit_id, is_primary)   ← 部门位置
                 unit_id → org_units (tenant_id, …)
```

- 加入时（管理员创建账号、接受邀请、申请通过），同时写入 `tenant_memberships`（`source` 分别为 `manual`、`invitation`、`application`）与一条主部门记录（必须选择一个部门，默认根节点）。
- 人员可以有多个部门，但只能有一个主部门。主部门唯一约束为 `(tenant_id, user_id)`。
- 部门只决定组织位置与界面筛选，不决定权限。权限只来自 `tenant_user_roles`。
- 停用账号：`tenant_memberships.status = revoked`，保留部门记录，用于审计与恢复。

### 2.3 角色与部门

- 角色沿用 `tenant_roles`、`tenant_user_roles`，权限目录沿用 `authz/catalog.py`（菜单与 API 权限）。
- "按部门分配角色"是界面操作：选择部门 → 勾选成员 → 选择角色 → 写入 `tenant_user_roles`，每个人一条记录。不新增部门级角色表，撤销时逐人撤销。
- 新增 API 权限键 `org:manage`（维护组织树与部门归属），属于权限目录变化，需要在提案确认时一并确认。`members:manage`、`roles:manage` 沿用现有键。

### 2.4 企业微信

现状（代码核对）：

- 扫码登录：通过企业微信自建应用（`corp_id`、`agent_id`、`secret`，配置在 `configs/nexus.toml` 的 `[wecom]`）获取 userid。
- 绑定：已登录用户发起绑定，把 `(wecom, corp_id, userid)` 写入 `user_identities`。未绑定的企业微信用户不会自动创建账号。
- 没有通讯录同步：部门、成员都不从企业微信读取；`WeComDirectory` 只有授权地址与换 userid 两个方法。

本设计对企业微信的预留：

- 企业空间可以记录 `corp_id`（`tenants.wecom_corp_id`，可空，只记录）。
- 绑定时若企业空间已记录 `corp_id`，只允许绑定到本企业账号，避免跨企业绑定。
- 通讯录同步（后续提案）需要通讯录 Secret，读取部门后写入 `org_units`（`source = wecom`），成员写入 `tenant_memberships`（`source = wecom`）。本阶段不实现。

## 3. 界面

### 3.1 左侧栏（调整后）

只保留四块内容：新建会话、智能体（新建会话下方的快捷入口）、最近会话、底部用户。工具箱、产物、知识库、自动化、组织移入设置。智能体在设置的"功能"分组中仍保留管理页面，侧栏入口只是快捷方式。

```
┌────────────────────┬──────────────────────────────────┐
│ ＋ 新建会话          │                                  │
│ 🤖 智能体             │                                  │
│ ──────────────────  │                                  │
│ 今天                │                                  │
│   会话标题 A          │         对话页（主区域）            │
│   会话标题 B          │                                  │
│ 更早                │                                  │
│   会话标题 C          │                                  │
│ ...（滚动）           │                                  │
│ ──────────────────  │                                  │
│ 👤 张三 · 企业空间 ▴   │                                  │
└────────────────────┴──────────────────────────────────┘

点击用户名称弹出（向上展开）：
  ┌──────────────────────┐
  │ 张三                  │
  │ 当前空间：某某公司  ▸   │  ← 空间切换（子菜单，只列出有身份的空间）
  │ 设置                  │  → 路由到 /settings
  │ 退出登录               │
  └──────────────────────┘
```

- 侧栏宽度、折叠、响应式沿用 `2026-11-03-web-shell-tdesign` 的规则。
- 空间切换放在用户菜单中；只有一个空间时隐藏"空间切换"。
- 新建会话按钮保留 WeKnora 的快捷键提示。

### 3.2 设置的分组（按空间类型与角色显示）

设置是独立页面（`/settings`），分区是二级路由（`/settings/:section`），三级编辑使用抽屉或对话框。

**个人空间（owner）**

| 分组 | 分区 |
| --- | --- |
| 账户 | 个人资料、通用、我的记忆、环境变量 |
| 功能 | 知识库、智能体、工具箱、产物、自动化 |
| 模型与运行 | 模型管理、Native 运行 |
| 集成 | IM 渠道、API、MCP 服务器 |
| 数据与扩展 | 向量存储、解析引擎、存储引擎、沙箱、网页搜索 |

**企业空间（管理员：owner 或 admin）**

| 分组 | 分区 |
| --- | --- |
| 企业 | 企业信息、组织架构、成员、角色与权限、审计 |
| 账户 | 个人资料、通用、我的记忆、环境变量 |
| 功能 | 知识库、智能体、工具箱、产物、自动化（按角色显示） |
| 模型与运行 | 模型管理（企业默认与个人 Key）、Native 运行 |
| 集成 | IM 渠道、API、MCP 服务器（按角色显示） |
| 数据与扩展 | 向量存储、解析引擎、存储引擎、沙箱、网页搜索（仅管理员） |

**企业空间（普通成员）**：只显示"账户""功能"（按角色）与"模型与运行"中的个人部分。没有"企业"分组。

**系统管理（仅平台管理员，任何空间都显示在最后一组）**：系统设置、模型目录、任务队列、平台 API 密钥、审计日志（平台级）、会话查询、系统概览。平台管理员不在企业内部维护组织树。

### 3.3 "企业"分组的页面

**企业信息（二级）**：企业名称、企业编码（只读）、创建时间、企业微信 `corp_id`（可空，只读展示；本阶段由平台配置）。编辑名称使用对话框（三级）。

**组织架构（二级）**：

```
┌─────────────────┬──────────────────────────────────────┐
│ 🏢 某某集团       │ 部门：研发中心                          │
│  ├ 北京子公司      │ 上级：北京子公司    状态：启用           │
│  │  ├ 研发中心  ◀ │ 成员 12 人（主部门 9，兼任 3）            │
│  │  └ 销售部      │ [新增子部门] [重命名] [移动] [停用]      │
│  └ 上海子公司      │ ─────────────────────────────────── │
│                 │ 成员列表（主部门 / 兼任）                  │
└─────────────────┴──────────────────────────────────────┘
```

- 左侧树，右侧节点详情与成员列表；点击成员跳到成员页并筛选该部门。
- 三级：新增子公司或部门（对话框，名称、上级）、重命名、移动（选择新上级，自动拒绝子孙节点）、停用/启用（确认对话框，说明影响的人数）。
- 删除节点：只有空节点（无子节点、无成员主部门）才允许，按钮默认隐藏在"更多"中。

**成员（二级）**：

| 账号 | 姓名 | 手机 | 主部门 | 角色 | 状态 | 操作 |
| --- | --- | --- | --- | --- | --- | --- |

- 工具栏：新建账号、邀请、待审批（带数量角标）、按部门筛选、按角色筛选、批量分配角色（选中多人后打开三级对话框）、批量禁用。
- 三级：
  - 新建账号（抽屉）：账号、姓名、手机、主部门（必选）、兼任部门（可选）、角色（至少一个）、初始密码（管理员设置，提示"首次登录须修改"）。
  - 编辑账号（抽屉）：姓名、手机、部门（主与兼任）、角色。
  - 重置密码（对话框）：设置新的初始密码，下次登录须改密。
  - 禁用或恢复（确认对话框）。
  - 邀请（对话框）：输入手机号或账号，选择部门与角色。
  - 审批申请（对话框）：查看申请人与理由，选择部门与角色，通过；或填写原因后拒绝。
- 企业管理员不能禁用或降级 owner；owner 只能由 owner 变更。

**角色与权限（二级）**：

| 角色 | 成员数 | 菜单权限 | API 权限 | 操作 |
| --- | --- | --- | --- | --- |

- 内置角色（owner、admin、member）只读；自定义角色可以新建、编辑、删除（无成员时）。
- 三级：新建或编辑角色（抽屉）：名称、菜单权限（沿用 `authz/catalog.py` 的 `MENUS`）、API 权限（沿用 `API_PERMISSIONS`，新增 `org:manage`）、智能体权限（沿用 `TenantAgentGrantRecord`）。
- 三级：分配角色（对话框）：选择角色，选择对象（按人或按部门批量选人）。

**审计（二级）**：企业内的组织、成员、角色、登录相关事件；按时间、操作人、对象筛选。平台级审计仍在系统管理下。

### 3.4 注册与登录页

- 注册页：Tab "个人 / 企业"，表单见第 1.2 节。
- 登录页：一个表单（账号或手机号 + 密码）。登录后有多个空间时进入空间选择页。
- 空间选择页：列出个人空间与所属企业（类型、角色、最近使用时间）；底部"加入其他企业"（输入企业编码、填写理由）；"待处理的邀请"与"我的申请"两个列表。
- 企业微信扫码入口保留在登录页底部（沿用现有行为）。

## 4. 权限

| 操作 | 个人空间 owner | 企业 owner | 企业 admin | 企业 member |
| --- | --- | --- | --- | --- |
| 维护组织树（`org:manage`） | — | 是 | 按角色 | 否 |
| 管理成员账号（`members:manage`） | — | 是 | 按角色 | 否 |
| 维护角色（`roles:manage`） | — | 是 | 按角色 | 否 |
| 查看审计 | — | 是 | 按角色（`audit:read`） | 否 |
| 查看个人设置 | 是 | 是 | 是 | 是 |

- 审批与邀请需要 `members:manage`。申请人不需要任何角色，可以查看自己提交的申请。
- 所有接口仍由后端 RBAC 判断；前端只决定入口是否显示。
- 非成员访问企业接口返回 404；成员但角色不足返回 403（沿用现有规则）。

## 5. 与现有模型的变化

| 现有 | 变化 |
| --- | --- |
| `org_units` 无 `tenant_id`，由平台管理员维护 | 增加 `tenant_id`，由企业维护 |
| `tenant_org_bindings` | 企业空间不再使用，迁移后删除 |
| `user_org_units` 主部门每人一个 | 改为每个企业一个 |
| `tenant_memberships.source` 含 `organization` | 改为 `manual`、`invitation`、`application`；`organization` 取消 |
| `users.phone` 无唯一约束 | 全局唯一（部分唯一索引） |
| 无申请与邀请 | 新表 `space_join_requests`（见 proposal 数据模型） |
| `GET /api/v1/tenants/{id}/…` 的组织信息接口（空间内查看绑定组织） | 改为查看本企业组织树 |

## 6. 与 web 外壳提案的关系

- `2026-11-03-web-shell-tdesign` 的侧栏结构（"更多功能"折叠区）由本设计第 3.1 节取代：侧栏只保留新建会话、最近会话与用户区，原"更多功能"中的项目移入设置的"功能"分组。
- 该提案的设置分组与分区清单（`design.md` 第 4 节）由本设计第 3.2 节取代。两份提案的 TDesign 迁移、路由与占位页规则仍有效。
- 实施顺序：先确认本提案，再实施外壳（外壳需要显示个人与企业两种设置分组）。

## 7. 迁移

依据需要确认的第 3 项（现有数据）：

- **A（开发库）**：删除并重建。迁移只做结构变更与种子数据。
- **B（有数据）**：
  1. `tenants.kind` 对所有已有空间设为 `enterprise`；
  2. 对每棵已绑定的组织树，若绑定单个空间则归该空间；绑定多个空间则为每个空间复制一棵树（保留节点 id 映射，记录在审计中）；
  3. `user_org_units` 主部门约束调整；
  4. `tenant_memberships.source = organization` 的记录保留，但标记为失效，待企业管理员确认后转为 `manual`（或撤销）。

迁移分两步：先加列（可空，有默认值），回填数据，再加约束。两步在同一次 Alembic 迁移中完成，并提供降级脚本（仅恢复结构，不恢复已删除的绑定）。

## 8. 测试要点

- 注册：个人注册后有个人空间；企业注册后注册人为 owner；企业编码重复被拒绝。
- 登录：统一登录；多空间用户看到空间列表并可切换；账号或密码错误返回同一信息；首次登录改密前只允许改密与退出。
- 邀请与创建：手机号已存在时管理员只能邀请，不能设置密码或修改身份；手机号不存在时才创建账号。
- 申请：同一人对同一企业只能有一条待处理申请；拒绝后冷却期内不能再次申请；通过时指定部门与角色并写入 `source = application`；退出企业后审计保留。
- 部门：主部门唯一（按企业）；移动节点拒绝形成环；停用节点不能作为新归属。
- 角色：按部门批量分配逐人写入；撤销只删除对应角色行。
- 权限：个人空间不暴露企业接口；企业成员调用管理接口返回 403。
- 迁移：B 方案的数据回填与组织树复制。
- 浏览器：注册两种类型、企业登录、企业设置的三级弹窗、用户菜单与设置路由。

### 9.3 设置分组

按 WeKnora `Settings.vue` 的分组与顺序显示，只显示当前空间类型与角色允许的分组。本阶段实现：

- 常规设置（语言、主题）
- 个人资料（`UserProfile.vue`）
- 空间信息（`TenantInfo.vue`）、成员（`TenantMembers.vue`）、API Key
- 组织（`/platform/organizations`）
- 审计（企业空间，Admin+）

其余分组（模型、知识库检索、Web 搜索、MCP、沙箱、记忆、Ollama、存储、向量库、解析引擎等）在菜单中保留，本阶段显示占位，由后续阶段实现。

### 9.4 平台管理员

WeKnora 的 `views/system/*`（用户管理、模型目录、运行队列、审计）属于平台管理员。本阶段只实现只读汇总（企业与组织数量），不实现企业内部结构的修改，对应确认结果第 9 条。
